FCREPO-842 If a previous "add" to the policy index (dbxml) fails, subsequent updates fail as the existing doc can't be deleted

Description

Adds to DBXML can fail, eg if they are not schema-valid (or due to some problem with DBXML). This is leaving Fedora objects with an existing policy datastream, but no corresponding dbxml policy.

When the datastream is later updated, the dbxml update is failing as no existing policy could be found to first remove before adding.

Change the update to be a "safe" update, ie only delete if already exists.

Theoretically we could instead fail the saving of the Fedora policy datastream, but safer to at least have the policy datastream preserved (and in fact we would want to (1) save the policy datastream and check that this works before updating dbxml and then (2) if dbxml fails revert the policy datastream change. Difficult without transactions.)
