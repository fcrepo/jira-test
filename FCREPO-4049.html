Description

From https://github.com/fcrepo/fcrepo/issues/2278
Fedora version: Release: 6.5.1 | Commit 6d5a1bb

Steps to reproduce

  • Create a new binary file eg with curl -u fedoraAdmin:fedoraAdmin -XPUT http://localhost:8080/fcrepo/rest/my-file --data-binary @my-file
  • Try to get that file with an unexpected mime-type eg curl -v -u fedoraAdmin:fedoraAdmin -XGET http://localhost:8080/fcrepo/rest/my-file -H "Accept: application/xml

Expected: A 406 response with the content-length equal to the HTML error message in the body.

Actual: A 406 response with the content-length equal to the binary resource.

Impact: When the binary file is longer than the returned error message the client will hang waiting for the rest of the message and will eventually timeout. This makes it difficult to properly handle the 406 response.

Notes

This seems to only affect non-RDF resources.

Tested behaviour with bruno, curl and Spring HTTP clients.

Dan Field, 2026-01-21 14:05 UTC

The issue is only present where running in a container server like Tomcat. In that situation it returns a tomcat rendered error message with a content-length of the underlying binary.

If running from mvn jetty:run Fedora returns a 0 length body and a content-length header of 0 to match.
