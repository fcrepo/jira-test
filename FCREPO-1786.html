FCREPO-1786 Fixity for "external" content always reports success.

Description

Performing fixity on a resource that is external (was produced using the message/external-body mime type) always returns true. Furthermore the stated message digest is also misleading, as it's the sha1 of an empty String.

It might be sufficient just to remove support for fixity on resources with external bodies, but alternately it might be nice to support an accurate (at least at time of ingest) sha1 for that external content, and therefore allow fixity to be performed on the external resource.

James Griffin, 2016-01-26 15:23 UTC

Hello Michael Durbin, Julie Allinson, and Andrew Woods,

My apologies for the delay in my addressing this. Regarding the request in this issue:

It might be sufficient just to remove support for fixity on resources with external bodies

This is straightforward, and I can structure a pull request featuring this.

it might be nice to support an accurate (at least at time of ingest) sha1 for that external content

I certainly agree with this in principle, but as I understand the code base (specifically, the fcrepo-kernel-modeshape package), the implementation may interfere with the degree to which Modeshape is integrated.

Currently, the fixity appears to be generated from the raw bytestream accessed using a JCR Binary Node Object:

fcrepo-kernel-modeshape/src/main/java/org/fcrepo/kernel/modeshape/FedoraBinaryImpl.java
    /*                                                                                                                                                                                                                                        
         * (non-Javadoc)                                                                                                                                                                                                                      
         * @see org.fcrepo.kernel.api.models.FedoraBinary#getContent()                                                                                                                                                                        
         */
    @Override
    public InputStream getContent() {
	try {
            return getBinaryContent().getStream();
	} catch (final RepositoryException e) {
            throw new RepositoryRuntimeException(e);
        }
    }

    /*                                                                                                                                                                                                                                        
     * (non-Javadoc)                                                                                                                                                                                                                          
     * @see org.fcrepo.kernel.api.models.FedoraBinary#getBinaryContent()                                                                                                                                                                      
     */
    @Override
    public javax.jcr.Binary getBinaryContent() {
	try {
            return getProperty(JCR_DATA).getBinary();
        } catch (final PathNotFoundException e) {
            throw new PathNotFoundRuntimeException(e);
        } catch (final RepositoryException e) {
            throw new RepositoryRuntimeException(e);
        }
    }

I can override one of these method implementations in order to issue a GET request in order to resolve the URL of the external resource, and hence, retrieve the content.

The alternative might be to introduce this functionality somewhere higher within the API, such as FedoraFixity#getDatastreamFixity:

fcrepo-http-api/src/main/java/org/fcrepo/http/api/FedoraFixity.java
    /**                                                                                                                                                                                                                                       
     * Get the results of a fixity check for a path                                                                                                                                                                                           
     *                                                                                                                                                                                                                                        
     * GET /path/to/some/datastream/fcr:fixity                                                                                                                                                                                                
     *                                                                                                                                                                                                                                        
     * @return datastream fixity in the given format                                                                                                                                                                                          
     */
    @GET
    @Timed
    @HtmlTemplate(value = "fcr:fixity")
    @Produces({TURTLE + ";qs=10", JSON_LD + ";qs=8",
            N3, N3_ALT2, RDF_XML, NTRIPLES, APPLICATION_XML, TEXT_PLAIN, TURTLE_X,
            TEXT_HTML, APPLICATION_XHTML_XML, "*/*"})
    public RdfStream getDatastreamFixity() {

	if (!(resource() instanceof FedoraBinary)) {
            throw new NotFoundException(resource() + " is not a binary");
	}

        LOGGER.info("Get fixity for '{}'", externalPath);
        return ((FedoraBinary)resource()).getFixity(translator())
                .topic(translator().reverse().convert(resource()).asNode())
                .session(session);

    }

Using this approach, of course, there are likely to be implications for cases where the JCR Binary Nodes within Modeshape don't retrieve the content of these remote resources.

Please let me know if I am misunderstanding any aspect of this issue, and how best to proceed. Thank you.
