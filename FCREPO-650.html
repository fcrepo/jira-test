Stephen Bayliss, 2011-05-03 22:32 UTC

Noting the PID specification https://wiki.duraspace.org/display/FCR30/Fedora+Identifiers and RFC3986 http://www.ietf.org/rfc/rfc3986.txt sect. 2, the only non-alphanumeric characters allowed in a full namespace:pid are as follows, with notes as to encoding as per RFC3986

: -> 2.2, gen-delims, however does not need escaping as part of a path. Only valid as a namespace separator in a pid, can't appear in the namespace-id or object-id component itself

  • -> 2.3 Unreserved Characters, no escaping necessary
    . -> 2.3 Unreserved Characters, no escaping necessary
    ~ -> 2.3 Unreserved Characters, no escaping necessary
    _ -> 2.3 Unreserved Characters, no escaping necessary
    % (as part of escaped octet) -> must be percent encoded

So, the only escaping we need to do is to encode the % of escaped octets, eg if the PID is ns:my%20pid this should be encoded as ns:my%2520pid

Stephen Bayliss, 2011-07-14 11:00 UTC

Discussed on committer call 2011-07-12.

The current position is that the REST API endpoints should not be considered as persistent HTTP URIs as the REST API is an API and therefore subject to change over the long term. Fedora provided no guarantee so far as to the long-term persistence/stability of the REST API endpoints, and currently it is the view that a persistent identifier infrastructure is something that should be provided outside of the core Fedora software (although there is a desire to minimise "breaking" changes to an API such changes are felt to be inevitable over the very long term).

The documentation (on identifiers) should be revised to identify the REST endpoints as the canonical HTTP URIs for Fedora resources, and software components implementing a persistent identifier infrastructure should reference these endpoints (especially they should not reference the old "LITE" APIs). Implementers should be aware that if these REST endpoints are published directly as identifiers for Fedora resources that there is not a long-term guarantee over their stability.
