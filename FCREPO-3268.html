Description

This bug can be seen in the following scenario:

  1. Start fedora
    java -jar fcrepo-webapp/target/fcrepo-webapp-6.0.0-SNAPSHOT-jetty-console.jar --headless
  2. Create a binary resource
    curl -XPOST -H"Slug: binary1" -H"Content-type: text/plain" --data-binary "This is some text" http://localhost:8080/rest
  3. Verify that retrieval of resource works
    curl -i http://localhost:8080/rest/binary1
  4. Verify that retrieval of resource description works
    curl -i http://localhost:8080/rest/binary1/fcr:metadata
  5. Stop fedora
  6. Remove the index
    rm /tmp/fcrepo.ocfl.work.dir/fedoraToOcflIndex.tsv (or wherever it is configured to be located)
  7. Start fedora
  8. Verify that retrieval of resource works
    curl -i http://localhost:8080/rest/binary1 - BOOM!
  9. Verify that retrieval of resource description works
    curl -i http://localhost:8080/rest/binary1/fcr:metadata - BOOM!
