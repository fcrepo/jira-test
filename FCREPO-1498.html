Description

HTTP Log: https://gist.github.com/tpendragon/74d618ec8b6d71859c12

When a triple is added to a resource's body because of indirect containment the etag doesn't change, despite the representation being different.

There was some discussion in IRC about the feasability of keeping the etag up to date.
http://irclogs.fcrepo.org/2015-04-23.html

Esmé Cowles, 2015-11-02 14:11 UTC

Since the etag is calculated from the last-modified property, this is probably impacted by fcrepo-1742. I've added this case to the draft spec of what actions should update the last-modified property: https://wiki.duraspace.org/display/FF/Design+-+Last-Modified+Property

James Griffin, 2015-11-17 16:49 UTC

Confirming this statement from Esmé Cowles, I have found that the last-modified property does not appear to be properly updated under the conditions in which this issue was reproduced:

[...]
# Given two resources test/1 and test/2...
# Create an indirect container test/1/members
curl -v --data @create_indirect_container.ttl --header "Content-Type:text/turtle" -X PUT http://localhost:8080/fcrepo/rest/test/1/members

< HTTP/1.1 200 OK
* Server Apache-Coyote/1.1 is not blacklisted
< Server: Apache-Coyote/1.1
< Cache-Control: private
< Expires: Thu, 01 Jan 1970 00:00:00 UTC
< ETag: "123f5db42dc101b0a3c6a4fa0ffc234178f93027"
< Last-Modified: Tue, 17 Nov 2015 15:17:43 GMT

[...]
# Set test/1 as a proxy for test/2
curl -v --data @create_proxy.ttl --header "Content-Type:text/turtle" -X POST http://localhost:8080/fcrepo/rest/test/1/members
[...]

# Get the ETag for test/1 (now managed using an indirect container)
curl -v http://localhost:8080/fcrepo/rest/test/1

< HTTP/1.1 200 OK
