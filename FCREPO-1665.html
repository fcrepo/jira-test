Description

Summary: In/Direct Containers do not manage the membership triples of NonRdfSources.

Steps to reproduce:

  • Create an ldp:NonRdfSource, say an image (img)
  • Create an ldp:DirectContainer (dc), with membershipResource of img, and some hasMemberRelation (rel)
  • Create a new resource (new) inside dc
  • GET img/fcr:metadata

Expected Behavior: The fcr:metadata response to include the triple: img rel new

Observed Behavior: The triple does not appear in any representation

Remediation Requested: Either the container should reject the NonRDFSource as the object of membershipResource (boo!) or preferably the triple should be added to the fcr:metadata response, otherwise in contravention of LDP 5.4.2.1.

Andrew Woods, 2015-10-30 23:25 UTC

I have just verified the same result reported by Nianli Ma; namely, it is now possible to have Fedora/LDP create a membership relationship on a binary resource via a DirectContainer (as detailed in the linked scripts provided by Esmé Cowles).
I have also verified that it is not currently possible to create such a relationship on the description of a binary resource. In other words, the linked script has two scenarios, one named "describedby-description-working.sh" (no longer works) and another named "describedby-NonRDFSource-broken.sh" (now working).

Robert Sanderson, you suggest that both scenarios should work, but I would argue that the current state is the desired behavior. The NonRdfSourceDescription is a resource that, by definition, contains a description of its associated binary resource. It, in itself, is merely a construct for getting RDF about the associated binary. The subject of all of the triples in the NonRdfSourceDescription is the binary resource.
There is currently no way of GETting RDF that describes the NonRdfSourceDescription; therefore, having the NonRdfSourceDescription as the membershipResource of a DirectContainer (or IndirectContainer) does not make sense in the Fedora/LDP model.

In terms of this ticket, does that seem reasonable? or do you have a use case or need for RDF that has the NonRdfSourceDescription as a membershipResource?
