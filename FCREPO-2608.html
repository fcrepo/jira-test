Description

User identities are now strictly URIs for the purposes of authz, messaging, etc. Make the current user URI available via fcrepo-kernel-api. At the very least, change org.fcrepo.kernel.api.FedoraSession#getId() to return this URI.

To capture these URIs in the first place:

  • if the provided credentials use a string username, append as a hash to a globally configured baseURI (provide sensible defaults).
  • If the provided credentials are a URI, use that.

There may be code in fcrepo4/fcrepo-module-webac that already does this.
https://github.com/fcrepo4/fcrepo-module-auth-webac

Aaron Birkland It looks like method org.fcrepo.kernel.api.FedoraSession#getId() is used for other purpose in Fedora at this time. For example, https://github.com/fcrepo4/fcrepo4/blob/master/fcrepo-kernel-modeshape/src/main/java/org/fcrepo/kernel/modeshape/services/BatchServiceImpl.java#L95.

Should we repurpose the use of FedoraSession#getId() in Fedora, or expose the user URI in other names like org.fcrepo.kernel.api.FedoraSession#getUserAgent()?

Aaron Birkland, 2017-09-19 17:54 UTC

Looking through the code, I think we should repurpose FedoraSession#getId().  Repurpose might not be the right word.  We're using it for the same purpose, just changing the semantics of the identifier.  

BatchServiceImpl is using the userid as a part of a key to a lookup table for transactions.  I suspect just using .toString() from the URI should suffice for that purpose.

I did notice, however, that you may want to look at the signatures of the methods in:

https://github.com/fcrepo4/fcrepo4/blob/28fb8b98528e092fc00e7ba7455bee86c5fa3a4c/fcrepo-kernel-api/src/main/java/org/fcrepo/kernel/api/services/BatchService.java

Effectively, all usernames are URIs now.  So users of the BachService will either have to do a URI#toString(), or the signatures will need to be changed to accept a URI (and internally probably do a URI#toString() anyway.  I leave it to your judgement as to decide which approach to take.

 

 

 

 

Aaron Birkland, 2017-09-19 18:26 UTC

Never mind,  as per IRC conversation, the semantics of FedoraSession#getId() are different after all.  So adding a method to get the user's URI is the right thing to do
