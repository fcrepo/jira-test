Description

Asger pointed out that it is currently necessary to parse FOXML or perform a field search in order to determine the state of an object or datastream. It's also necessary to use API-M in order to determine the format uri of a datastream. Better would be to provide all this information via the REST api, where appropriate.

Comments (4)

Bill Branan, 2009-02-16 15:52 UTC

Updates to the REST API to provide this information have been made as part of FCREPO-391 Closed .

Daniel Davis, 2009-02-18 15:41 UTC

Consider providing the information in the response header for appropriate verms instead of adding verbs to REST-API. If verbs are needed then this information still would be useful in the response header. Also returning the PID and a good last modified date could be made available.

Chris Wilper, 2009-02-19 03:04 UTC

Note that the solution in FCREPO-391 Closed will provide this info via existing verbs by extending the information that is returned.

Bill Branan, 2009-02-19 14:50 UTC

FCREPO-391 Closed introduces a new verb for retrieving datastream content, in order to allow a datastream's "profile" to also be available. The datastream profile includes the information provided by APIM.getDatastream. The profile will be available at the url http://host:port/fedora/objects/PID/datastreams/DSID, appending /content to this url will return the datastream contents.
