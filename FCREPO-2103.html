Description

On our testing server, out of a batch of thousands of fixity service calls we saw hundreds of BAD_CHECKSUM responses. In spot-checking the objects, further calls to the fixity service always produced a SUCCESS response. The logging in this area of the code is not verbose and Fedora does not raise an exception or log a warning or error when a BAD_CHECKSUM is returned (from ModeShape I guess).

I suspect this problem may prove difficult or impossible to reproduce, but I wanted to record it officially.

I have just ran into a problem that sounds very much like this and have figured out a way to reliably reproduce it.

If I perform two fixity checks at the same time then they will both fail with BAD_CHECKSUM. I'm doing this from command line console with curl. In one window I have "sleep 1 ; curl http://localhost:8984/rest/dev/bv/73/c0/40/bv73c0402/files/0a7aec4e-c3c1-4203-a479-cad7aa442fdb/fcr:fixity" and in another window another curl command without the sleep. Then press enter on the window which has the sleep and a roughly second later press enter on the other window so that both requests go out at the same time. They'll both come back with BAD_CHECKSUM.

The files I'm checking are about 100 MB in size. The same thing seems to happen with smaller files but you'll need to be more accurate with getting the two requests happen at the same time. With the 100 MB files it's not very hard at all to get the requests overlap and fail.

It doesn't seem to matter which files I'm checking. Each request can check the same file or different files, makes no difference to behaviour.

Checking each file always results in a SUCCESS if I don't have another request going on at the same time.

I'm on Fedora 4.7.3.
