Environment

Our cloud setup:

Fedora
- Version: 6.5.0
- keepaliveTime=30sec

Postgres:
- Version: 12.16
- Custom settings: idle_in_transaction_session_timeout=180 minutes

Deployed as a docker stack. The database container is in endpoint_mode: dnsrr and the port is in mode: host

Our customers environments can differ and our mostly running on Windows servers.

Description

When committing a long running Fedora transaction, in which the time needed to perform the commit is long (due to a large total size of files of many gigabytes and a large numbers of files for example), the database connections needs to stay open for a long time without any activity because moving all those files from OCFL staging directory to the OCFL root (committing the OCFL persistent storage session, fcrepo-kernel-impl/src/main/java/org/fcrepo/kernel/impl/TransactionImpl.java#L361) can take a considerable amount of time.

The current implementation makes it hard to commit larger Fedora transactions that create/update many Fedora ressources and/or add large binary contents.

Extract of the log message when committing the dabase transcaction because it has been closed by the database server or because the underlying TCP connection has been closed:

fedora_db_connection_timeout_stack_trace.txt

If connection drops are frequent it can be problematic to keep the database connections alive by adjusting the parameters (different security zone, network hardware that is configured to kill long connection…).

Especially in environments of our customers it’s hard to finetune/adjust all parts involved in this (e.g. Firewall, settings of a central PostgreSQL database).

It would greatly improve the situation if moving the files from OCFL staging to the OCFL root could be done before opening or after committing the database transaction.
