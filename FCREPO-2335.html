Description

When migrating between repositories, the base URL of the repository may change. We already support changing the hostname and port, but we should also support changing the webapp context (e.g., /rest/ vs. /fcrepo/rest/, etc.).

Related to this ticket, when a single resource that has relationships with other resources in the repo is exported from a repo with context /f4 and subsequently imported to a repo with context /fcrepo, the relationships still reference resources with the old (/f4) context. 

Esmé Cowles, 2017-05-16 18:53 UTC

I had a mostly working solution to this that I was able to rebase on current master.  But in reviewing it I realized it depended on having "/rest" in the URIs to figure out what the baseURL was (which is not going to be a good assumption going forward with other implementations).

I'm going to set that aside and see if replacing the source parameter with mapping to/from parameters will make work more generally.
