Description

When working on the HTML UI I discovered that if you have a LDP-RS with contained resources and you GET with the header

Prefer: return=representation; omit="http://fedora.info/definitions/v4/repository#ServerManaged"

You still get the ldp:contains triple, but you can't PUT that body back without getting a 409 Conflict

 

Example.

curl -o output_turtle -H"Accept: text/turtle" -H'Prefer: return=representation; omit="http://fedora.info/definitions/v4/repository#ServerManaged"' http://localhost:8080/rest/48d04ae0-d733-44f1-bed0-d25d2bd0f9c9 -ufedoraAdmin:fedoraAdmin

To clarify - the work of this ticket is to ensure that no server managed triples are returned so that a GET with Prefer omit SMTs returns a document that can be PUT back. 

Jared Whiklo, 2018-10-02 13:47 UTC

For reference. When we PUT triples into Fedora it is handled by the RdfAdder  and RdfRemover which extend the PersistingRdfStreamConsumer which seems to do this test (though there must be more).

When we GET triples from Fedora it is handled by the ContentExposingResource at the HTTP layer and it seems to use this which passes off to getTriples() which calls to the FedoraResource.getTriples() which uses the LDP_CONTAINMENT context which maps to ChildrenRdfContext which doesn't seem to have any filters applied.

My guess is that we need to filter based on the Prefer tags like we do for properties.
