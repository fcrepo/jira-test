I disagree strongly with this PR. It appears to conflict directly with the LDP and HTTP specifications.

Esmé Cowles, 2016-08-10 13:26 UTC

Unknown: the current HTTP spec says (https://tools.ietf.org/html/rfc7232#section-3.1):

An origin server MUST use the strong comparison function when comparing entity-tags for If-Match (Section 2.3.2), since the client intends this precondition to prevent the method from being applied if there have been any changes to the representation data.

Since we cannot emit strong ETags, my reading of the chart in https://tools.ietf.org/html/rfc7232#section-2.3.2 is that any strong comparison involving a weak ETag must fail. So I believe this PR faithfully implements that.

The LDP spec says we SHOULD support If-Match. But if the above is true, then I think we cannot. Complying with the MUST of the HTTP spec would trump a SHOULD from the LDP spec.
