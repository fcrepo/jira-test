Comments (12)

Daniel Lamb, 2017-09-29 19:10 UTC

When working through a test case, I've discovered the code as-is will accept either acl:Agent foaf:Agent or acl:AgentClass foaf:Agent.  I'm assuming we want just acl:AgentClass here and not acl:Agent at all?

Daniel Lamb, 2017-09-29 19:13 UTC

Also noticed that enabling webac requires AuthN.  So iin this case, we consider "Public" viewing to be any authenticated user?  Just want to clarify scope and make sure I'm not on the hook for 'anonymous' browsing where no credentials are provided.

Aaron Birkland, 2017-09-29 20:13 UTC

It's probably necessary to allow anonymous reads somehow (without credentials of any sort), where permitted by ACLs.  Maybe via choice of principal provider (i.e. provide a default URI to designate anonymous users, when no user principal has been provided by any means of authn?)  

Andrew Woods, 2017-09-29 21:47 UTC

Daniel Lamb, yes, we should only support acl:AgentClass.

As for anonymous access, this is the situation that Peter Matthew Eichman resolved with Tomcat Values. The fact is that in default configurations, requests will be prompted for AuthN before they even get to Fedora. In the context of this ticket, "allowing any authenticated user" to access resources protected by "acl:AgentClass foaf:Agent" is sufficient.

I would suggest a follow-on ticket for allowing true open access of certain resources even when WebAC is enabled. It is not clear to me that that particular challenge is one that can be resolved exclusively at the Fedora level.

Peter Matthew Eichman, 2017-10-02 15:53 UTC

Andrew Woods, I concur that this is something that we won't be able to solve exclusively at the Fedora level, as long as we are relying on the servlet container to provide AuthN. As you say, at UMD we had to implement a set of valves [1] to parse out preemptive authentication information from the HTTP requests and add them as security principals to the servlet request. Plus, we had to create a separate micro-webapp [2] that just prompts for AuthN and puts the credentials into a shared session.

[1] https://github.com/umd-lib/optional-authn-valve

[2] https://github.com/umd-lib/fcrepo-user-webapp
