Description

DateTimeUtil does allocate 1 SimpleDateFormat object at least for each datastream/version. Since SimpleDateFormat is not thread-safe as pointed out by Ben this could be done via a ThreadLocal<> rather than a static object reference. I'll check into that and maybe try out other formatter as well.

frank asseg, 2012-10-26 14:50 UTC

As discussed in yesterday's committer call i conducted some tests with the Java API and Joda Time:

Java API I 55593.13 ns
Java API II 5386.17 ns
Joda Time I 51827.76 ns
Joda Time II 9197.76 ns

The tests marked "I" have been constructing a DateFormatter for each parsing cycle, while the tests marked with "II" have been reusing an instance.
Since Java's SimpleDateFormat is not thread safe the "Java API II" test is not eligible for usage in fedora but was added for comparison.
Since JodaTime's DateFormatter is thread-safe "Joda Time II" seems a valid way to improve the performance a slight bit and decreasing object allocation.
I'll implement a DateUtil using JodaTime and send Adam a request for review.
