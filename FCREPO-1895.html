Description

The integration tests for the WebAC module use literals to identify acl:agents, but they should use URIs.

See https://github.com/fcrepo4/fcrepo-module-auth-webac/blob/master/src/test/resources/acls/01/authorization.ttl#L4

If the WebAC module is actually using URIs already, then the tests should be updated to reflect this.

This is intended to align the Fedora and Hydra WebAC usage. See https://github.com/projecthydra/hydra-head/issues/313 for the Hydra Access Controls ticket created for changes there.

Esmé Cowles, 2016-03-14 13:48 UTC

If the user/group ids are coming from an external system like Hydra or Islandora, then that system can be responsible for making URIs out of them. If they are email addresses or usernames from a local system, then they can be made into mailto: URIs, or prefixed with a dummy HTTP prefix that identifies them. If they are from something like OAuth, then they may already be URIs.

Having a defined baseURI seems more useful when servlet auth layer is being used, and the ids provided are email addresses or usernames, which would usually be the case when using common auth modules like LDAP/AD or JDBC.

Unknown, 2016-03-14 14:25 UTC

The baseURI mechanism is designed specifically to address the case of servlet auth and mapping usernames/roles to URIs. For delegated (e.g. header-based) authentication, any URI format can be used by a client, and the current PR fully supports that.
