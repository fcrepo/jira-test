Description

SLF4J is a modern logging framework that, among other things, allows applications to cope with dependent libraries that hardcode dependencies on specific frameworks.

Fedora currently uses Log4J, and has to jump through hoops in order to get the logging frameworks (commons-logging, java.util.logging) of its dependent libraries to log to the same place.

Ideally, all fcrepo code should use the SLF4J api when logging is needed, and be agnostic about the underlying logging implementation. Appropriate runtime dependencies can then be included in the classpath to get the desired implementation to be used for all logging operations, whether coming from the org.fcrepo classes, or from classes they depend on. This can be done in a sane way with the help of SLF4J's legacy bridges[1].

Since the Fedora server has runtime dependencies on libraries that hardcode use of java.util.logging (sun-xacml), commons-logging (commons-httpclient and more), and log4j (mulgara), a bridge should be used for each of these frameworks so that all calls to them effectively go through SLF4J.

Lastly, there is the matter of the actual logging implementation to use (i.e., the "sink" for SLF4J). It appears that Logback[2] is the way to go here:
a) It's being actively developed as a replacement for log4j, by its founder.
b) Generally, when a legacy bridge is used for SLF4J, the actual implementation cannot be used as the "sink", for reasons described at [1].

[1] http://www.slf4j.org/legacy.html
[2] http://logback.qos.ch/

Committed to trunk. Fedora's logging is now all done consistently through slf4j APIs, and the legacy bridges are employed in order to get all log messages of libraries we depend on going through slf4j.

Logback is used as the runtime logging implementation. For the Fedora server, configuration is similar to that of log4j: The logback.xml file stored in $FEDORA_HOME/server/config can be modified to change log levels and filter by package + class in a variety of ways. The default configuration is set to notice configuration changes while the server is running ( FCREPO-639 Closed ).

Client and server scripts (with the exception of fedora-rebuild.sh) use a default configuration logs only WARN or ERROR messages to the console, and ignores all others. These can now be easily changed by modifying server/bin/logback.xml or client/bin/logback.xml. As before, the rebuilder still uses the same logging configuration as the server, but sends its output to server/logs/fedora-rebuild.log by default.

The fop, saxon, and imagemanip webapps are configured by default to send all WARN and ERROR messages to standard output which, for tomcat, means their errors will be logged in catalina.out by default. This can be changed by modifying their respective WEB-INF/classes/logback.xml files.

During development, when unit or integration tests are run, logging is by default configured to report INFO, WARN, and ERROR messages to STDOUT. This can be changed by either modifying src/test/resources/logback.xml, or creating a non-version-controlled logback-test.xml file in the same directory.
