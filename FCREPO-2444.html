Description

The RO-BagIt profile (https://github.com/ResearchObject/bagit-ro) calls for the tag manifest to be used to specify additional files to be included in the bag as annotations or provenance for the primary objects of the data directory. (See example https://github.com/ResearchObject/bagit-ro/blob/master/example1/tagmanifest-sha1.txt)

The import/export tool right now seems only to support export of the tag manifest, containing hard-coded key/value pairs from the BagConfig (per https://github.com/fcrepo4-labs/fcrepo-import-export/blob/master/src/main/java/org/fcrepo/importexport/exporter/Exporter.java#L141-L142). It seems to completely ignore this file on import.

In order to import a bag that adhered to the profile, I think it would need to be able to parse the supplied tag manifest and import the files identified therein

Comments (2)

Bridget Almas, 2017-05-18 20:06 UTC

The tagmanifest-sha1.txt/tagmanifest-md5.text lists all the files in the RO Bundle metadata directory  and the manifest.json in the metadata directory describes how the files in there (annotations or provenance) are related to the primary data objects in the data directory.

However, I'm feeling this might not be worth pursuing so much further.  Maybe direct support of RO Bundle BagIT profile is out of scope for the import/export tool? That might be the case if all it is meant to do is import or export BagIt packages that represent the Fedora LDP model directly.  I was reminded of the Data Conservancy's API-X based Package Ingest tool (https://github.com/DataConservancy/dcs-package-ingest) by a member of that group today and I'm wondering if that is more what I was thinking of for this profile. I'm not sure what it does with files that aren't explicitly described using the LDP containment model either though.

It's probably going to be necessary to write something that maps the RO bundle model to the LDP model whichever tool is used, but doing so means that the RO bundle profile would no longer be what was being ingested anyway so it's not clear to me that the import/export tool should in fact support it directly.
