Example

An achivalgroup can have objects within the group that are created, deleted, and recreated. This process can have a number of effects on the objects, and the archival groups version history. Below is a simple example of an archival group with such a history:

This is the docker startup we used.

     version=6.3.0-SNAPSHOT
     docker image pull fcrepo/fcrepo:$version
     docker run --rm --name=fcrepo --publish 8666:8080 fcrepo/fcrepo:${version} 2>fcrepo.err >fcrepo.log &
     sleep 5
     docker exec fcrepo bash -c "{ apt-get update; apt-get -y install tree; }"

This example writes a few files, deletes an image file and recreates it.

     info_fedora="http://localhost:8666/fcrepo/rest"
     curl="curl -u fedoraAdmin:fedoraAdmin"
     put_art="$curl -XPUT -u fedoraAdmin:fedoraAdmin -H'Content-type:text/x-ascii-art; charset=utf-8' --data-binary @-"

     $curl -XPUT -HLink:'<http://fedora.info/definitions/v4/repository#ArchivalGroup>;rel="type"' ${info_fedora}/pet:/99/ashley
     echo -e "  ∧_∧\n ̳o.o̳\n  |♡\\ \n" | $put_art $info_fedora/pet:/99/ashley/image.art >/dev/null
     sleep 2
     echo  "YUM YUMs" | $curl -XPUT ${info_fedora}/pet:/99/ashley/snacks.txt
     sleep 2

     $curl -XDELETE $info_fedora/pet:/99/ashley/image.art >/dev/null
     sleep 2
     $curl -XDELETE $info_fedora/pet:/99/ashley/image.art/fcr:tombstone >/dev/null
     sleep 2
     echo -e "\\    /\\ \n )  ( \`)\n(  /  ) \n \\(__)|" | $put_art $info_fedora/pet:/99/ashley/image.art >/dev/null
     sleep 2

BUG? Archival Group Version

Previous versions of the archival group don't have their contemporaneous image.art object files. In the example below the 1st version of the image.art object is gone, even though it's a accessible via the objects version history. It also doesn't exist in the version with snacks.txt

      versions=$($curl $info_fedora/pet:/99/ashley/fcr:versions \
                      -H'Accept:application/ld+json' |\
                    jq -r '.[]["http://www.w3.org/ns/ldp#contains"][]["@id"]' | sort)

     for i in $versions; do
         echo "=== ASHLEY VERSION $i ===="
         $curl $i;
         echo ''
     done

Feature? - Object Versions share ArchivalGroup version

It seems to me that it'd be better to have every object in an archival
group share the same versions and they match the filesystem versions. This
seems more consistant with some of the documentation of the archival
groups. In addition, in the current method you can only find the objects
for a particular archivalgroup version using a timegate.

Feature? - fcr:tombstone

I don't know this history of fcr:tombstones in F4, but in F6 I think of
them as removal from the filesystem. If if were possible to re-PUT a
deleted object without deleting the tombstone, I'd suggest that objects in
an archival group just don't have tombstones.

Hi Quinn,

After discussing this among the tech team, we’ve decided there are two actions to take on this.

The first is to fix the NullPointerExceptions which are occurring and causing the HTTP 500s to be returned, as the server should be returning a correct response.

The second is to better document Archive Groups and their use cases, in addition to considerations around them such as the workflow you’ve run into. Fedora isn’t able to keep all context around resources in Archive Groups, and as such when they get purged information is lost from the containment index and we end up with a limited view compared to OCFL because of OCFL’s immutable nature. In general we recommend atomic resources to be used to avoid any complications such as the above, unless an Archive Group really is required.

I’ve created tickets for both of these if you’d like to watch them:

  • https://fedora-repository.atlassian.net/browse/FCREPO-3875
  • https://fedora-repository.atlassian.net/browse/FCREPO-3876

I believe this ticket can be closed, but I’m going to leave it open until at least the NPE has a fix in.

-Mike
