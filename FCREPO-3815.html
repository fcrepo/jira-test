Description

Fedora 6 breaks out resource representation into a number of small files for each resource. The more versions of a resource you have, the more of these small files will be generated. Compared to Fedora 3 , Fedora 6 uses many more files and therefore when running on linux, many more inodes. Depending on the structure of one’s Fedora 3 repository - ie if you have a large number of versions on each resource - the migrated Fedora OCFL repo can have an order of magnitude more files.

Furthermore, when using the migration validator, many small files are generated as part of the validation and reporting process.

The task here is to document how users should estimate the number of inodes they’ll need based on the number of resources they intend to store/migrate. Also it would be good to highlight the migration validator options that can be used to minimize inode consumption.
