FCREPO-527 Looser CModel-SDef coupling in the CMA

Affects versionsFedora 3.x trunk

Description

In the current CMA model, the "providesService" arc from a CModel object to an SDef object is necessary in order to add additional methods to a set of objects. But the two arcs from the SDep to the SDef and CModel are actually enough to tie these together implicitly. Doing it this way could allow people to think about content modeling concerns (the "stuff" in the objects) as a separate activity from adding methods to a set of objects.
