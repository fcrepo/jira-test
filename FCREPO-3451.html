Description

Per the Fedora specification, the following state-token behavior still needs to be implemented:

  • https://fedora.info/2018/11/22/spec/#x-if-state-token
    A client may include the X-If-State-Token header field in a PUT request to make the request conditional on the resource's current state token matching the client's value.
  • https://fedora.info/2018/11/22/spec/#x-if-state-token
    A client may include the X-If-State-Token header field in a PUT request to make the request conditional on the resource's current state token matching the client's value. An HTTP PUT request that includes an X-If-State-Token header must be rejected with a 412 (Precondition Failed) response if the implementation supports state tokens, but the client-supplied value does not match the resource's current state token.

The issue can be demonstrated by creating a resource, then making a PUT request with a mismatching state-token.
$ curl -i -XPUT localhost:8080/rest/state
$ curl -i -XPUT localhost:8080/rest/state -H"X-If-State-Token: mismatch"

The second request should fail with a 412 Precondition Failed response.
