Andrew Woods, 2021-01-14 14:16 UTC

My understanding of the source of these fixity mismatch errors is captured in: https://jira.lyrasis.org/browse/FCREPO-3145

The migration code reads in the inline XML, then reserializes it to disk. The issue is that the order of XML attributes changes in this process. The data is identical, but the bytes are not.

The ideal solution would be to resolve FCREPO-3145 Closed (which I unsuccessful tried for too long). In the absence of that solution, we are left with options that involve ignoring and/or calculating and persisting new digests.
