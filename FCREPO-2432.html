Description

This task is to add an optional configuration to allow for updating the following server managed triples:

  • fedora:lastModifiedBy
  • fedora:createdBy
  • fedora:created
  • fedora:lastModified

By default, this capability should be disabled.

Additionally, a configuration class that contains this configuration could be used to use both System Properties and Spring beans to set and get this configuration element.
This update should target both `master` and `4.7-maintenance` branches.

Michael Durbin, 2017-05-15 20:33 UTC

In making this change, I spent an inordinate amount of time trying to find out what I was doing wrong when I PUT some a single dc:title triple and got a conflict with a message about an rdf:type property. 

 

It turns out, this is expected behavior.  When you PUT triples to update a resource you have to include triples that you can't actually set... triples you'd have to query fedora to get.  This is exceedingly impractical for a user (or the writer of integration tests).... you might as well use sparql update if you already have to create some sort of difference between the current state and the state of the resource you want. 

 

As part of this ticket I propose relaxing that requirement to include those server managed triples in PUT requests that are meant to replace existing resources. 

Esmé Cowles, 2017-05-15 20:37 UTC

Mike, you can  do a PUT request without having to specify all the server-managed triples if you add the Prefer header 'handling=lenient; received="minimal"'.  That will make the PUT only operate on the user-managed triples.

Michael Durbin, 2017-05-16 13:13 UTC

Thanks, Esmé Cowles, I'll update my code and comments accordingly.

Michael Durbin, 2017-05-17 15:20 UTC

If PUT isn't to be supported by all fedora implementations and our import/export tool will want to be written generically enough to support all spec-compliant implementations, we will need to allow PATCH requests to update these properties as well, since that is the only way to update update the resource that describes non-rdf resources.

Michael Durbin, 2017-05-17 21:18 UTC

Since we have to support PATCH updates to make binaries work, I had to abandon any pretense of locking down this feature to certain types of requests.  As it is, the repository can be configured either to allow updates of these properties or not.  When you can update them, the repository makes no effort to stop you from doing something non-sensical, but will continue to update the properties implicitly at times when it is appropriate.
