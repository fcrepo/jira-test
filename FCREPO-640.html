Description

Although ::1 has been verified to work in IPv6 environments (see FCREPO-581 Closed ), the default policies deny-apim-if-not-localhost and deny-reloadPolicies-if-not-localhost will not work as expected (authorization fails) in environments where the client IP address comes in as a long-form IPv6 loopback address. The long form of the IPv6 loopback address is 0:0:0:0:0:0:0:1, and can also be provided as 0:0:0:0:0:0:0:1%0 (the latter is the case on my mac, when using Firefox to hit a local Fedora repository instance).

These default policies should be updated to work in such cases.

Fixed in trunk and maintenance-3.3, but unsure under what conditions the trailing '%0' is given in the client ip address.

See http://www.fedora-commons.org/confluence/display/DEV/mail/14353387

Chris Wilper, 2010-02-18 22:51 UTC

As Steve pointed out in the thread, the %0 specifies the optional zone index. Policies now do matching via wildcard, since the zone index can take several possible forms (not just %0, but %eth0, etc).
