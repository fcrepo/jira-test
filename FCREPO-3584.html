FCREPO-3584 Resource locking does not take into account ghost nodes

Description

The resource locking does not take into account ghost nodes. This means that there's a race condition to create the resources `a` and `a/b` where `a` is ghost node in the later request.

Here's one example of how the problem could manifest:

{{# Create a transactioncurl -u fedoraAdmin:fedoraAdmin -v -XPOST http://localhost:8080/rest/fcr:tx
txid=2c994f1f-3951-4805-8742-72fc93745be8

  1. Create the binary a/b in the transaction
    curl -u fedoraAdmin:fedoraAdmin -H"Atomic-ID: $ {txid}" http://localhost:8080/rest/a/b -H "Link: <http://www.w3.org/ns/ldp#NonRDFSource>; rel=type" -v -H "Content-Type: text/plain" -X PUT --data-binary "ghost"

    # Create the binary a outside of the transactioncurl -u fedoraAdmin:fedoraAdmin http://localhost:8080/rest/a -H "Link: <http://www.w3.org/ns/ldp#NonRDFSource>; rel=type" -v -H "Content-Type: text/plain" -X PUT --data-binary "ghost"

    # Commit the transaction
    curl -u fedoraAdmin:fedoraAdmin -X PUT -v http://localhost:8080/rest/fcr:tx/${txid}
  1. See that the binary a contains the child b
    curl -u fedoraAdmin:fedoraAdmin http://localhost:8080/rest/a
    curl -u fedoraAdmin:fedoraAdmin http://localhost:8080/rest/a/b}}
