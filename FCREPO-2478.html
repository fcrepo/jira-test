FCREPO-2478 Use POST with a Slug header instead of PUT

Description

The API Spec does not require support for PUT to create, so we should use POST with a Slug header to create resources instead.

Comments (6)

Michael Durbin, 2017-05-24 18:27 UTC

... and PATCH for modifications?

Benjamin Armintor, 2017-05-24 18:31 UTC

As far as I know PUT to update is not in danger - Andrew Woods?

Esmé Cowles, 2017-05-24 18:36 UTC

Yes, I think using PUT to update works fine (and is going to stay in the spec, AFAIK) — the import/export utility just needs to supply the If-Match header.  Since it is creating the placeholder resources that are being updated, we could probably get the ETag when we create the placeholders, and not even have to do a separate HEAD request.

Andrew Woods, 2017-05-24 20:08 UTC

Benjamin Armintor: yes, PUT to update is safe.

Esmé Cowles, 2017-05-25 19:27 UTC

Benjamin Armintor, I was going to open a separate ticket for using If-Match on PUT-to-update, but I remember now that the problem with that is that we only have weak ETags, because of the non-fixed nature of RDF not allowing for byte-for-byte certainty.  We've previously discussed If-Unmodified-Since as an alternative — would you be amenable to supporting that in Cavendish?
