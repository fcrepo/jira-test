Scott Prater, 2020-01-29 17:26 UTC

The problem appears when migrating inline datastreams.  In my test case, I compared the inline datastream in the test object stored on the filesystem in the Akubra structure with the OCFL versioned file of the same datastream (i.e., a direct file-to-file comparison).  The two files differed as described above.

I then downloaded the same source datastream using the Fedora 3 API, and compared it to the OCFL versioned datastream, and the two were identical.  Which shows, as Andrew Woods surmises, that Fedora 3 is transforming the stored XML during delivery.

So the question is:  which should be considered the canonical version of the inline XML datastream?  The version stored on disk, or the version delivered by Fedora through its API?  If the former, then OCFL contents should match the disk version, and this bug stands;  if the latter, then this issue is not a real bug, and can be closed.

I lean towards the stored version, but I could be talked out of that.  The stored F3 version is the version that matches the original ingested XML datastream, and as such, could be considered the "truer" version to the original (pre-Fedora) source.

Peter Winckles, 2021-01-27 20:19 UTC

There are two issues here.

1. The inline xml is being read by a DOM parser which does not guarantee attribute order.
2. Fedora 3 modifies the xml before calculating the digest: https://github.com/fcrepo3/fcrepo-historical/blob/e8a3be191cce6bbf8f55cd02bf1d52ac53425146/fcrepo-server/src/main/java/fedora/server/storage/types/DatastreamXMLMetadata.java#L92

I have an uncontroversial solution for issue 1. However, if we want the migrated xml to match the recorded digest, then we will need to migrate the version of the xml that the above linked code produces.

Do we want to do this?

Scott Prater, 2021-01-27 21:23 UTC

I think the OCFL xml file should be a copy of the inline xml that is stored on disk in the FOXML file, not transformed in any way by Fedora 3 or the migration utility.
This raises a problem for checksum comparison, as Fedora 3 transforms the stored inline XML prior to calculating and recording, then verifying the checksum.  This means that what is stored in OCFL will have a different checksum than the one recorded in the Fedora 3 datastream record.  I'm okay with that.  The differences can be accounted for as part of a validation process, separate from the migration process.
