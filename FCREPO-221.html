Bill Branan, 2008-10-29 14:36 UTC

The current implementation (as of GSearch 2.1) is to allow the configvalues.xml ant script to set the full path of xsl:includes for all XSLT files under GSearch config. This solution guarantees all included files will be resolved correctly, regardless of the server setup or classloading policies. There does not appear to be a need to make further changes at this time.

From Gert: I remember having problems long ago with relative paths in the xsl:includes, because they resolved to the directory from where tomcat was started (instead of the natural thing, namely resolving to the directory, where the calling xslt was), and thus did not find demoCommon.xslt. It has not seemed a problem to have absolute paths in the final config files once they are installed under tomcat. I do not have a clue how to do it otherwise, in GTransformer or elsewhere.
