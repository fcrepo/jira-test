Description

After migration of data from a Fedora 3.7.1 repository into a fresh Fedora 6 instance, the previously external datastreams of the F3 repo do exist as child nodes of the corresponding resources, however, upon accessing them an internal server error occurs. This, consulting the stack trace (see attached file), seems to be caused by a NullPointerException.

Some more information about the datastreams: They are, as mentioned, part of the External Reference control group, their MIME type is text/plain;charset=UTF-8, they are in an active state and their versionability is set to replace older versions. An example for the referenced content (CMDI XML) can be seen here.

Felix Helfer, if you'd like a hot-fix, you can use this branch I just made: https://github.com/pwinckles/migration-utils/tree/content-size

git clone -b content-size https://github.com/pwinckles/migration-utils.git

After building that version of the migration-util, you'll need to do a fresh migration of your F3 objects.

I am not planning on submitting a PR for this fix. Instead, we're going to change how content size is recorded so that it's not possible for it to have a null value. However, because we're trying to get an alpha release together, it is unlikely that this comprehensive fix will be made until sometime next week. Hopefully, this quick fix will unblock you for the time being.

Let me know if you experience any other problems.
