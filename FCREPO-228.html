FCREPO-228 Batch Modify Parser mangles some input XML

Description

When the batch modify parser encounters an inline xml datastream that looks like:

<a:element xmlns:a="urn:example:a">
<b:subelement xmlns:b="urn:example:b">
</b:subelement>
</a:element>

...the output it sends to Fedora is not well-formed. In particular, the namespace declarations are moved to the root, but still present in the sub-elements, minus the attribute name, like so:

<a:element xmlns:a="urn:example:a" xmlns:b="urn:example:b">
<b:subelement ="urn:example:b">
</b:subelement>
</a:element>

Ideally, the output that the batch modify utility sends to Fedora should be exactly the XML that occurs within the xmlContent element.

This was originally reported by Deborah Kaplan at Tufts on May 27th, 2008. It was thought to have been fixed by bugfix #1838750, but on July 11th, Deborah reported that wasn't the case and I verified.

A fix should ensure any well-formed inline XML, regardless of how namespaces are declared, arrives to Fedora in the same way it was given in the batch modify directives file – without changing where namespaces are declared.

This bug needs to be fixed in trunk and maintenance-2.2, with appropriate tests.
