Description

Once the external content PR is in, it would be good to check that the proper ConstrainedBy information is sent when the user sends in an invalid request.  

API Information for external content constrainedBy messages is here:  https://fcrepo.github.io/fcrepo-specification/#external-content

Bethany Seeger, 2018-07-05 15:27 UTC

Part of this has been tested - the proper constrained by link is returned in this scenario: "In the case that the specified handling cannot be respected, the restrictions causing the request to fail must be described in a resource indicated by a rel="http://www.w3.org/ns/ldp#constrainedBy" link in the Link response header."

Bethany Seeger, 2018-08-17 17:37 UTC

The proper ConstrainedBy link is returned correctly in the case of 'handling' being invalid. All is well with this and it meets the spec.

The ConstrainedBy information will also be returned if the ExternalContent Link is malformed in other ways, though that's implementation specific. Just mentioning that here.
