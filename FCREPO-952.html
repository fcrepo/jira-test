Description

The database internally uses a SMALLINT for the systemVersion in the doRegistry table. This value is incremented every time you modify an object, and overflows when you reach 32767 modifications.
This was reproduced using a small piece of code that added and removed a relation from and object repeatedly.

This is fixed in bebcf148a98c75d86054f8d5856b5042d77e615b. I did take a quick look at making use of the full range of INT. There are bits of code that assume 0 as the default or initial value. So better off marking the systemVersion column as unsigned. However, it doesn't look like our dbspecs support passing unsigned as an option.
