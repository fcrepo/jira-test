Description

Add support for users supplying metadata values to be included in the Bag. Some or all of these fields may be required by some profiles:

Source-Organization
Organization-Address
Contact-Name
Contact-Phone
Contact-Email
External-Description
External-Identifier
Bag-Group-Identifier
Internal-Sender-Description

Values should passed via a --bag-config param that points to a yml file like this: https://gist.githubusercontent.com/ruebot/b7d4e8a592d304d9a9a47000355424a6/raw/6f4f0dc86bd09da9683d6003544d48a10718f2d8/bag-info.yml

Also change --bag to --bag-profile.

Danny Bernstein, 2016-12-12 18:48 UTC

Esmé Cowles: So are you thinking we should add these as commandline params? Or should they go in their own file and then that file path is passed in as a command line param? Or some other idea? Just curious what your thoughts are there.

Esmé Cowles, 2016-12-12 18:52 UTC

I'm not sure. I think we could add them as command-line params. But some of them (e.g., Source-Organization, Contact-*) seem like things that would be the same for basically all Bags produced by an org, so some kind of config file where these could be entered does seem like a good idea.

https://jira.duraspace.org/browse/FCREPO-2224 has an example BagIt profile, so maybe there's a way to include the values in there, and then the user could specify the bag profile file instead of just the name like the initial implementation?

Danny Bernstein, 2016-12-13 19:04 UTC

Esmé Cowles: So if I'm understanding you correctly: it would probably be best to have a simple config file (json? ) that gets passed to the command line. When this param is present, a bagit profile must also be present. Then FCREPO-2356 Closed will be responsible for enforcing the rules. So maybe no individual metadata values will be passed directly on the commandline. Only via the config file. Does that sound about right?

Esmé Cowles, 2016-12-13 19:07 UTC

Danny Bernstein: That sounds good to me. Once we have a release, we can gather feedback on that, and see if people would rather be able to specify some of the values as command-line arguments instead. But putting them all in the JSON file sounds like a good first approach.

Esmé Cowles, 2016-12-14 14:56 UTC

Danny Bernstein: I went ahead and created a wiki page with the metadata fields I know about from the BagIt spec and the requirements docs I've seen: https://wiki.duraspace.org/display/FF/Design+-+Bag+Metadata

I included a column with my best guess about which fields users would want to supply on a per-Bag basis (presumably as a command-line parameter) and which ones fields would probably be the same for all Bags. We should get feedback on how this should work from our stakeholders.

I wouldn't worry about this for the purposes of this ticket, I just wanted to make sure you knew about this.
