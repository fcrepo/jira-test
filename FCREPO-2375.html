Description

With Fedora 4.7.0, when I do a HEAD request on a non-existent repository URI with an invalid namespace, I get a 404:

$ curl -I http://localhost:8080/rest/invalid:foo
HTTP/1.1 400 Bad Request
Date: Thu, 22 Dec 2016 19:14:39 GMT
Content-Type: text/plain
Content-Length: 38
Server: Jetty(9.2.3.v20140905)

(An error about the invalid namespace prefix is logged to the server log, but not displayed to the user in any way).

With 4.7.1-RC-1, I get a 400 Bad Request:

$ curl -I http://localhost:8080/rest/invalid:foo
HTTP/1.1 400 Bad Request
Date: Thu, 22 Dec 2016 19:15:53 GMT
Content-Type: text/plain
Content-Length: 38
Server: Jetty(9.2.3.v20140905)

Aaron Birkland, 2017-01-05 21:05 UTC

I'm a little confused - what is the relationship between performing a HEAD on http://192.168.99.100:8080/fcrepo/rest/invalid:foo and the absence of registered test: prefix?

Esmé Cowles, 2017-01-05 21:12 UTC

Aaron Birkland — the ActiveFedora test that led to this issue was doing a HEAD on the URL http://localhost:8986/rest/test/test:123. In 4.7.0, that returns a 404 (because the test: prefix is registered), but in 4.7.1-RC-1, it returns a 410 (because test: was removed).

I incorrectly thought it was the namespace handling that had changed. But in fact, it was the removal of the test: prefix that caused the change in behavior.

Esmé Cowles, 2017-01-05 21:36 UTC

Aaron Birkland, 2017-01-05 22:13 UTC

I think there may be two issues here:

1) the removal of "test:" prefix in the cnd file. This has implications beyond the 400/404 issue, so it makes sense to keep "test:" around for the 4.7.x series in its own right

2) Fedora's response code to URIs that look like http://path/to/resource/prefix:whatever. Should the http response codes be affected by the contents of the cnd file at all? Shouldn't they just be 404s (resource does not exist) rather than 400 (you're not interacting with this resource correctly)?

kefo, 2017-01-05 22:37 UTC

+1 to retaining the current behavior in 4.7.x

As for '2', I don't see why it should be affected by the 'cnd' file unless the cnd file defines that specific node (not the namespace), such that it should exist. It seems to me that, if, for example, http://192.168.99.100:8080/fcrepo/rest/invalid:foo doesn't exist, then it should return a 404. If, however, it does exist - or it is a service that should exist - and you are interacting with it incorrectly, it would be a 400 (or Bad Request) or possibly a 405 (depending).
