Description

Validation for POLICY datastreams only occurs when they're read for the purpose of enforcement (after they're ingested). This makes it possible to ingest a non-schema-valid POLICY datastream, which then makes it impossible to access the object at all due to validation failures for every subsequence API operation involving the object.

This problem manifests itself when policy enforcement is active and you ingest
an object that contains a malformed/invalid policy in the object's POLICY
datastream. The object will ingest without any errors, but once ingested you
are unable to access the object by either API-A or API-M because of an
authZException.

The authZException is actually masking the underlying cause of the exception
which is a ValidationException thrown by the parser when unable to
successfully parse the malformed policy. Repository wide policies are
validated at server startup, but policies embedded in an object's POLICY
datastream are not parsed until an attempt is made to access the object.

A temporary workaround should this occur is:

1) shutdown the Fedora server
2) edit fedora.fcfg and set the "ENFORCE-MODE" parameter to "permit-all-
requests"
3) restart the server
4) edit/remove the object with the malformed policy
5) shutdown the server
6) edit fedora.fcfg and set "ENFORCE-MODE" parameter back to "enforce-policies"
7) restart the server

------- Additional Comment #1 From Ross Wayland 2006-04-21 17:18 [reply] -------
The proper fix for this problem is probably to just parse POLICY datastream
policies at the time of ingest and throw an exception if the policy is
invalid. Catching the problem at ingest time would prevent the object from
being added to the repository.

This will have some impact on ingest performance, so needs to be evaluated
before implementing a permanent fix.
