FCREPO-1214 RISearchServlet chrashes if stylesheets unaccessable

Environment

Debain 7 (32 bit), default Tomcat7

Description

Installation of Fedora to standard Debain Tomcat via deployment descriptor files (fedora.xml context description in /var/lib/tomcat7/conf/Catalina/localhost) doesn't set up the webapp directory in the way RISearchServlet (and probably other components) is expecting it. In particular the directory /ri (containing stylesheets) is missing.

However, the set up of RISearchServlet doesn't check for existence/accessibility of these files on initialization.

Part of the problem seems to be, that Trippi needs absolute File path to the stylesheet files, instead of resource URL (obtained by calling getResource).

Maybe connected to this issue:
https://jira.duraspace.org/browse/FCREPO-534

Fedora is running in standard Debian 7 Tomcat installation as a webapp configured with deployment descriptor in /etc/tomcat7/catalina/localhost/fedora.xml:

<?xml version="1.0" encoding="UTF-8"?>
<Context docBase="/opt/fedora/install/fedora.war">
<Parameter name="fedora.home" value="/opt/fedora" />
</Context>

In this environment $CATALINA_HOME usually points to /usr/share/tomcat7. As you can see here, all the Fedora files are located in /opt/fedora.

The stylesheets you mentioned are present in /var/lib/tomcat7/work/Catalina/localhost/fedora/WEB-INF/classes/ri and thus should be in the classpath.

Ralf Claussnitzer, 2014-08-17 20:17 UTC

Hi Benjamin,

I tested a very basic Fedora installation on a Debian VM. Everything looks OK to me.

Step by step:
1. Build Fedora 3.8.0-SNAPSHOT
2. Set up Debian 7.6 VM (Linux debian 3.2.0-4-486 #1 Debian 3.2.60-1+deb7u3 i686 GNU/Linux)
3. Install default Tomcat7 (req. Open JDK 6)
4. Use fcrepo-installer to install to /opt/fedora using the existing Tomcat (install.properties below)
5. Set FEDORA_HOME environment variable to /opt/fedora via /etc/profile.d/fedora.sh
6. Remove all /usr/lib/tomcat7/webapps/fedora, /usr/lib/tomcat7/webapps/fedora.war, /usr/lib/tomcat7/work/fedora
7. Edit /etc/tomcat7/Catalina/localhost/fedora.xml to set docBase="/opt/fedora/install/fedora.war"
8. Restart Tomcat7
9. Check fedora/risearch Servlet... Works.

Maybe one should consider automating this kind of integration test. Vagrant [1] looks promising, but I'm not yet able to build up a working Debian7 image.

[1] http://www.vagrantup.com/
