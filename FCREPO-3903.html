Description

I have encountered a problem where Fedora fails to start if MySQL is not fully ready at the time of Fedora startup. This is a problem during bootstrapping of my server, since even if I create a dependency between Fedora and MySQL, systemd will sometimes attempt to start Fedora before MySQL is ready to receive connections.

This was discussed on the August 17, 2023 dev call. Consensus was that it would make sense for Fedora to introduce a “wait-and-retry” loop around database initialization, so that it doesn’t immediately fail when a dependency is offline. Ideally, the wait duration and retry limit could be configurable via Java properties so that the behavior could be customized and/or disabled.
