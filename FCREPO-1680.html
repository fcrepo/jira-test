Andrew Woods, 2015-08-07 13:18 UTC

Instead of deciding on a new hardcoded property which to map F3 PIDs to, would it be more flexible to instead introduce a configuration element (with a default of "dc:identifier") that can be changed to whatever the user wants?

Michael Durbin, 2015-08-07 13:20 UTC

That sounds more flexible. We should change the default though as well, to avoid a collision between the dc:identifiers from the fedora 3 DC datastream and the dc:identifier from the pid.

Michael Durbin, 2015-08-07 14:57 UTC

To be clear, we weren't explicitly migrating the PID before, we were relying on the behavior of fedora 3 where the pid is automatically populated in the DC datastream. This may not have been a safe assumption, because perhaps you can delete that from the DC datastream, furthermore, as the issue reporter pointed out, there's no automatic way to discern the pid among potentially multiple dc:identifier fields.

This fix will:
1. explicitly migrate the pid
2. allow users to set a custom predicate for that (and other simple) property

Andrew Woods, 2015-08-07 15:12 UTC
