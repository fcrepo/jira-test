Description

Fedora will often report ERROR for simple operations that can hardly be called an error.

As fedora is a server system, there are really two kinds of ERRORS

1. User request failed
2. Server got broken

For a maintenance perspective, I want my maintenance department to monitor the fedora log for problems with the fedora server. These should not monitor the logs for users timing out or not knowing the correct password.

I feel we should rework the log statements, or provide a way for the user-request problems to be filtered to a separate file.

Chris Wilper, 2011-01-25 23:46 UTC

Discussion today about levels:

FATAL: I can't keep running. Or I've detected a situation where there's a risk of data loss, so I'm shutting down.
ERROR: Server detected inconsistent state between db and persistent storage, an unexpected IO error accessing either the DB or filesystem.
WARN: Sysadmin should probably know about this, or a potential cause of future error is detected.
INFO: Clearly user error, or signifant server events (startup, module initialization)

Chris Wilper, 2011-01-25 23:50 UTC

Whoops. I forgot that slf4j doesn't have a FATAL level....here's why:

So if we want to distinguish between application-stopping and and non-application-stopping ERRORs, we must do so within the text of the log message. Actually saying something like "Really bad thing X happened! Shutting down Fedora..." would be fine I think.
