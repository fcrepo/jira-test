FCREPO-3781 Create a means for allowing users to drop in custom service jars that extend the Camel Toolbox

TypeNew Feature
StatusOpen
PriorityLow
ReporterDanny Bernstein
Created2021-10-05 22:30 UTC
Updated2022-02-17 07:09 UTC
Componentsfcrepo-camel-toolbox

Description

The idea is to provide a means that users can add new services to the camel toolbox by simply linking an external jar containing an @Configuration tagged java class.

Perhaps it could work by dropping the jar in a specific directory or something like that.

Comments (4)

Ralf Claussnitzer, 2022-02-04 08:22 UTC

I’m not absolutely sure how Spring Boot looks for components, but I think a drop-in directory that contains JARs should be possible to some extend.

This brings up some more intricate questions:

  • What must be provided for the development of such extensions (provided dependencies)?
  • What is the packaging format for extensions, if they themselves depend on other libraries (SpringBoot format)?
  • Security considerations

The Karaf OSGI runtime had this covered. What’s the solution for Spring Boot?

Ralf Claussnitzer, 2022-02-16 14:14 UTC

From looking at how the Driver application is configured I assume that all extensions simply had to be JARs on the classpath. These would provide the annotated classes (@Configuration) and a RouteBuilder for being picked up by the Spring classpath scanner. All that's needed for this to work is changing the Java command in entrypoint.sh to pick-up additional JARs. They could for example reside in camel-toolbox-config/.

It’s still unclear to me what dependencies would be required for developing and testing extensions outside of the fcrepo-camel-toolbox project.

Danny Bernstein, 2022-02-17 06:47 UTC

Hi Ralf Claussnitzer : I think this sounds about right. I could imagine providing a list of package names in the properties file that would be passed to the @Configuration annotation. But your question about what dependencies would be required for developing and testing extensions outside of the CTB is also not completely clear to me. Perhaps it would help to approach by discussing your use case and then try to generalize from there. Also, what security considerations did you have in mind?

Ralf Claussnitzer, 2022-02-17 07:09 UTC

My use case is a service that watches container updates to generate RDF tuples from XML-binaries and update them in a Fedora container. It’s an XPath based indexing job basically but the target system is Fedora itself.

Security considerations was just a guess. I’m assuming they exist. Somebody could manage to inject malicious code or open up arbitrary HTTP endpoints. We might want to limit what people can do. But I’m not sure if this in scope at the moment.
