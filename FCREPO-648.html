Description

Use standard, well-known frameworks/libraries to:

  • Resolve inter-module dependencies via dependency injection
  • Provide hooks to initialize/de-initialize modules when the webapp container starts and stops
  • Allow re-configuration and plugging in of alternative modules without re-compiling

For more in-depth information on this work, please see: http://fedora-commons.org/confluence/x/JAAbAQ

Benjamin Armintor, 2010-07-14 22:27 UTC

Update on the issue branch:

  • Servers create a Spring application context, and register themselves as a singleton bean. Servers create a child context for all other beans, including modules.
  • Servers register bean definitions from $ {fedora.home}

    /server/config/spring with an XML bean definition reader

  • Servers parse the fcfg, and create bean definitions from all module configurations.
  • Server required module roles are validated if they appear as Spring bean definitions or ar fcfg configurations.
  • Servers instantiate all modules as Spring beans. This allows all the modules, and the context Server, to be autowired into other Spring bean definitions.
  • Existing modules can run un-changed; most Spring work confined to the Server abstract class. ResourceIndex modifed to allow location of triplestore connector via Spring.
