Description

Currently we are doing no validation of OCFL objects that are side loaded (ie copied directly into the OCFL and reindexed).  This task  is to add some validation capability in fcrepo-storage-ocfl that can we used by the http /fcr:reindex endpoint.

List of validations to implement:

- Every header file has a corresponding content file, unless the
  header indicates the resource is deleted in which case it must not
  have a corresponding content file
- Every content file has a corresponding header file
- The Fedora ID of the object at the root of the OCFL object equals
  the OCFL object ID
- Any child resources must correctly reference their parent and have
  a correct ID
- Fedora IDs must start with info:fedora
- Fedora ID parts may not be empty
- Fedora ID parts may not equal:
  - fcr-root
  - .fcrepo
  - fcr-container.nt
  - fcr:tombstone
  - fcr:versions
- Fedora ID parts may not end with:
  - ~fcr-desc
  - ~fcr-acl
  - ~fcr-desc.nt
  - ~fcr-acl.nt
- Every non-RDF resource must have a non-RDF description
- All resource headers must contain:
  - id
  - parent
  - stateToken
  - interactionModel
  - createdDate
  - createdBy
  - lastModifiedDate
  - lastModifiedBy
- Non-deleted resource headers must contain:
  - contentPath
  - contentSize
  - digests
- Non-RDF resource headers must contain:
  - mimeType
  - archivalGroup = false
- External Non-RDF resource headers must contain:
  - externalUrl
  - externalHandling
- Archival group resource headers must contain:
  - archivalGroup = true
  - objectRoot = true
- Archival part resource headers must contain:
  - archivalGroup = false
  - objectRoot = false
  - archivalGroupId
- Atomic resource headers must contain:
  - archivalGroup = false
  - objectRoot = true
- Digest URI must be formatted as urn:ALGORITHM:DIGEST
- Timestamps must be in ISO-8601 format
- Every version of the object must have all of the above validations
  applied
