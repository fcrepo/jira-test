Description

In order to consider the REST API stable (non-beta), we need to finish several pieces of it and make sure certain bugs are addressed.

After this point, we will not make backward-incompatible changes without giving sufficient warning to users. Ideally, this means marking functionality as deprecated for a release, so people have time to adjust their client code.

In the committer discussion on Nov 10 '09, we agreed that stabilizing the REST API does not require that the relationship-related methods are exposed in it. A future version of Fedora may extend the REST API to add these.
