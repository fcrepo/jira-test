FCREPO-1996 Should we use a binary's SHA1 as its ETag?

Description

We currently use last-modified dates to generate weak ETags. And this PR aims to make binaries and their descriptions have a single last-modified date and thus ETag: https://github.com/fcrepo4/fcrepo4/pull/1022

We could use a binary's SHA1 as its ETag, which would avoid invalidating caches when a property changed but the content did not.

Should we use a binary's SHA1 as its ETag? Do we need to provide separate last-modified timestamp for binaries too?
