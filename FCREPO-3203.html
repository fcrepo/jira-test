FCREPO-3203 Migration-utils: improve performance of small batch migrations

TypeImprovement
StatusOpen
PriorityMinor
ReporterScott Prater
Created2020-02-02 22:33 UTC
Updated2020-02-03 14:42 UTC
Componentsf4-migration
Fix versionsfcrepo-migration-utils-4.5.0

Environment

CentOs 7 Linux, Java 11, CIFS-mounted source filesystem (Fedora 3.8.1, Akubra storage), CIFS-mounted target filesystem

Description

Migrating a single object from 400,000 objects takes approximately 3.5 hours in our environment, despite using a pre-generated datastream index.  Upon examination, it looks like every single object is scanned (from the filesystem?) then checked to see if it should be migrated.

I ran the following command at 10:02 AM:

java -jar target/migration-utils-4.4.1-SNAPSHOT-driver.jar --source-type=akubra --datastreams-dir=/fedora3-prod/fedora/datastreams --objects-dir=/fedora3-prod/fedora/objects --target-dir=/fedora-migration-test --layout=pairtree --pid-file=/var/tmp/test-migration-pids.txt --index-dir=/var/tmp/datastream-index --debug

 

The file /var/tmp/test-migration-pids.txt contains a PID for a single object.

Looking at the debug log, I saw many of these entries, one per object in our repository:

DEBUG 10:02:16.741 (UserProvidedPidListManager) PID: 1711.dl:2IWVGDIWTE4FU8Q, accept? false
 DEBUG 10:02:16.765 (UserProvidedPidListManager) PID: 1711.dl:X6FSD5T4JBUPS9D, accept? false
 DEBUG 10:02:16.786 (UserProvidedPidListManager) PID: 1711.dl:56KTJDLD47H2D8R, accept? false
 DEBUG 10:02:16.816 (UserProvidedPidListManager) PID: 1711.dl:6OKBI5VJH3DD49B, accept? false
 DEBUG 10:02:16.840 (UserProvidedPidListManager) PID: 1711.dl:ALJVKGFZONRTD8R, accept? false
 DEBUG 10:02:16.863 (UserProvidedPidListManager) PID: 1711.dl:5U7C22BGOOC6C8B, accept? false

Migration-utils scanned approximately 25 - 30 object per second.  There are 390,925 objects in our repository.

At 10:35, it found the object to migrate, and migrated it:

DEBUG 10:35:38.890 (UserProvidedPidListManager) PID: 1711.dl:4RJO2AJNM55JH82, accept? true
DEBUG 10:35:38.910 (ResumePidListManager) PID: 1711.dl:4RJO2AJNM55JH82, accept? true

After migrating it, it migration-utils then continued to scan through the rest of the objects in our repository.  It finished running at 1:28 PM.
Total run time for one object:  3 hours 26 minutes.

Recommendations for partial migrations, reading from a PID list:

1.  Stop the migration when the last PID in the list is migrated.

2.  Generate a reusable object index, similar to the datastream index, that can be quickly scanned on subsequent runs.
