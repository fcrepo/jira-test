Description

Created stress test script (see attached file).

The script loops over the following tasks 10,000 times:

  • open a transaction
  • create an object
  • commit the transaction

Fedora starts consistently throwing error around cycle #950.

After that, the app becomes unresponsive and Tomcat needs to be killed. See logfile excerpt.

Interestingly, on my ArchLinux development VM with less RAM and processor this does not happen.

Andrew Woods, 2015-01-19 21:09 UTC

Former user, I have been doing some profiling/experimenting, and discovered that for every new transaction, a new thread is added to the RepositoryChangeBus. Those threads do not go away.

I ran four scripted tests on the 4.0.0 release that simply creates batches of 500 UUIDPathMinter containers:
1. Authorization enable, with each create in its own transaction
2. No Authorization, and no transactions
3. No Authorization, with each create in its own transaction
4. Authorization enable, and no transactions
