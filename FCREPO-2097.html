FCREPO-2097 Ontology document doesn't return a Content-Type header

Description

The Fedora ontology is available online, but LDP clients have a hard time parsing it since it doesn't include a Content-Type header. It really MUST return a Content-Type header. I see that most other ontologies will redirect clients to a URL with a .rdf extension.

For example:

$ curl -i http://fedora.info/definitions/v4/2016/03/01/repository

HTTP/1.1 200 OK
Date: Sun, 31 Jul 2016 13:09:56 GMT
Server: Apache
Last-Modified: Mon, 02 May 2016 15:50:16 GMT
ETag: "621a-531ddf2e5c191"
Accept-Ranges: bytes
Content-Length: 25114

A. Soroka do you have an opinion on this? I would be satisfied if the resources simply returned Content-Type: application/rdf+xml.

A. Soroka, 2016-08-01 11:27 UTC

If that's what it the content type is, that's what the header should be. Why would there be any debate about that? I don't see any reason to screw around with file extensions. If we want to get tricky, we can do redirects to different serializations based on content type, but I'm not going to spend my time doing that unless someone is actually asking.
