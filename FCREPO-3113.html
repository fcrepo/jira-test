Description

For a Fedora3 RELS-EXT datastream that was identified as "RELS-EXT.1" in the foxml, even though there was only one version of the RELS-EXT content, the migration tool put RELS-EXT in OCFL v2, instead of v1 with the other datastreams. There's only one version of the RELS-EXT, so it can just be in OCFL v1.

Here's the relevant foxml:

<foxml:datastream ID="RELS-EXT" STATE="A" CONTROL_GROUP="X" VERSIONABLE="true">
      <foxml:datastreamVersion ID="RELS-EXT.1" LABEL="External Relations" CREATED="2019-05-09T15:52:01.885Z" MIMETYPE="application/rdf+xml" FORMAT_URI="info:fedora/fedora-system:FedoraRELSExt-1.0" SIZE="318">
                <foxml:contentDigest TYPE="MD5" DIGEST="870c9172498c0459d45df88b9686c8e8"/>
                <foxml:xmlContent>
<rdf:RDF xmlns:fedora-model="info:fedora/fedora-system:def/model#" xmlns:rdf="http://www.w3.org/1999/02/22-rdf-syntax-ns#">
<rdf:Description rdf:about="info:fedora/test:233605">
<fedora-model:hasModel rdf:resource="info:fedora/bdr-cmodel:commonMetadata"></fedora-model:hasModel>
</rdf:Description>
</rdf:RDF>
               </foxml:xmlContent>
       </foxml:datastreamVersion>
</foxml:datastream>

Andrew Woods, 2019-11-07 21:36 UTC

ben_cail, the way that the migration-utils application determines which datastreams should be in a given "version" is by using timestamps. All datastream versions that share the same timestamp belong to the same "version".
See:
https://github.com/fcrepo4-exts/migration-utils/blob/master/src/main/java/org/fcrepo/migration/handlers/VersionAbstractionFedoraObjectHandler.java#L80
and:
https://github.com/fcrepo4-exts/migration-utils/blob/master/src/main/java/org/fcrepo/migration/handlers/VersionAbstractionFedoraObjectHandler.java#L117-L124

If you believe Fedora "versions" should be constructed by a different means than creation-date, maybe we should make a change.

The Brown U object listed in this ticket:
https://gist.github.com/awoods/760ee7cbd3f84b56ba517f44aea3116d
