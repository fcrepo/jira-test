Description

SimpleDOWriter is converting between strings and bytes without specifying the character encoding - the platform default is used. The original encoding is ignored resulting in invalid UTF-8 strings.

Stephen Bayliss, 2009-09-09 10:41 UTC

Reproduced on Windows. JVM argument -Dfile.encoding can be used to change the platform default encoding, so it should be possible to reproduce this on Linux by, for example, using -Dfile.encoding=cp1252

Stephen Bayliss, 2009-09-09 17:59 UTC

Investigating this in a bit more detail

SimpleDOWriter.addRelationship writes the new triple to a ByteArrayOutputStream in the format org.trippi.RDFFormat.RDF_XML - this format specifies UTF-8 (and not the platform default encoding).

Subsequently when converting this stream to a string (xmlContent) no encoding is specified, so it is incorrectly interpreted using the platform default encoding. The string is then converted back to bytes and assigned to the datastream, which by default uses UTF-8.

There appears to be no need for this intermediate string xmlContent, instead out.toByteArray() can be used directly, as this will be UTF-8.

As RDFormat.RDF_XML is UTF-8 and by default DatastreamXMLMetadata is UTF-8 by default this should be fine. A better solution could be to construct the DatastreamXMLMetadata and explicitly specify the encoding as RDFFormat.RDF_XML.getEncoding().

Stephen Bayliss, 2009-09-14 08:59 UTC

Carsten Friedrich has verified that removing the String xmlContent at line 291 and using out.toByteArray() directly to assign to the datastream object fixes this problem.
