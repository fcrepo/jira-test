Description

The task here is to clarify the best practice in the documentation.

 

Because of the way that acl:default takes the ACL and re-writes it onto child objects, then any object that is underneath gets the same permissions.

Because you would need the parent object to have the class defined in the acl:accessToClass, then why not specify acl:accessTo.

If instead you use acl:default and acl:accessToClass, then this seems to be a method to assign these permissions to a subset of the children (those with the specified class).

ie.

/rest/trunk

<> a pcdm-use:Image

/rest/trunk/fcr:acl

 <> a webac:Acl .
 <#auth1> a acl:Authorization ;
    acl:accessToClass pcdm-use:Image ;
    acl:mode acl:Read ;
    acl:agent "somebody" ;
    acl:default </rest/trunk> .

Then any child item that shares the type pcdm-use:Image would get these authorizations, others would continue up the tree.

Jared Whiklo, 2018-09-07 19:22 UTC

This could be a question of best practices. But I am seeing no use for the acl:accessToClass predicate without an acl:default in the same acl:Authorization. Maybe what I am suggesting is we code a best practice into the implementation and maybe that is a bad idea? But I really don't see why you use acl:accessToClass to refer to a single specific resource which is how our WebAC implementation works without an acl:default predicate.

This seemed more problematic when discussing with Aaron Birkland and Peter Matthew Eichman yesterday. But I am fine letting people use acl:accessToClass however they want, I'm just thinking people may expect this to work differently than it will.

If Aaron Birkland and Peter Matthew Eichman don't have a good reason, then I'm good with closing this and letting the cats run un-herded.

Peter Matthew Eichman, 2018-09-12 18:37 UTC

My current feeling on this is that we should not enforce this in the implementation, but instead make it clear in a best practices document that authorizations with acl:accessToClass without acl:default are likely to be useless, or not be doing what you think you are doing. (Until, of course, someone comes along with a strange edge case where it does make sense )

Peter Matthew Eichman, 2018-09-21 15:16 UTC
