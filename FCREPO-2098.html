Esmé Cowles, 2016-08-09 19:57 UTC

One potential issue here is that when a client gets a Weak ETag back for a LDP-RS, if it tries to use it in the If-Match header of a subsequent update, it will fail even if the resource hasn't changed.

A close reading of the current HTTP spec (https://tools.ietf.org/html/rfc7232) makes it clear that If-Match requires a strong ETag, so a client shouldn't send a Weak ETag in the If-Match header. Given the current implementation, where LDP-RSs always have Weak ETags, we should fail the If-Match test for all updates to LDP-RSs. Clients should use alternatives, such as using the If-Unmodified-Since header.
