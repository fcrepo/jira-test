Description

From a Fedora Tech Meeting on March 31st, 2016.

The goal of this issue is to create a way to automatically test release candidates as well as have a subset of those tests be available to be done manually. The subset of the tests which could be manually performed would be available to help new users learn how to work with the Fedora4 API.

The conversation focused creating a tool (TCK/script) that can be run to automatically test a release candidate, based on the list on the testing procedure pages [1][2].

Part of the tests in the tool could be exposed via some mechanism (HTML?) and made available for new users to learn how to use the Fedora4 API.

[1] https://wiki.duraspace.org/display/FF/Release+Testing+-+4.5.1
[2] https://wiki.duraspace.org/display/FF/Release+Testing+Procedures

Jared Whiklo, 2016-04-02 19:40 UTC

I've updated these tests quite a bit over the past couple of days.

I was able to get the fixity test to verify the fixity test result, however I stored the sha-1 result in the test as different machines and OSs will have different ways to generate it.

I added an indirect container test, which uses the pcdm:Collection example to test that the ldp:hasMemberRelation property is added to the ldp:membershipResource pointing to the correct resource.

These matching tests are simple (using grep, sed and string ==) but they work... so far.
