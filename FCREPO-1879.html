FCREPO-1879 Prefer header should determine response entity on LDPR creation

Is related toFCREPO-1878 On creation of LDPR, Content-Type is inappropriate to response entity

Description

"Prefer: return=minimal" should return the newly created LDPR URI in the format indicated in the Content-Type header (possibly matching the Accept request header).

"Prefer: return=representation" should return a representation of the newly created resource in line with a subsequent GET.

If a Prefer header is included, the response should include a Preference-Applied header.

The default behavior should be the minimal response, but not include a Preference-Applied header.

Benjamin Armintor, 2016-01-28 17:07 UTC

I'm agnostic (but persuadable), but I could see value in a minimal triple of:

<createdUri> a <ldp:ResourceSubclass>

especially since IIRC the LDP spec is vague about what RDF posted to a new resource should do in the absence of a specified interaction model (create a container of some kind, or a RDFSource, or what). But that's also in the Link@rel=type headers, presumably.

Esmé Cowles, 2016-01-29 12:50 UTC

I'm not sure how useful JSON, RDF or any other formats are for Prefer: return=minimal – we're just returning the URI, and the only use case I've heard for this is using curl from the command-line. Almost any other tool can get the URL of the created resource from the Location header just as easily. So I would think the minimal response would always be text/plain regardless of any Accept header.

If there is a use case for the minimal response in some other format, that's fine. But I don't think we should support content negotiation for it unless there's a real need for it.

Robert Sanderson, 2016-01-29 15:16 UTC

Benjamin Armintor Given that the URI is also in the headers, the class of LDP resource seems like a good single triple if we want to go that way. Also the information needs to be known before the response can be sent (it has to also be in the headers) so it's not like there's an additional cost to build the response, per A. Soroka's concern.
