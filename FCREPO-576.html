Description

This has been discussed before, just making a note of it here. This should go hand-in-hand with the move to make policies first-class objects in the Fedora repository. Ideally, we'd give the repository manager the option to cache policies in memory or use dbxml for repositories with a lot of policies.

An alternative to DBXML (and to a memory-based or simple file-based policy indexing/caching mechanism) could be exist - http://exist.sourceforge.net.

Benefits over DBXML

  • written in Java
  • deployable either as a servlet in the same container as Fedora, or separate (comes with Jetty to do this)

It is LGPL, therefore there should be no licensing issues distributing with Fedora and linking to it.

Stephen Bayliss, 2010-11-30 22:57 UTC

We should also consider a non XML database option. The XPath queries to be executed are not free-form, and are well-known (selecting a set of policies based on an essentially fixed set of XACML values). We could potentially move to a higher-level abstraction, ie the interface doesn't receive XPath queries but a data structure specifying the XACML values (and beneath this, where the implementation is an XML database, the XPath queries would get built).

So, index up front (in memory, SQL, etc) based on the known locations of the XACML values that will be searched upon.

Stephen Bayliss, 2011-03-11 16:56 UTC

Part 1: Simple in-memory PolicyIndex added. This maintains a local cache directory of policies which is cached in memory when the server starts. The index does not in fact do any indexing - queries for matching policies will return all policies for evaluation (similar to what the legacy XACML implementation does). Probably suitable where there is a small number of policies. Could be enhanced to do indexing.

Stephen Bayliss, 2011-03-27 15:10 UTC

Adding eXist support requires adding the XML:DB API to the distribution. xmldb.jar added to local repo, this needs adding to a maven repo. Currently added to pom as xmldb/xmldb-api/1.4

Source of this is from the eXist software distribution (but covered by XML:DB licence). XML:DB API licence added to Fedora licence directory.

eXist client files required (to make the XML:DB API work) are (from eXist distribution)

  • exist.jar (contains more than client classes, but there is no separate client jar)
  • xmlrpc-client-3.1.2.jar
  • xmlrpc-common-3.1.2.jar
  • ws-commons-utils-1.0.2.jar

Setup instructions need to reflect this (ie adding the above to the classpath, either Fedora's lib or some common location)
