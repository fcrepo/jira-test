Because the nt:file JCR type has a primary attribute on the jcr:content child node when you do a getNode() you actually get that child back.

I tried to make a new JCR type that had the timemap inside the jcr:content, but it didn't work for some reason. So I've altered the way we get the TimeMap when the resource is a binary.
