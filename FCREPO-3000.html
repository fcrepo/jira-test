Description

It appears that the inheritance algorithm is not working correctly with acl:default  when the authorization has an acl:default predicate that references a child resource of the acls owner.

To illustrate: 

Create the following resources:

 

curl -X PUT -u fedoraAdmin:fedoraAdmin http://localhost:8080/rest/box -i
curl -X PUT -u fedoraAdmin:fedoraAdmin http://localhost:8080/rest/box/cookies -i
curl -X PUT -u fedoraAdmin:fedoraAdmin http://localhost:8080/rest/box/cookies/cookie -i

PUT the following acl to  http://localhost:8080/rest/box/fcr:acl

 

@prefix acl: <http://www.w3.org/ns/auth/acl#> .
<#authorization1> a acl:Authorization;
 acl:accessTo </rest/box/cookies>;
 acl:default </rest/box/cookies>;
 acl:mode acl:Read;
 acl:agent "testuser".

Using the following command:

curl -X PUT -u fedoraAdmin:fedoraAdmin http://localhost:8080/rest/box/fcr:acl -H "Content-Type: text/turtle" -d "@acl.ttl"

Then:

 

 

# GET box produces 403 as expected
curl -u testuser:testpass http://localhost:8080/rest/box -i

# GET cookies produces 200 as expected
curl -u testuser:testpass http://localhost:8080/rest/box/cookies -i

# GET cookie produces 403 when it should return a 200 
curl -u testuser:testpass http://localhost:8080/rest/box/cookies/cookie -i

Jared Whiklo, 2019-06-05 15:07 UTC

This fix requires the addition of acl:default but for a specific Fedora only purpose. It is meant to say that things below inherit this ACL, but (and I'm doing some guessing here) because the ACL is actually on the parent the acl:default is the only important part. The system doesn't find an ACL on the child, then moves up to the parent and sees an acl:default so it passes it down.

I'd say that either

a) we change so that when the current resource doesn't have an ACL we move up the tree and check first for an acl:accessTo of the original resource and second for an acl:default for a parent. Having multiple AUTHZ in a single ACL means we need to ensure that the AUTHZ with acl:default is not for a child of the checked resource.

b) We don't respect acl:accessTo that is not the current resource. So you have acl:accessTo and acl:default or acl:accessToClass and acl:default to affect nested resources.

Danny Bernstein, 2019-06-06 18:57 UTC

We have decided not to support acl:accessTo and acl:default values that refer to children of the ACL's resource.
