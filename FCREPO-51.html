Background:

To protect against repeatedly attempting to ingest the same object when
iterating the lowlevel objects directory, the rebuilder keeps track of all PIDs
it has ingested so far. If it encounters one it has already seen, it skips it
and prints a warning.

Problem:

For large repositories, it's impractical to store all "seen" PIDs in memory.
Therefore, a memory-efficient int-based set is used in conjunction with
String.hashCode().

A hash collision arises when String.hashCode() returns the same value for two
different PIDs. This causes the second one to be skipped by the rebuilder.

The rebuilder no longer has this issue; it has been modified to NOT attempt early detection of duplicate objects in file storage during a rebuild. When such a situation occurs, it causes an error and requires manual cleanup.
