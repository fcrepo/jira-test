FCREPO-2895 Must Disallow PATCH of "ldp:contains" as (In)Direct ldp:hasMemberRelation

Description

Fedora should not allow the use of `ldp:contains` for the `ldp:hasMemberRelation` Object on Direct and Indirect containers.

In the example of Direct Containers, the following scenario should be prohibited:

  1. Create a resource
    > curl -i -u fedoraAdmin:fedoraAdmin -XPUT http://localhost:8080/rest/dresource
  1. Create a Direct Container:
    > curl -i -u fedoraAdmin:fedoraAdmin -XPUT http://localhost:8080/rest/d -H "Link: <http://www.w3.org/ns/ldp#DirectContainer>;rel=\"type\""
  1. Add Direct Container triples to the new container:
    > curl -i -u fedoraAdmin:fedoraAdmin -XPATCH http://localhost:8080/rest/d -H "Content-Type: application/sparql-update" --data-binary @direct.su
    ...where direct.su is:
    ```
    INSERT { <> <http://www.w3.org/ns/ldp#membershipResource> </rest/dresource> ; <http://www.w3.org/ns/ldp#hasMemberRelation> <http://www.w3.org/ns/ldp#contains> . }

    WHERE {}
    ```
    The above PUT should fail because "ldp:hasMemberRelation" is set to "ldp:contains"

Currently, in the above scenario, any resource that is added to </rest/d> will result in a triple on </rest/dresource> of the form:
</rest/dresource> ldp:contains <child-of-d>

...which is bad

Note 1: The above scenario should also be prevented for Indirect Containers.
Note 2: If using PUT in the above scenario with the Direct Container triples, the PUT fails as expected.
