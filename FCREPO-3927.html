Jared Whiklo, 2024-04-17 13:50 UTC

Close in this case you are making a regular BasicContainer so the ldp:hasMemberRelation is never acted upon. If you alter it to be

#!/bin/sh

ldp="http://www.w3.org/ns/ldp#hasMemberRelation"
fdra="http://fedora.info/definitions/v4/repository#any_predicate_will_do"
uuid=$(uuidgen)

curl -v -u fedoraAdmin:fedoraAdmin -X PUT -H"Link: <http://www.w3.org/ns/ldp#DirectContainer>; rel=\"type\"" --data-binary "<> <${ldp}> <${fdra}>." -H "Content-Type: text/turtle" "http://localhost:8080/rest/${uuid}"

You should get a 409 Conflict saying

hasMemberRelation cannot take a server managed property as an object: property value = http://fedora.info/definitions/v4/repository#any_predicate_will_do

Michael Ritter, 2024-04-17 20:09 UTC

Jared Whiklo thanks I see the 409 now. I did some digging because I was curious how this was handled in previous versions of Fedora and it looks like this used to be handled in ContentExposingResource#ensureValidMemberRelation which never checked against the container type.

I’ll update the test to add the DirectContainer header so that we see the 409 for the ldp:hasMemberRelation checks.
