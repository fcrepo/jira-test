FCREPO-54 Improve shutdown behavior with long-running requests

Description

Fedora's webapp shutdown currently relies on servlet container to ensure all requests are complete. However, the servlet container doesn't always wait until requests are finished in order to call destroy(). For long-running requests, this can be problematic because the resources (the db, etc) might be closed before the requests have a chance to finish.

According to

http://java.sun.com/j2ee/tutorial/1_3-fcs/doc/Servlets12.html

...this is not a good assumption. It can cause a long-running (over 2 seconds
in Tomcat, by default) API-M request to be abnormally terminated if shutdown is
occurring at the same time.

------- Additional Comment #1 From Chris Wilper 2006-05-12 13:24 [reply] -------

Workaround:

1) Disallow new API-M requests.
2) Wait for any existing requests to complete.
3) Stop the server.

For #1, this strategy should work:

You can stop any new requests from getting through to Fedora by putting a policy
in play (at runtime) that temporarily restricts access to API-M and API-A.

The following policy can be used as a starting point:
http://www.fedora.info/download/2.1.1/userdocs/server/security/xacml-policies/default/repository-wide/deny-apim-if-not-localhost.xml

After putting it in the correct place, use the fedora-reload-policies tool to
put it into play without stopping the server:
http://www.fedora.info/download/2.1.1/userdocs/server/cmd-line/index.html#reload

NOTE: Be sure to remove the "disallow API-M" policy before restarting the server
again.
