Asger Askov Blekinge, 2009-11-23 18:00 UTC

Added a new API method for creating a new object

Available in fedoraclient as createNew(Logmessage,PID), where both are optional.

Available in similar way for the SOAP method.

Surprisingly, and undocumented, the REST api already had this method

Asger Askov Blekinge, 2009-11-30 11:12 UTC

Modified the method.

The official method is not

createNew(String newPid, String state, String ownerid, String label, String logmessage) and returns the pid of the new object.

It is available in the soap api and in the fedora client.

It is registered as a new method for XACML.

I really hope this method will make it into Fedora before 3.3

Stephen Bayliss, 2010-11-30 01:30 UTC

If we wish to be consistent with the REST API we could consider management method ingest with a zero length/null input stream should create a "template" object in the same manner as the REST API does currently (ie move the functionality from the REST API to the SOAP API).

Stephen Bayliss, 2010-11-30 23:17 UTC

For info, the REST API treats as equivalent creating a new object (ie from template, no object xml supplied) and creating an object from a FOXML file (same XACML action - Constants.ACTION.INGEST.uri)

Chris Wilper, 2010-11-30 23:27 UTC

During committer discussion on Nov 30 2010, there seemed general agreement that this kind of capability (in addition to cloning) really belongs on a content model. But that it's ok address the disparity between the SOAP and REST APIs in this regard in the meantime. Passing no content to ingest is a reasonable approach for now.
