Description

Currently the root ACL (ie /rest/fcr:acl) is returned with a 200 http code when no user-defined root ACL has been PUT in place.  If an authorized user attempts to PATCH it,  a 404 is returned because there is no jcr node behind the endpoint.   This may confuse users. To dispel that confusion we should return 409 conflict with an textual explanation of the problem in the body (ie something like:  "The default root ACL is system generated and cannot be modified.  To override the default root ACL you must PUT a user-defined ACL to this endpoint.  Once a user-supplied ACL has been created, it may be modified using PATCH or deleted.").
