Description

Purpose: For chunked downloading and better support of various HTTP1.1-savvy utilities and services (including WebDAV clients, httpfs, etc..)

Description: Fedora should provide Content-Length in GET and HEAD response headers when this information is easily available. When practical, the Content-Range header (partial read) on GET request should also be supported.

Details: Support of both should be possible for any Fedora HTTP request that maps to exactly one Inline or Managed datastream in the repository. This includes:

1) getDatastreamDissemination
2) getDissemination (where the input maps directly to an X or M datastream and does not go through a service)

Stephen Bayliss, 2010-11-01 13:10 UTC

A couple of comments.

The size for managed content datastreams is preserved as a datastream (version) attribute in the FOXML. The size is calculated in DefaultDOManager.doCommit, see lines 1210, 1215, 1218. The ILowLevelStorage interface was modified in 3.4 to return the stream's size on addDatastream and replaceDatastream (this is supported by Akubra, but potentially may not be supported by external ILowLevelStorage implementations).

It sounds reasonable to me to use MIMETypedStream to carry this information. MIMETypedStream currently has a "header" field (org.fcrepo.storage.types.Property[]). The header field is currently set for example to return a content-disposition header indicating the filename to be used for a datastream; and the BaseRestResource.buildResponse returns the contents of this header field (and others, potentially including content-length) as HTTP headers. So it would seem the route to go down if MIMETypedStream could consistently be populated with the appropriate content-length header.

Probably need to think about what to do for external content, whether we persist the size in the FOXML, when to update this size (for instance, a HEAD request to the external content and inspection of last-modified/etags to determine if the size is "current") - I think there were some discussions about this at a committer's meeting.
