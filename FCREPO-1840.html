FCREPO-1840 Incorrect Accept header should return an appropriate 4xx status code

StatusClosed
ResolutionFixed

Description

When making a GET request with an incorrect mimeType, e.g. "Accept: application/turtle", fedora responds with a 500 status code. It should, instead, respond with a 400 code.

Unknown, 2015-12-22 14:30 UTC

That is not the way to resolve this ticket, IMO.

The reason this works is due to the fact that 406 errors are generated upon trying to look up a suitable RDF writer from the supplied Accept header. If none exists, the 406 is thrown, which basically overrides what JAX-RS is already designed to handle by implementing this ourselves (a bad design, IMO): http://git.io/vEZuu

The same thing can be achieved by removing the */* attribute to the FedoraLDP class: http://git.io/vEZBF

That behavior makes much more sense in my opinion. It does have the drawback that you can't send an Accept header for Binary resources (I'm not sure what an Accept header would mean for Binary resources, though).
