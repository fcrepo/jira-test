Description

Uploading an Ogg Vorbis file to fcrepo4 results in a stacktrace (see https://github.com/fcrepo4/fcrepo4/issues/893).

This may be related to this dependency and exclusion: https://github.com/fcrepo4/fcrepo4/blob/master/fcrepo-boms/fcrepo-jcr-bom/pom.xml#L24 – we're excluding some of the vorbis-java components because they require an older version of Tika than we're using. The versions mentioned in the comments are much older than the current requirements of the vorbis-java package, so this may be as simple as updating the pom.xml to use current versions of the related packages.

Former user, 2015-08-28 17:58 UTC

As it turns out, just uploading the content "OggS" is enough to trigger this bug:

curl -X PUT --data-binary OggS http://localhost:8080/rest/$RANDOM

Luckily, the fix is just as easy: we have some exclusions for the vorbis-java-tika package (because an old version was pulling in an old version of tika). But removing those exclusions and bringing in the current versions of those packaged used by Modeshape fixes this bug. I've pushed an IT to demonstrate this (see https://travis-ci.org/fcrepo4/fcrepo4/builds/77721025). I've updated the PR with a second commit that removes the vorbis-java-tika exclusions: https://github.com/fcrepo4/fcrepo4/pull/894
