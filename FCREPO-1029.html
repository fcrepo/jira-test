Description

Ensure that any failure in doCommit() logs an error message, not a warning - specifically any failure due to failing to update the objectStore, datastreamStore, registry, fieldSearch or resourceIndex should be logged as an error.

Tidy up the ingest recovery vs purge code. Currently the purge code is re-used as ingest tidy-up to remove any artefacts that were committed due to a failed ingest. These are separate concerns. Specifically failures on purge should be logged as errors; whereas failure to remove a failed ingest artefact could be a warning due to an ingest failing part-way through.

Logging tidied up to report updates to storage, index etc as errors (and also include pid in messages).

Object removal code moved to separate method, with a "failSafe" parameter; true indicates warn only, false indicates we were doing a purge and therefore any error removing artefacts is an error condition.

We could in future change behaviour to throw an exception if a purge fails; or would it be better to report the error and continue (since the repository can still be used; albeit with potential inconsistences in the storage).
