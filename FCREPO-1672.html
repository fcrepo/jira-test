Description

At present, Fedora depends on Jena 2.12.1

The 3.x series has just been released. After some initial investigation, there are a few issues related to upgrading to the new version at this point.

Two minor issues relate to dependency conflicts between the fedora libraries and the LDP integration tests (which uses 2.12.x). The fcrepo-transform module also depends on an older 2.x version of the Jena API.

In the fedora kernel, the main change from 2 to 3 involves how string literals are represented. With RDF 1.1, there is no difference between the literal "abc" and "abc"^^http://www.w3.org/2001/XMLSchema#string. But at present, they are serialized differently in the JCR layer. Transitioning to Jena 3 would require normalizing how those string literals are persisted.

Esmé Cowles, 2015-12-15 15:36 UTC

Unknown: I took a look at Jena 3.0 and saw the same issue you've outlined. I think for the change to how untyped literals are handled, we could just update the tests to expect the typed version to be emitted. And then it would be good to make sure that untyped literals are stored in JCR as string typed. I'm less sure about what we'd do for the LDP TCK. It hasn't been updated for a new version of Jena, but I suppose we could update it ourselves (presumably they'd accept a PR along those lines, and we could use our fork until that happens).

This strikes me as much the same issue as FCREPO-1799: there are some changes in RDF 1.1 that break RDF 1.0 handling in small and subtle ways. So I think an important consideration is whether RDF 1.1 adoption is happening quickly enough that we need to push forward with it, or whether it's more important to maintain RDF 1.0 support. I don't know how quickly RDF 1.1 adoption is going. I wonder whether you (or A. Soroka or cb) have a better sense on that?

A. Soroka, 2015-12-17 15:30 UTC

I don't think RDF 1.1 adoption is the most important thing (he wrote, as someone who thinks the "no type is string type" move was a big mistake). The important thing is all the improvements we get for upgrading Jena's internals (he wrote, having made some of those PRs). That's worth the price of normalizing output. I don't quite agree with Esmé Cowles that just normalizing to string-type all over is the best approach. I think we should record the type and return it. That should pass all correctly-written tests.
