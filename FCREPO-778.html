The Dublin Core datastream appears not to be validated (looking at org.fcrepo.server.validation.ValidationUtility and elsewhere). Maybe that is by design? Noted in 3.4 but probably the case in earlier versions.

Is there an XML schema to which we can refer? It's not immediately clear to me from the documentation what validity means exactly for the DC datastream, but perhaps I'm missing it...

Stephen Bayliss, 2012-01-03 15:13 UTC

It's the OAI DC schema. www.openarchives.org/OAI/2.0/oai_dc.xsd - xsi:schemaLocation="http://www.openarchives.org/OAI/2.0/oai_dc/

There's a copy in the fcrepo-server/src/main/resources/xsd directory

A. Soroka, 2012-01-03 20:59 UTC

Then I don't see how it could be "by design". Seems like an open-and-shut bug to me.

It also raises (in my mind) a question I put to Chris Wilper some weeks ago-- is it time to examine Fedora's XML processing as a whole and look to factor out validations, transformations, etc. to some purposed infrastructure (by pooling transformers, etc.)?

Stephen Bayliss, 2012-01-04 13:49 UTC

There could be issues with existing repositories which could potentially contain invalid DC and how this should be dealt with, if validation is added.

Agreed that factoring out XML processing into one place and pooling transformers etc would be an excellent move.

A. Soroka, 2012-01-04 21:11 UTC

Off the top of my head, my suggestion would be to enable validation only at ingest (leave old content be) and document the new behavior loudly!

Factoring out XML services would be exactly the kind of place that OSGi whiteboard pattern μservices really shine. Might be a good place to "put in the thin end of the wedge" towards OSGi. I'll raise the question at the next committers' call and perhaps we'll open an issue.
