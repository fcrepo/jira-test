FCREPO-3951 Transactions not rolled back after timeout if there are existing requests

Description

During testing, we encounter the problem that the automatic transaction rollback (https://wiki.lyrasis.org/display/FEDORA6x/Transactions) is not applied if at least one reuqest has been sent to the transaction. In this case, the transaction remains uncommitted until the manual rollback is performed. If transaction is empty it is correctly rolled back after the period set in the config file.

Ben Pennell, 2024-09-23 19:05 UTC

Hopefully this PR should either help with or resolve the issue:

https://github.com/fcrepo/fcrepo/pull/2093

The expiration times of transactions were having the timeout period added to them every request rather than being set to the now+timeout. The result was that if you made a lot of requests in a transaction, each one would add 3 minutes to the expiration time. For example, making 100 requests (read or write) gives you an expiration time 300min after the transaction was started. So it could effectively produce transactions that never seem to timeout.
