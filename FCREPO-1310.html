Description

The processor classes in fcrepo-camel will transform an RDF representation of a fedora node into a SPARQL-Update query capable of being sent to an external triplestore. It would be useful to be able to optionally store these in named graphs.

The implementation should accept a new header value, for example CamelFcrepoNamedGraph, which would allow for dynamic changes to this value without needing a separate processor class.

It's for the external triplestore. The current processor classes will take an RDF graph and format it into a sparql-update query for use with an external triplestore. Those queries, however, don't support named graphs, which may be useful in several different contexts. The idea is that if an appropriate header is present, the sparql-update query will add a GRAPH <graph-name>

{ ... }

wrapper to the queries.

Unknown, 2015-01-28 17:08 UTC

fcrepo-camel doesn't make the triplestore request. The request would typically be made with the camel-http4 component like this:

from("fcrepo:localhost:8080/rest")
.process(new SparqlUpdateProcessor())
.to("http4://triplestore-host:8080/ds/update");

In this example, the RDF body is picked up from fedora, based on the value of the CamelFcrepoIdentifier header; it is then passed to the SparqlUpdateProcessor processor, which converts the payload into a sparql-update body; and finally the payload is POSTed to the triplestore with the appropriate headers. The processor classes are really just convenience classes for implementors. The proposal is to support this:

from("fcrepo:localhost:8080/rest")
.setHeader(FcrepoHeaders.FCREPO_NAMED_GRAPH)
.simple("default.graph")
.process(new SparqlUpdateProcessor())
.to("http4://triplestore-host:8080/ds/update");

This provides the ability to dynamically set a named graph for these processor classes so that the payload that is sent to the external triplestore contains the appropriate GRAPH <>

{ ... }

syntax.
