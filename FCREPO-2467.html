Esmé Cowles, 2017-05-22 16:38 UTC

FWIW, I did see some issues relating to having a source with a slash and a destination without, or vice versa.  I considering munging the URLs to make sure they both had slashed, but decided against it because it would limit the flexibility.

Maybe we should check for the mismatch and log a warning?

Situ, Longshou, 2017-05-22 17:27 UTC

Esmé Cowles I see it works with the following command that exclude the slash:
$ java -Dfcrepo.log.importexport=DEBUG -jar target/fcrepo-import-export-0.1.1-SNAPSHOT.jar -a -d data -m import -M http://localhost:8686/f4/rest,http://localhost:8080/fcrepo/rest -r http://localhost:8080/fcrepo/rest/

While it'll fail with status 404 for the wrong server address (which were converted to http://localhost:8686/fcrepo/rest/book0) when append a slash to both the source and resource:
INFO 10:08:39.054 (Importer) Importing container .../data/fcrepo/rest/book0.ttl to http://localhost:8686/fcrepo/rest/book0
ERROR 10:08:39.108 (Importer) Error while importing .../data/fcrepo/rest/book0.ttl (404) ...

I am fine with either way that you want, update README, responds with an informative error message, allow the maps to include or exclude a trailing slash, or ... I haven't worked on it yet. Just feel free to make any changes. Thanks.

Andrew Woods, 2017-05-22 17:44 UTC

Esmé Cowles: what flexibility limitations do you have in mind?

 I considering munging the URLs to make sure they both had slashed, but decided against it because it would limit the flexibility.

Esmé Cowles, 2017-05-22 18:35 UTC

I was thinking about mappings where you wanted to replace a slash with something else, e.g.:

http://localhost:8080/rest/dev/a to http://localhost:8080/rest/dev-a
http://localhost:8080/rest/dev/b to http://localhost:8080/rest/dev-b

or wanted to make a change that wasn't terminated at a slash, e.g.:

http://localhost:8080/rest/aabb to http://localhost:8080/rest/xxbb

Esmé Cowles, 2017-05-23 15:08 UTC

Would logging a warning when one URI ended with a slash and the other didn't be good enough here?  I agree that they should typically match, but would like to avoid munging the URIs (since that would frustrate users trying to do mappings that depended on the mismatch).

Situ, Longshou, 2017-05-23 15:20 UTC

Esmé Cowles I think the major issue is that it fails when both the source/resource have slash appended at the end. Something weird and it seems like a bug somewhere.
