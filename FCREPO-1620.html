Description

The HTTP spec isn't particularly clear, but blog posts like this:

http://blog.iandavis.com/2010/11/a-guide-to-publishing-linked-data-without-redirects/

make it sound like we should be adding a Content-Location header when we generate content-negotiated responses. The implication of this would be each RDF serialization would need to have its own URL (e.g., http://localhost:8080/rest/resource.json).

Esmé Cowles, 2016-02-10 15:32 UTC

If we were still doing strong etags, then I think it would make sense to create a separate URI for each representation, with an associated etag. This would let us continue to serve different representations, but also let us provide a distinct URI for each one.

As it is, we've switched to weak etags, so I think this is moot.
