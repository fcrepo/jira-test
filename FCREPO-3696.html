Description

I noticed this problem when doing some optimization the search tables with a repo with 1.5 million object.

It appears that a simple read operation such as
curl -u fedoraAdmin:fedoraAdmin http://localhost:8080/rest/
passes a transaction id to the containment index which in turn causes it to use ContainmentIndexImpl.SELECT_CHILDREN_IN_TRANSACTION  which is much slower than the lighter weight  ContainmentIndexImpl.SELECT_CHILDREN which is used when the transaction id is null.  Since we're always using a transaction, we are always using the more complicated and slower query.
