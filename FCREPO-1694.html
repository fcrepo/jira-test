Description

If our separation of API and implementation is complete and correct, no non-deployable module should depend on fcrepo-kernel-modeshape except via Maven scope "test". This explicitly excludes deployable modules like fcrepo-webapp.

Unknown, 2015-08-12 12:09 UTC

I would also note that almost all of the modules (including fcrepo-kernel-api) depend on org.modeshape/modeshape-jcr-api (e.g. org.modeshape.jcr.api.JcrConstants).

Furthermore, fcrepo-auth-common and fcrepo-connector-file also depend directly on org.modeshape/modeshape-jcr (as opposed to org.modeshape/modeshape-jcr-api)

Other than (perhaps?) fcrepo-connector-file, I would think that the only dependencies (transitive or direct) on anything modeshape-related should be confined to the fcrepo-kernel-modeshape module.
