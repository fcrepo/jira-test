Description

The current implementation of fcrepo-camel allows a user to interact with a remote fedora repository over https by setting the secure=true URI parameter.

I do not think this is a good implementation. It is error prone and departs from how this is handled in other camel components (such as http4).

The better implementation would remove the 'secure' option and instead use the https:// protocol if the fedora port is set as 443 (otherwise using http://). I am not convinced that there is a use case for using https:// with non-standard ports (e.g. 9443), and as it stands, this seems like an unnecessary option.

If that use case emerges, we can revisit this decision.

Just a note, this change provides additional flexibility with the format of the "baseUrl" value. Up until now, the format had to be fcrepo://fedora.host.org:8080/rest (where the hostname, port and path are arbitrary).

Now, it is possible to write:

fcrepo://fedora.host.org:8080/rest (as before)
fcrepo://http://fedora.host.org/rest (for connections with explicit schemes)
fcrepo://fedora.host.org:443/rest (for secure connections)
fcrepo://https://fedora.host.org:9443/rest (for secure connections on non-standard ports)

This brings the component more in line with how the camel-http4 component works in this regard.

NB, as with all camel components, the initial forward slashes can be omitted without changing the meaning of the route. These two uris are equivalent:

fcrepo://fedora.host.org:8080/rest
fcrepo:fedora.host.org:8080/rest

And that same variation applies to all of the examples above.
