FCREPO-2855 Only one of acl:accessTo or acl:accessToClass should be allowed in an Authorization

Description

Because the acl:default predicate means that the specified Authorization should be shared to child resources, then there is no reason to specify both of the acl:accessTo and acl:accessToClass.

acl:accessToClass would allow you more options (see FCREPO-2854 Closed ).

But acl:accessTo would be re-written to the child objects URI, voiding any acl:accessToClass statements.

ie.

/rest/test_object

<> a example:Box .

/rest/test_object/fcr:acl

<> a webac:Acl .

<#auth1> a acl:Authorization ;
   acl:mode acl:Read ;
   acl:accessTo </rest/test_object> ;
   acl:accessToClass example:Box ;
   acl:agent "Bob" ;
   acl:default </rest/test_object> .

Any child (ie. /rest/test_object/child) would see an effective Acl of

<> a webac:Acl .

<#auth1> a acl:Authorization ;
   acl:mode acl:Read ;
   acl:accessTo </rest/test_object/child> ;
   acl:accessToClass example:Box ;
   acl:agent "Bob" .

 

Therefore it is probably better to disallow having both acl:accessTo and acl:accessToClass in the same authorization.
