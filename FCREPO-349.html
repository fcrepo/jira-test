Comment Submitter: cwilper
Merged into trunk r7522. Changelog below:

Auto-ingesting system content model objects
(which are read-only) and use standard FORMAT_URIs and
MIMETYPEs for system content model-defined datastreams.
As of this checkin, the validation utility correctly validates all
demo objects.

Full log for this changeset:

Formats:
Added appropriate format objects (and schemas where
appropriate) for all fedora-defined special datastreams.
This includes RELS-EXT, RELS-INT, METHODMAPs, etc.
Demo object updates:
Consistency (also done for system objects):

  • all special datastream now assert an appropriate FORMAT_URI.
  • formatting (pretty-printed w/2-space indents, 80 column wrap)
  • ordering (DC, then RELS-EXT, then cmodel-specific)
  • object labels (indicates kind of object and demo it's a part of)
  • datastream labels (for all special datastreams)
  • SIZE attribute removed from all demo foxml datastreams
  • VERSIONABLE=true for all RELS-EXT (was mixed)
  • Removed DISABLED/none checksum info for system + demo objects
    (when the element is absent, it has the same meaning)
    Other cleanup:
  • Demo DS-COMPOSITE-MODELs no longer state that DC
    and RELS-EXT are required (this is done by the
    FedoraObject-3.0 content model)...unless the content model
    in question specifically requires the existence of one of those
    datastreams (as is the case with the smiley demo)
  • Removed one demo object's AUDIT datastream
    (was side effect of demo obj creation)
  • Removed special datastreams formerly created by bdef/mech builders:
    (SERVICE-PROFILE and DS1 "programmer documentation")
  • Removed a RELS-INT (was side effect of former METS serialization,
    but don't want to highlight RELS-INT in any demos 'till refactoring
    #1814088 is resolved)
  • removed unused test objects
  • fixed remainder of test/doc objects (in code and otherwise)
    to use format uris and consistent labels for DC, RELS-EXT,
    METHODMAP, DSINPUTSPEC, and WSDL datastreams.
  • Made sure example POLICY datastreams use the XACML_POLICY1_0
    FORMAT_URI.
    Deserializer changes:
  • When deserializing legacy format objects, consistently
    puts the old fedora-model:cModel and rdf:type attributes
    into the DigitalObject's extProperties.
    Serializer changes:
  • Optional SIZE attribute not serialized when = 0
  • Fixed bug #2006837: Inconsistent use of none vs. DISABLED
    for ds checksums.
  • Optional CHECKSUM and CHECKSUMTYPE not serialized
    when not present (or "none"/"DISABLED", as this means the
    same thing)
  • METS Ser/Deser no longer attempts to "take over" FORMAT_URI
    if it's already defined.
  • Made sure AUDIT datastreams are written with the POLICY1_0
    FORMAT_URI and a consistent label.
    Demo object conversion:
  • generates pretty-printed mets, atom, and atom-zip formats at build
    time (tests updated accordingly)
  • added -Ddemo.format=atom-zip option for tests
    Admin GUI:
  • Updated client-created datastreams and default DC with
    standard format uris and labels.
  • Made client-created DS-COMPOSITE-MODEL not use DC as
    example.
    Misc other cleanup:
  • When ingesting legacy format objects, automatically
    updates any system-defined datastreams with the
    appropriate MIMETYPE and FORMAT_URI.
  • Replaced occurances of CMDA with CMA
  • Relaxed RELSExtValidator so that it allows self-referential
    relationships (necessary because ContentModel-3.0
    has itself as a content model). There has never been
    a danger to having self-referential relationships, so this
    was kind of a bogus rule anyway.
  • Removed requirement in BatchModifyParser that inline XML
    has text/xml MIMETYPE.
  • Fixes DOTranslationUtility's static initializer so that it
    gets configuration from Server.getConfig(), which doesn't
    require a server instance to be running.
  • Removed most occurances of SERVICE-PROFILE
