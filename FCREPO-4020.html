Description

Upgrading to Jersey 3 and Apache Jena 5.4.0 resulted in Jena hanging when parsing the simplest turtle documents. Some of these seems to be due to Jena being much stricter about syntax and streams.

Some test work was to buffer the stream internally to Fedora in the HttpRdfServeice with

private static Model parseInMemory(final InputStream bodyStream, final String extResourceId, final Lang format)
    throws IOException, RiotException, RuntimeIOException {
        final byte[] body = bodyStream.readAllBytes();
        try (InputStream in = new ByteArrayInputStream(body)) {
            final Model inputModel = createDefaultModel();
            RDFDataMgr.read(inputModel, in, extResourceId, format);
            return inputModel;
        }
}

private static Model parseAsTemp(final InputStream bodyStream, final String extResourceId, final Lang format)
        throws IOException, RiotException, RuntimeIOException {
    final Path tempFile = Files.createTempFile("fedora-upload-", ".rdf");
    try (OutputStream out = Files.newOutputStream(tempFile)) {
        bodyStream.transferTo(out);
    }

    try (InputStream fileIn = Files.newInputStream(tempFile)) {
        final Model inputModel = createDefaultModel();
        RDFDataMgr.read(inputModel, fileIn, extResourceId, format);
        return inputModel;
    } finally {
        Files.deleteIfExists(tempFile);
    }
}

But it also seems to fail in the fcrepo-auth-webac filter, buffering there did not resolve the issue immediately.
