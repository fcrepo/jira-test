Description

Datastreams and Objects both have a state, which can be A (active), I (Inactive), or D (deleted). Those states should be represented in the migrated OCFL object.

For D or I datastreams, the datastream versions should be migrated over as normal, but in a subsequent OCFL version, those D/I datastreams should be removed, so they don't show up as active files in OCFL.

For D or I objects, the content should all be migrated into OCFL as normal, but then the object should be marked as deleted somehow. One possibility would be to remove all the files in the final object version, or maybe there's another native OCFL way to mark an object as deleted.

Yup, this one is done too The behavior is that by default I streams are migrated the same as A streams, but have a triple that indicates that they are inactive. There is a flag on the migration util that can be used to treat I resources the same as D's. That is to say, they are migrated and then deleted so that they appear as tombstones.
