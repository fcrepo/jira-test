Description

AtomZIP files specify src giving the content location. Exported objects in AtomZIP format give this as simply the file name (within the zip).

The current validation code tries to validate this location and fails.

Comments (4)

Stephen Bayliss, 2012-02-21 01:43 UTC

Managed datastreams in FOXML use the file: protocol - so there is I guess an open question as to whether the AtomZIP format should specify this as well? But file: is usually a full path; in this case it's referring to content in the zip, so it's not really a file... And for Archive export format the managed content in any case is embedded in the FOXML in Base64... (so no file: in this case)

If we modified AtomZIP to use file: it would break archived content and prevent it being imported (although if that content had managed streams it can't currently be imported in any case due to this bug; but it would break existing objects that only have inline datastreams).

Stephen Bayliss, 2012-02-21 17:13 UTC

1 line fix to remove validation of the datastream filename in the zip file (as it's not a URL or a file: protocol) has been committed.

Should leave this ticket open though as this is pointing to a lack of tests for ingesting objects using AtomZIP (from memoryi sn't there a parameter that can be supplied to control ingest format for the integration test suite?)
