Esmé Cowles, 2016-06-23 13:40 UTC

Yes, this is with the PostgreSQL backend. The data follows the CurationConcerns/HydraWorks pattern:

  • one container for the object which has a `members` IndirectContainer
  • one container for each source file (a FileSet) — this container has a `files` DirectContainer, where two binaries are added (a 100MB TIFF image and a ~50KB HTML file)
  • each of the FileSets has a proxy added to the object `members` container.
Esmé Cowles, 2016-06-24 14:33 UTC

I've tried a few different things, and have only been able to reproduce the error with the configuration I was using:

  • Using MySQL instead of PostgreSQL worked without errors
  • Ingesting on my local machine with PostgreSQL 9.4 worked without errors
  • I'm currently testing PostgreSQL 9.5 (instead of 9.3) to see if that resolves the problem
Esmé Cowles, 2016-06-24 19:34 UTC

This problem was fixed by using PostgreSQL 9.4 or 9.5. I've updated the wiki docs to indicate these versions should be used with Modeshape5: https://wiki.duraspace.org/display/FEDORA4x/Configuring+JDBC+Object+Store
