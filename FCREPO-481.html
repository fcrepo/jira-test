FCREPO-481 FieldSearch fails when 'pid' not selected

Description

Janna Wemekamp reports:

Fedora's search functions fail with the following error if the pid column isn't requested as part of the result set:

javax.ws.rs.WebApplicationException: fedora.server.errors.StorageDeviceException: Error with sql database. The column name pid was not found in this ResultSet.

This is true of the 'search' web interface and the REST API.

Eg.
http://localhost:8080/fedora/objects?title=true&identifier=true&terms=&query=pid~demo%3A*&maxResults=20
http://localhost:8080/fedora/search?title=true&identifier=true&terms=&query=pid~demo%3A*&maxResults=20

Comments (2)

Chris Wilper, 2009-04-20 17:30 UTC

Verified. Workaround is to request the pid even if it's not needed.

This is caused by FieldSearchResultSQLImpl.step requiring the pid to exist in the ResultSet even though it's not requested in the SELECT.

It looks like step() really does require this, so when building the query internally, the SELECT should ask for the pid regardless of whether it's returned to the caller.
