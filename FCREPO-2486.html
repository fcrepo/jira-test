Joshua Allan Westgard, 2017-05-25 13:43 UTC

This bug was created with the addition of a new feature of import/export, and at first glance it's going to be a bit complicated to deal with. The current behavior is that the verifier simply excludes nonRDFsource resources and files on disk with the .binary extension when it is traversing the tree of resources to check.

Now in addition we'll need to filter the rdf to remove references to binaries from the origin resource before comparing to the destination resource. Determining which triples to filter out could be a little bit tricky.

Situ, Longshou, 2017-05-25 16:51 UTC

Joshua Allan Westgard I agree. Maybe at least we need to a way to address this issue so that users won't try the verification tool with binary excluded? It seem like that users may use a simple command like "java -jar bin/fcrepo-import-export-0.1.1-SNAPSHOT.jar -d data -m export -r http://localhost:8080/fcrepo/rest" to export a dataset without the binary (-b) option and verify it at the very beginning, which could be disappointed with those mismatching messages. Joshua Allan Westgard, 2017-05-25 17:34 UTC

Esmé Cowles, thanks. I think we could. Just to make sure I understand, the logic is:

  1. for each rdf resource get the graph
  2. find all the triples with objects that begin with the repository base
  3. do a head on each one and if it is a binary, filter that triple
