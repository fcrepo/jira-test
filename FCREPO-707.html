Description

listDatastreams request (format=xml) returns a response that does not validate. For example, http://localhost:8080/fedora/objects/fedora-system:ContentModel-3.0/datastreams?format=xml

returns a response that is missing the default namespace declaration, and the schemaLocation has an invalid location (at least via REST API)

Comments (3)

eddie, 2010-05-29 03:05 UTC

As a followup, I believe the following corrections need to be made:
1. declare default namespace, e.g.: xmlns="http://www.fedora.info/definitions/1/0/access/"
2. correct schemaLocation to: xsi:schemaLocation="http://www.fedora.info/definitions/1/0/access/ http://www.fedora-commons.org/definitions/1/0/listDatastreams.xsd"

Finally, it looks like we're serializing the listDatastreams response in two different places (ListDatastreamsServlet and DefaultSerializer), depending on whether it's in response to a SOAP or REST call and in the latter case, we're providing an invalid location, e.g. http://localhost:8080/listDatastreams.xsd

Chris Wilper, 2010-06-01 16:36 UTC

What's the impact on existing clients for this fix? Does this go in 3.4? (commits are to trunk thus far)

eddie, 2010-06-01 18:17 UTC

Impact is probably similar to the changes necessary in TestAPIALite: if you were relying on xpaths to parse the results, the xpath expressions are going to have to be namespaced as well.
