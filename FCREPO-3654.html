Environment

CentOS 7, two filesystems of type xfs

Description

When I attempt to run the fcrepo-webapp one-click application with fcrepo.home set to a path that is a symlink, the application cannot read the location and throws a java.nio.file.FileAlreadyExistsException.  If I change the location to the explicit path, the application starts up without a problem.

This is the symlink.  Note that /home and /opt are on different filesystems (though that shouldn't make a difference).  The symlink is soft.

lrwxrwxrwx. 1 root root 37 Feb 23 19:11 /opt/fedora6 -> /home/sprater/projects/fedora/fedora6

 

Here is a sample command line, with fcrepo.home pointed to the symlink:

java -Dfcrepo.home=/opt/fedora6 -Dfcrepo.ocfl.root=/opt/ocfl/data/ocfl-root -jar fcrepo-webapp/target/fcrepo-webapp-6.0.0-SNAPSHOT-jetty-console.jar

Attached is a log with the full output and stack trace when fcrepo.home points to a symlink.

Scott Prater, 2021-02-24 16:01 UTC

Upon further testing, the error is only thrown when the entire path points to a symlink, not when one of the parent directories in the path is a symlink.

Example that works:  /opt/fedora -> /home/projects/sprater/fedora;  fcrepo.home=/opt/fedora/fedora6
Example that fails:  /opt/fedora6 -> /home/projects/sprater/fedora/fedora6;  fcrepo.home=/opt/fedora6

The same issue occurs when fcrepo.ocfl.root is set to a path the ends in a symlink.  May be an issue for any property that is a path?

Peter Winckles, 2021-02-24 16:07 UTC

Unfortunately, it sounds like this is the intended behavior of the API:

https://bugs.openjdk.java.net/browse/JDK-8130464

We'll need to check if the path exists before calling Files.createDirectories
