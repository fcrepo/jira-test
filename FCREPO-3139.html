Description

This ticket is to design some disambiguation pattern for filenaming in the OCFL persistence layer when conflicts occur.

In general the identifier a user provides will be used all the way to the OCFL persistence layer to make it more "readable". But in certain cases file naming conflicts will occur.

Example

The current design pattern of a Archival Group would allow for the following overlap

license.txt # user creates
license.txt-description.nt
license.txt-description.nt # user creates
license.txt-description.nt-description.nt

The user generated license.txt-description.nt would attempt to overwrite the Fedora generated file of the same name.

We need to alter one of these filenames (Probably the second created one) and still track the relationship somehow to the original identifier. Please figure out how we want to do this.
