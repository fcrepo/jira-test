Description

Now that NonRdfSourceDescription properties are actually stored on the associated Binary resource, when the client is updating /fcr:metadata its etag (read: caching) is not affected.
To reproduce:

  • curl -XPUT -H"Content-Type: image/jpeg" --data-binary @image.jpg http://localhost:8080/rest/picture
    • Use your own jpg file
  • curl -I http://localhost:8080/rest/picture/fcr:metadata
    • Note etag value
  • curl -i -XPATCH -H"Content-Type: application/sparql-update" --data-binary @update.su localhost:8080/rest/picture/fcr:metadata
    • "update.su" is attached
  • curl -I http://localhost:8080/rest/picture/fcr:metadata
    • Note etag has not changed
