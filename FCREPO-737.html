Chris Wilper, 2010-07-04 20:44 UTC

All schema issues reported by Mark are fixed, except the WSDL issue.

There are actually a few problems regarding the WSDL:
1) The WSDL-SCHEMA datastream of the fedora-system:ServiceDeployment-3.0 object is never ingested properly. If you look at the source, the XML declares that the CONTROL_GROUP is "X" but it's referenced. Interestingly, validation of the object at ingest time doesn't catch this fact and silently ignores it, so that the WSDL datastream is actually never found.
2) Given that the WSDL-SCHEMA datastream, referenced by the DS-COMPOSITE-MODEL of the object is absent from the content model object, I would also think this would cause a runtime error to occur when the new ECM method "validate" is called via the REST API. No such error occurs.
3) A cursory glance at the actual wsdl schema at xmlsoap.org indicates that several of the demo objects, as well as the example service deployment object in the wiki page, are wrong for the reason Mark indicated ("/" and " " are not allowed in NCNames)
