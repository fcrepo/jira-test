FCREPO-763 Ability to validate FeSL policies

TypeStory
StatusClosed
ResolutionWon't Fix
PriorityMinor
ReporterChris Wilper
Created2010-08-10 18:48 UTC
Updated2015-01-16 20:59 UTC
Resolved2015-01-16 20:59 UTC
Componentslegacy - Fedora, legacy - FeSL
Affects versionsFedora 3.x trunk

Description

The validate-policy.sh/.bat script that comes with Fedora assumes the v1 XACML schema, but FeSL policies use the v2 XACML schema. Although FeSL Authorization is still considered experimental, it would be good to have a way for people to validate the newer-style policies.

Comments (3)

Stephen Bayliss, 2011-04-08 15:15 UTC

FESLPOLICY datastream contents is validated on create/update against xacml 2.0 schema - should we close this issue? The script is useful for legacy xacml policies but doesn't seem useful for FeSL now that policies are stored in object datastreams.

Greg Jansen, 2013-01-23 20:37 UTC

This script does not seem to be updated for XACML 2.0 in release 3.6.2. It was unable to recognize my Policy element until I changed the schema back to XACML 1.0. I think we do still need this script. It is easy to deploy a broken policy and render the repository unresponsive. Backing out policies for troubleshooting requires several steps, including turning off authorization.

Looks like updating the script only involves changing a 1 to a 2 in env-server.sh or env-server.bat.

Andrew Woods, 2015-01-16 20:59 UTC
