Description

The fcr:fixity endpoint responds oddly to invalid request methods. Generally the results are errors, but not expected ones.

PUT to existing binary (would probably expect a 405 and related message)

curl -ufedoraAdmin:fedoraAdmin -XPUT http://localhost:8080/rest/binary_with_sha1/fcr:fixity

# HTTP/1.1 409 Conflict

# NonRdfSource resources cannot contain other resources

PATCH or DELETE (would expect a 405)

curl -ufedoraAdmin:fedoraAdmin -XPATCH http://localhost:8080/rest/binary_with_sha1/fcr:fixity

# HTTP/1.1 404 Not Found
# Error: No OCFL mapping found for info:fedora/binary_with_sha1/fcr:fixity

HEAD (would expect a 405)

curl -ufedoraAdmin:fedoraAdmin -I http://localhost:8080/rest/binary_with_sha1/fcr:fixity -v

# HTTP/1.1 200 OK

Request to fcr:fixity of a resource that doesn't exist

curl -ufedoraAdmin:fedoraAdmin -XPUT http://localhost:8080/rest/doesnotexist/fcr:fixity
# HTTP/1.1 201 Created


curl -ufedoraAdmin:fedoraAdmin http://localhost:8080/rest/doesnotexist/fcr:fixity
# 404
# Error: No OCFL mapping found for info:fedora/doesnotexist

curl -ufedoraAdmin:fedoraAdmin http://localhost:8080/rest/doesnotexist
# 404
# Error: No OCFL mapping found for info:fedora/doesnotexist

# Try to create "doesnotexist" via POST, thinks the ID is taken
curl -ufedoraAdmin:fedoraAdmin -XPOST http://localhost:8080/rest/ -H"Slug: doesnotexist"
# http://localhost:8080/rest/3cedc11e-e8f8-4c77-91a7-ad50f230078c

PUT to fcr:fixity of an existing non-binary resource

curl -ufedoraAdmin:fedoraAdmin -XPUT http://localhost:8080/rest/helloworld

curl -ufedoraAdmin:fedoraAdmin http://localhost:8080/rest/helloworld/fcr:fixity -v
# HTTP/1.1 404 Not Found
# org.fcrepo.kernel.impl.models.ContainerImpl@69dd2e29 is not a binary
