FCREPO-3184 Import export utility validate BagIt Profile on import

Description

When importing a bag through the import export utility, a bagit profile can be specified though no validation is done to check that the bag conforms to the specified profile. If implemented this can serve to add an additional layer of verification of the data being imported.

Comments (6)

Michael Ritter, 2020-01-27 19:24 UTC

Andrew Woods, Danny Bernstein I had a question with respect to how the import functionality currently works for Bags and was looking to get some feedback:

  • When checking a BagIt bag against a bag profile, there's a question of if we should halt before the bag is imported. This makes sense to me as the bag profile allows for stronger guarantees about what you are receiving. I noticed that the import process does not halt for bags which have invalid entries in their manifest, so I'm trying to get an understanding of expected behavior.
  • There is a comment about using the bagit-java library to do bag validation once there's an updated release. In the pom it is pulling in 5.0.0-BETA, so this feels like it is in reference to having a release rather than a beta/snapshot. Just checking to see if my assumption is correct here.
  • The import process currently reads a SHA-1 manifest and uses those checksums in the headers when issuing a PUT for each binary. This allows partial uploads of BagIt bags to a repository, which I'm not sure is desired behavior. I'm not sure how many files would end up being touched if validation of the entire bag is also performed, but wanted to explore it.
    • Related to this - is there a desire to expanding beyond only using the SHA-1 manifest for BagIt bags? I imagine that would be a separate issue, but bags seem to offer more flexibility in that regard, especially if using a profile.
Andrew Woods, 2020-01-28 00:18 UTC

1. If a bag fails to validate, halting before any ingest makes sense.
2. A bagit-java release would be preferred, but using BETA is an option... since it is only used for validation... and if it appears that the outstanding issues on the BETA are reasonable.
3. I am not sure I completely understand your question. Is it related to your first question, and halting? In any case, supporting SHA-256 and MD5 would be great.

Michael Ritter, 2020-01-28 16:17 UTC

Andrew Woods 3 is related to the first question with respect to halting. I wasn't sure if the current behavior is intended when importing bags or if the utility should be updated to halt if a bag cannot verify its manifest.

Andrew Woods, 2020-01-28 17:10 UTC

+1 to halting... the tool certainly has room for improvement.
