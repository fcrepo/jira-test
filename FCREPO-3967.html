Ben Pennell, 2025-01-10 19:41 UTC

I think the jacoco setup already in fcrepo is close to what we would need, but I believe it is building for sonar. I'm not sure if they have an open source free tier for github integration.

In terms of other options, UNC currently uses CodeClimate which does code linting and presents coverage. There are also CodeCov and Coveralls, which both seem to have open source free tiers and github action integration.

I am most familiar with codeclimate. It adds over all test coverage to the PR and can be configured to fail a PR if test coverage is below a threshold. But it requires a browser plugin to display code coverage per file/line in the PR view. It can be a bit heavy handed with the linting, although it’s highly configurable.

It seems like Codecov directly integrates with the PR view without any additional steps, and shows coverage changes. It does not do any linting, which could be a plus or minus depending on how annoying you find your build failing because of code quality issues.

Coverall produces a report which gets linked to in a comment in the PR, but doesn't directly integrate with the github file view.

I believe someone that is the owner or admin to the fcrepo github repo would have to be the one to enable any of these tools. I don't have a strong opinion about which to use, although my impression is codecov would require less adjustment/setup than codeclimate.
