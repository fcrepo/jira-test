Description

This task is to improve the fixity service response by including the algorithm that was used while calculating the binary's checksum.

For example,

  1. Create a binary resource
    curl -XPUT -i --data-binary @some.pdf -H"Content-Type: application/pdf" localhost:8080/fcrepo/rest/book
  2. Run fixity (success)
    curl -i localhost:8080/fcrepo/rest/book/fcr:fixity
  3. Change the default digest algorithm
    curl -H"Content-Type: application/sparql-update" --data-binary @fixity.su -XPATCH -i localhost:8080/fcrepo/rest/book/fcr:metadata
    • Where "fixity.su" is:
      ===========
      PREFIX fedoraconfig: <http://fedora.info/definitions/v4/config#>

INSERT

{ <> fedoraconfig:defaultDigestAlgorithm "shaJunk" }

WHERE { }
===========

Result (failure):
---------------------------
<http://localhost:8080/fcrepo/rest/book#fixity/1478895023401> a premis:Fixity , premis:EventOutcomeDetail ;
premis:hasEventOutcome "BAD_CHECKSUM"^^<http://www.w3.org/2001/XMLSchema#string> ;
premis:hasMessageDigest <urn:sha1:44c4d081c1dc3530fdb1a2fe843e570170d3d054> ;
premis:hasSize "1324959"^^<http://www.w3.org/2001/XMLSchema#long> .
---------------------------

It would be helpful to know the reason for the BAD_CHECKSUM.

Additionally, it would be a bonus to include better data validation on the value provided in the on-ingest "digest" and the on-demand results.

Ralf Claussnitzer, 2017-02-10 12:57 UTC

PR: https://github.com/fcrepo4/fcrepo4/pull/1173 (wip)

The fake checksum algorithm is actually recognized, as you can see in the logs:
INFO 13:58:17.173 (FedoraFixity) Get fixity for 'book'
WARN 13:59:07.786 (FedoraBinaryImpl) No digest value was found to match the algorithm: shaJunk

If the algorithm cannot be recognized the calculation always falls back to SHA-1 (not really). This should, however, not lead to BAD_CHECKSUM result. The BAD_CHECKSUM result appears the problem of mixed up digest code. If the algorithm cannot be recognized, a BAD_CHECKSUM result is returned along with a default value of SHA-1 which in fact has never been applied.

Working on this issue revealed another problem with setting default digest algorithm:
First, it should not be allowed to configure an unrecognizable checksum algorithm.
Second, one can post multiple defaults. After some testing, my resource metadata looked like this:

{{$ curl -i http://localhost:8080/rest/book/fcr:metadata
HTTP/1.1 200
...
@prefix premis: <http://www.loc.gov/premis/rdf/v1#> .
...
@prefix config: <info:fedoraconfig/> .
...
<http://localhost:8080/rest/book>
rdf:type fedora:Binary ;
rdf:type fedora:Resource ;
fedora:lastModifiedBy "bypassAdmin" ;
config:defaultDigestAlgorithm "shaJunk" ;
config:defaultDigestAlgorithm "MD5" ;
config:defaultDigestAlgorithm "SHA-1" ;
premis:hasSize "2808177"^^<http://www.w3.org/2001/XMLSchema#long> ;
ebucore:hasMimeType "application/pdf" ;
fedora:createdBy "bypassAdmin" ;
...}}
