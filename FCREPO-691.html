Environment

MPTStore with Oracle or Postgres

Description

When using MPTStore as the Resource Index option, with a database (like Postgres or Oracle) that enforces a maximum length on column values, the triplestore can get into an inconsistent state because the asynchronous "flush" of the triples to update doesn't succeed due to a DB error. Currently, the only way of dealing with this is to track down the problematic object(s) in the repository, remove or correct them in the underlying storage, and do a resource index rebuild.

Ideally, Fedora would have an option to either reject or auto-truncate such too-long values and avoid this inconsistency problem altogether. This doesn't occur when using Mulgara as the underlying database because it doesn't have such length limits, however the option would be very helpful for people who have chosen another underlying triplestore.
