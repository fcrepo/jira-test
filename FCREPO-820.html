Description

Calling modifyObject AP-M method with no state change (ie sending "null" as the objectState) on an object with a FESLPOLICY datastream causes PolicyIndexInvocationHandler.java to incorrectly remove the policy from the cache. I dont believe this issue will exist for setting datastream states as well since the dsState can not be null in the setDatastreamState API-M method.

I have attached a patch that seems to fix the problem. The patch adds a check to make sure that managementMethod.parameters.objectState is not null or empty before touching the policy cache.

Mark Roy, 2010-11-13 09:04 UTC

A related issue that I just found was a similar behaviour when any datastream is purged from an object the policy is removed from the index and not added back.

Another issue that I see from examining the code is when adding any datastream, if the object has a policy it will be added to the index again regardless of whether or not it was already there. Not sure if the index can handle having two policies for the same object, but I think it is something that should be avoided so that the policies in the index dont become out of sync with the repository.

I will go through the logic of this class and attempt to find some rules that make sense. I think at least for the datastream modification rules it needs to check if the datastream being operated on is in fact the FESLPOLICY stream. Otherwise, it makes no sense to change the index.

Mark Roy, 2010-11-16 05:01 UTC

I've updated the rules in PolicyIndexInvocationHandler so that it now properly manages the cache. It now will only proceed with the datastream rules iff the datastream being operated on is the FESLPOLICY stream. Purging the policy stream also no longer necessarily deletes the policy from the cache; it checks after the delete is performed to see if there is still a policy and if so updates instead of deletes the policy.

The PolicyObject class also is modified so that if isPolicyActive() is called on an Object that does not have a FESLPOLICY stream, it returns false rather than throwing a null pointer exception. isDatastreamActive() was also modified to return FALSE if the FESLPOLICY stream does not exist instead of throwing a null pointer exception.

See the attached patches.
