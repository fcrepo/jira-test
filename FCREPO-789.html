Comments (2)

Chris Wilper, 2010-08-31 10:37 UTC

Looking at DefaultDOManager.java in trunk (post-3.4), the doRegistry table is updated without escaping DB-specific escape characters (apostrophes are handled, however). Updates to this table should be made using a PreparedStatement instead, so the JDBC driver can do the right thing. Note: the only other table that contains varchar or text data is doFields, and that was updated some time ago to use PreparedStatements for a similar reason.

Chris Wilper, 2010-09-01 15:48 UTC

Fixed in trunk. Fix was to omit the label, as it is never read from this table. The same was true for ownerId, so that was omitted from the table as well. The main change was to DefaultDOManager. See changeset at http://fedora-commons.svn.sourceforge.net/viewvc/fedora-commons?view=revision&revision=8781
