Stephen Bayliss, 2011-05-04 11:57 UTC

The underlying cause of this is the schema/output changes on the REST API for these two methods.

We have two places where the responses are serialised to XML (before then being transformed to HTML)

DefaultDisseminatorImpl uses org.fcrepo.server.access.defaultdisseminator.ObjectInfoAsXML()

Whereas the REST API uses org.fcrepo.server.rest.DefaultSerializer.objectProfileToXML()

Similarly for viewMethodIndex dissemination and the corresponding REST API method

The outputs of both of these are converted to HTML using the view stylesheets; however since the stylesheets have been modified in line with namespace changes etc in the REST XML output, the stylesheets no longer work against the system methods outputs as the XML generators for these have not been updated in line with the REST XML output.

We should only be generating this XML in one place, this would avoid this problem in future.

Suggest that org.fcrepo.server.access.defaultdisseminator.ObjectInfoAsXML() should be refactored to re-use the REST API XML serialiser.

Longer-term (or perhaps as part of resolving this) suggest that serialisers of Fedora entities should live in their own package; perhaps org.fcrepo.server.storage.types.serializers, or org.fcrepo.server.storage.serializers. And could be added to in the future eg to provide alternative serialisations such as json.

Stephen Bayliss, 2011-05-04 12:08 UTC

Should also be noted that the XML responses of these two methods are not schema-valid.

Stephen Bayliss, 2011-05-08 13:06 UTC

Refactoring to re-use the REST serializers for these two methods. There are other methods here that should probably be worked into a standard serialization package (see FCREPO-936 Closed ) - not sure if these other serializations are provided by the REST API, and as they are not causing problems I am leaving alone for the moment.
