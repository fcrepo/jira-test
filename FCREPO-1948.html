Aaron Elkiss, 2016-04-21 19:08 UTC

There are some issues with this test as designed - the default HTTP request sampler in JMeter keeps the entire request in memory at once; additionally individual arrays have limited size in Java so it can't even create an individual request with a 10GB random file attached. I was able to create up to about 500MB, and that still needed a heap size for JMeter of 8GB. If we want to run this plan as specified, it would need a custom sampler in JMeter that generates reasonable-sized chunks of large files rather than the entire thing at once.

Additionally, creating 1000s of multi-gigabyte files is going to require some serious storage capacity and take quite a lot of time; it might make sense to run the performance requests more frequently for this test than every 1000th request.
