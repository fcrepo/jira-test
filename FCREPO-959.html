NOTE: After this happens once, the rebuilder is subsequently able to start.

After modifying RebuildDOManager to not swallow the cause of the exception in this case, I got the following additional detail:

But Fedora was definitely stopped at this point. Derby may think another process is currently using the embedded db because it left a lockfile open or something. Perhaps the embedded Derby isn't being shut down properly in the Fedora webapp's context listener?

Chris Wilper, 2011-06-28 15:58 UTC

Fixed in master. This was indeed caused by a failure to properly shut down the embedded Derby database. The problem was introduced in March of this year, as part of the merge of FCREPO-504 Closed . As part of that commit, the reference to the embedded driver class was changed to the wrong value, which ultimately prevented the ConnectionPool.close() method from detecting that we were running the embedded db...so it didn't attempt to shut it down as it should have.
