Environment

Ubuntu JeOS Hardy Heron, JDK 1.5, run via included Tomcat - Fedora 3.1

Description

SPARQL ASK queries return False, regardless to actual match and the response format is not compliant to the SPARQL guidelines for ASK responses.

Spec:
http://www.w3.org/TR/rdf-sparql-query/#ask

From a basic query, the following is found (manually) to exist in the triplestore:

<info:fedora/dataset:1> <http://purl.org/dc/elements/1.1/identifier> "dataset:1" .

Performing a SPARQL query:

ASK

{ <info:fedora/dataset:1> dc:identifier "dataset:1" }

via: http://databank.ouls.ox.ac.uk:8080/fedora/risearch?lang=sparql&format=sparql&type=tuples&query=ASK%20

{%20%3Cinfo:fedora/dataset:1%3E%20dc:identifier%20%22dataset:1%22%20}

Response:
<?xml version="1.0" encoding="UTF-8"?>
<sparql xmlns="http://www.w3.org/2001/sw/DataAccess/rf1/result">
<head>
<variable name="k0"/>
</head>
<results>
<result>
<k0 datatype="http://www.w3.org/2001/XMLSchema#boolean">false</k0>
</result>
</results>
</sparql>

Expected response (from the SPARQL spec):
<?xml version="1.0"?>
<sparql xmlns="http://www.w3.org/2005/sparql-results#"
xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
xsi:schemaLocation="http://www.w3.org/2001/sw/DataAccess/rf1/result2.xsd">
<head>
</head>

<boolean>true</boolean>

</sparql>

Per yesterday's review of orphaned issues, I took a quick look at this:

SPARQL query:
ASK

{ <info:fedora/fedora-system:ServiceDefinition-3.0> <dc:identifier> "fedora-system:ServiceDefinition-3.0" }

Result:
<sparql xmlns="http://www.w3.org/2001/sw/DataAccess/rf1/result">
<head>
<variable name="k0"/>
</head>
<results>
<result>
<k0 datatype="http://www.w3.org/2001/XMLSchema#boolean">true</k0>
</result>
</results>
</sparql>

So, it's correctly returning true, but the response format is not SPARQL Query Results XML Format (http://www.w3.org/TR/rdf-sparql-XMLres/), see: FCREPO-1023 Closed

Going to close this issue, although I'm not sure what the correct fix version is. Looks like it was addressed 4 years ago in Mulgara: http://code.mulgara.org/issues/113
