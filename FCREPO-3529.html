Description

When a transaction is committed, a variety of DB tables are updated. Generally speaking, the way changes are made to the database is by accumulating changes in transaction tables, and then moving these changes from the transaction tables to the "real" tables when the transaction is committed.

Rollback logic exists, but all it does is drop records from the transaction tables. It is unable to rollback records that have already been moved out of the transaction tables. This means that it is possible for the DB to be left in an inconsistent state if there's an exception in the middle of committing transaction tables.

One solution to this problem is to ensure that all of the tables are updated within a single database transaction.
