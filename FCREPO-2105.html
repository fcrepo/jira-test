Description

I have been testing the performance of Fedora objects that link to many other repository objects (for example a collection with many members, or a book that contains many pages).

I've written up some of my findings in the Fedora wiki[1]. But the TL;DR version is that it's reasonably fast for small numbers of members, but gets progressively slower for larger numbers of members. And the move from LevelDB to a relational database for storing metadata looks like it's adding to this issue. So a book with 500+ pages or a collection that contains thousands of objects slows down to 30+ seconds to read the RDF from Fedora.

I mostly wanted to let people know about this issue so it can be a factor in discussions about modeling, performance, etc.

-Esmé

To verify the performance increases: (make sure you're running on a quadcore).

1. run fcrepo-webapp with the jdbc-postgres repository.json modeshape config.
2. git clone https://github.com/dbernstein/fcrepo-performance-test-scripts.git
3. execute ./n-members.sh 10000;
4. Note the elapsed times.
5. execute ./n-memberof.sh 10000;
6. Note the elapsed times.

7. Clear the fcrepo-data directory and your postgresql fcrepo database.
8. copy fcrepo4/fcrepo-config/src/main/resources/config/jdbc-postgresql/respository.json to /any/path/repository.json.
9. open the file and changed the cacheSize value to 500000.
10. run fcrepo-webapp with the -Dfcrepo.modeshape.configuration=/any/path/repository.json and add -Dfcrepo.enable-parallel-streaming-by-default=true.
11. Rerun 3 - 6.

You should see 5-10x speed increases.
