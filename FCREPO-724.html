Description

FCREPO-64 Closed means that SIZE attributes are now computed and stored for managed content datastreams. However pre-existing managed datastream versions won't have this attribute, so the size won't be correctly reported.

Therefore provide some kind of rebuild/migration tool to calculate SIZE for existing M datastream versions that don't have the SIZE attribute and save in the FOXML.

Comments (7)

Stephen Bayliss, 2010-08-10 16:47 UTC

Proposal:

For the REST api, getDatastream, include an additional parameter calculateSize [true|false] which forces a recalculation of the SIZE attribute (FOXML). For 3.4 restrict this to "M" datastreams; for future release consider expanding to other datastream control groups (as discussed on recent committer call, SIZE attribute needs considering for E and R datastreams; this method could be useful once we implement size for these - for instance to "pre-fetch" size of external content as a batch job).

For the SOAP api, a new method getDatastreamSize (or calculateDatastreamSize, fetchDatastreamSize??) (as we did for compareDatastreamChecksum).

Requirement:

There is currently nothing in ILowLevelStorage that will allow getting of the size of a managed content datastream (but the interface was updated to return the size when adding/modifying content as part of FCREPO-64 Closed ). Therefore a new method, or modification of existing method, would be required.

ILowlevelStorage.retrieveDatastream currently returns an InputStream - we could consider wrapping this in a class that also specifies the size. Need to consider downstream impact, particularly on those that have implemented their own storage. Maybe this could be considered as part of FCREPO-726 Closed - the plugin could return zero where implementors do not provide the ability to return a size (as would be the current situation); when implementors update their storage layer interface (as part of updating to use the new Java package names) they could implement getting of the size (or return zero if the storage layer does not permit).

Just wanted to mention that I started to put together a utility that can be used for this purpose. It can be used with old versions of Fedora 3.x through 3.6 (legacy and akubra-fs support), but currently does not have a pre-written filter to just compute new size values for managed datastreams. It can do a fixity re-computation, though, and a size-only "filter" could be written.
