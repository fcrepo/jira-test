FCREPO-245 Enable GSearch to start/stop properly

Description

Allow GSearch to start and stop properly when running in the same Tomcat server as Fedora. This involves making Server.properties available as there is currently an unmet runtime dependency there, as well as setting up a mechanism to handle GSearch starting prior to Fedora but still being able to connect to the message broker which is started by Fedora in the default configuration.

Comments (1)

Bill Branan, 2008-10-10 18:13 UTC

This issue has been resolved by;

  • Adding the server.properties file to fedora-client.jar and fedora-messaging.jar so that property values can be resolved correctly
  • Adding an option in the messaging client to start the connection to the messaging provider asynchronously, and updating GSearch to use this option. When starting the UpdateListener in GSearch, if a connection cannot be made a wait and retry will occur in a separate thread. This will allow Fedora to start up and make the messaging provider available.
