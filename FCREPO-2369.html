FCREPO-2369 Import-export verification tool's rdf comparison fails on unicode-escaped characters

Description

The import-export verification tool, when encountering unicode-escaped characters in an RDF document serialized to disk, fails to translate the characters in a way that allows it to recognize the same triples coming from Fedora.

It seems like the tool ought to be able to make the necessary transformation to recognize that the two resources are equivalent.

The problem is in the these lines: https://github.com/fcrepo4-labs/fcrepo-import-export-verify/blob/master/verify.py#L225-L226

If you parse the data directly with rdflib, the graphs are correctly interpreted as equivalent, but if you pass the response data to the parser with 'data=response.text', the graphs are interpreted as different. This must have to do with how unicode escapes are encoded/decoded during the handling of this data.
