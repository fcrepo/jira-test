Description

This bug can be seen in the following scenario:

  • After creating, deleting and purging an atomic resource, the path to the purged OCFL object remains, which is invalid.
    ```
    curl -i -XPUT -H"Content-Type: text/turtle" -d "<> <http://example.org#title> 'a title'" localhost:8080/rest/container
    curl -i localhost:8080/rest/container
    find /tmp/fcrepo.ocfl.storage.root.dir -name container
    curl -i -XDELETE localhost:8080/rest/container
    curl -i localhost:8080/rest/container/fcr:tombstone
    curl -i -XDELETE localhost:8080/rest/container/fcr:tombstone
    // Inspect path returned in the "find" command above... notice dangling directory
    ```
    See: https://github.com/fcrepo4/fcrepo4/pull/1687#issuecomment-637912832

This issue is also being tracked with: https://github.com/UW-Madison-Library/ocfl-java/issues/8
