FCREPO-3819 Update PUT requests to binary description metadata to store RDF subject as binary URI

Description

Currently when PUTting new RDF to a NonRdfSourceDescription the subject is stored on the OCFL on disk as the full NonRdfSourceDescription URI. This seems incorrect, so we want to alter RDF coming in to ensure that the subject is actually the binary URI.

ie.

<http://localhost:8080/fcrepo/rest/binary> NOT <http://localhost:8080/fcrepo/rest/binary/fcr:metadata>

This work would be in the https://github.com/fcrepo/fcrepo/blob/main/fcrepo-http-api/src/main/java/org/fcrepo/http/api/services/HttpRdfService.java

It was mentioned that the reasoning for this change was absent from this ticket. So I will add my interpretation for context.

Currently Fedora 6 is storing triples for binary resources using the binary description’s ID.

i.e. BINARY_RESOURCE/fcr:metadata instead of just BINARY_RESOURCE

The migration code made the opposite assumption, which led to users having difficulty removing triples (mostly because when displayed the BINARY_RESOURCE/fcr:metadata subject was changed to BINARY_RESOURCE). This led to a discussion about the reasoning for storing the triples one way but displaying them the alternate way.

It made more sense that the triples were stored in OCFL as Fedora was displaying them for long-term stability.
