FCREPO-1843 Allow inline transfer of binary resources

Is duplicated byFCREPO-3791 Allow GET of binary resources without "content-disposition: attachment" header

Description

When responding to a request for a Non-RDF Resource, Fedora always adds a "content-disposition: attachment" header, with filename and other details. This forces the browser to display a download dialog, making it impossible to serve/display/stream binary content directly from the repository.

Comments (4)

Michael B. Klein, 2015-11-17 20:02 UTC

Requesting a particular content disposition will have to happen through the URL itself, as opposed to a request header, since it will have to be usable within a rel, src, or href.

Possible resolutions:

  1. Change the default behavior to content-disposition: inline and add an fcr:attachment URL extension (similar to fcr:metadata) to force the download
  2. Keep the existing default behavior, and add an fcr:content URL extension to allow inline retrieval
  3. Similar to the above, but use a query string parameter (e.g., inline=true) to alter the response
Unknown, 2015-12-02 20:25 UTC

Couldn't this be solved with a reverse proxy that strips that header from the response? Isn't this only a concern if you are exposing fedora directly to the internet (without any sort of reverse proxy)?
