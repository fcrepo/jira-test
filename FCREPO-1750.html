Description

Currently when I request an RDF type I get a header like this:

Content-Type: text/turtle

It would be more complete if Fedora also included the encoding:

Content-Type: text/turtle; charset=utf-8

Comments (5)

Unknown, 2016-10-07 16:36 UTC

My reading of various W3C documents suggests that RDF should always be UTF-8; however, that conflicts with the HTTP/1.1 specification that states that any content type of "text/" is, by default (w/o a charset parameter), ISO-8859-1. The suggested resolution is that, for all RDF serializations that begin with "text/", there should be a charset=utf-8 parameter in the Content-Type header. For serializations that begin with "application/", the utf-8 charset is implied (e.g. application/ld+json or application/n-triples).

I would suggest that for any Fedora response that begins with "text/", there should also be a charset=utf-8 parameter. This would apply to:

text/turtle
text/plain (n-triples)
text/n3
text/rdf+n3
text/html

Here are the relevant documents:
https://www.w3.org/2008/01/rdf-media-types
https://www.w3.org/TR/turtle/#sec-mime
https://www.w3.org/International/articles/http-charset/index
https://www.w3.org/TeamSubmission/n3/#encoding
