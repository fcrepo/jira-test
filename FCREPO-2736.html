Headers from a RDFSource

Link: <http://www.w3.org/ns/ldp#Resource>;rel="type"
Link: <http://www.w3.org/ns/ldp#Container>;rel="type"
Link: <http://www.w3.org/ns/ldp#BasicContainer>;rel="type"

 

But headers for NonRDFSource

Link: <http://www.w3.org/ns/ldp#Resource>;rel="type"
Link: <http://www.w3.org/ns/ldp#NonRDFSource>;rel="type"

and for a fcr:metadata endpoint

Link: <http://www.w3.org/ns/ldp#Resource>;rel="type"
Link: <http://www.w3.org/ns/ldp#RDFSource>;rel="type"
Jared Whiklo, 2018-04-23 13:37 UTC

This behaviour has been in-place since 2014.

https://github.com/fcrepo4/fcrepo4/commit/9b6bd6f5bbcfb045a4f7fd9a7e0536efb3bb6126#diff-d372035f89c8d0846920e20bd13e0145R436

In looking at the example requests in the W3C LDP spec I noticed that while the initial responses use

Link: <http://www.w3.org/ns/ldp#RDFSource>; rel="type",
<http://www.w3.org/ns/ldp#Resource>; rel="type"

once they start to implement a DirectContainer the response headers change to

Link: <http://www.w3.org/ns/ldp#DirectContainer>; rel="type",
<http://www.w3.org/ns/ldp#Resource>; rel="type"

Replacing the RDFSource with the explicit container definition. I am guessing this is why cb did it this way originally.
