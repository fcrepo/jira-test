Osman Din, 2015-09-17 13:33 UTC

This is happening because of conflicting Guava lookups.

Guava first removed their Closeables.closeQueity() method in v 17.0:

https://github.com/google/guava/commit/b05363dc42ed0be66f83a2dda182265c062bc754#diff-3ba08d6a53c177c0f784f39387fe4c76

Please see the release notes:

https://code.google.com/p/guava-libraries/wiki/Release17

And then they re-added it, but with a different signature:

https://github.com/google/guava/commit/f6f3aab8605bd368ef37ce82298d8896a358f669

And even before this change of mind, they were trying to deprecate it in v 15.0.

Anyway, FileChannel is a Closeable but it's not an InputStream or a Reader (although the latter are indeed Closeable):

http://docs.oracle.com/javase/7/docs/api/java/nio/channels/FileChannel.html

But this is relied upon by level db 0.5, like so:

https://github.com/dain/leveldb/blob/0.5/leveldb/src/main/java/org/iq80/leveldb/impl/MMapLogWriter.java#L83

The particular line tries to close a FileChannel, but a newer Guava version (version 18.0 loaded by fcrepo) expects an InputStream or a Reader.

My guess is that on some operating systems an older version of guava is available at classpath but this fails to happen on Windows Server. But this is a guess –
I haven't seen it happening in action and I'm not sure if it's worth verifying this.

However, it must be noted:

This bug is occurring as a side effect of fcrepo use of older ModeShape and Infinispan versions.

The end result of using an older version of Infinispan, whether via ModeShape or directly,
is that LevelDB connector jar version 0.5, not 0.7, is brought in.

Therefore:

If upgrading to latest ModeShape is on the roadmap anyway, and the stale logic of a class (see below) in fcrepo-kerne-modeshape is scheduled for an update, then this bug should get resolved automatically.

The reason for this suggestion is the following commit:

https://github.com/infinispan/infinispan/commit/7e2695f1317995e2efa3cffec4881d807aa1d246#diff-04dc5d029560773ac79faaf3da0fbb22R136

Why is that significant? In the 0.7 version of the LevelDB jar, they created their own class org.iq80.leveldb.util.Closeables and removed the dependency on com.google.common.io.Closeables, altogether.

https://github.com/dain/leveldb/commit/be7714e4356f575520d306d8710488563f660066#diff-f4544cb6331d092347a0ebe3cf598549L22

ModeShape 4.3.0 (and above) should take care of this issue. The following is the switch they made to newer Infinispan version:

https://github.com/ModeShape/modeshape/commit/19f518b00c799a4dd93d95189d9283e60e09f416#diff-087bd377ad142482401f1d144ba2a9ddL247

And, a change would be necessary to a utility class in fcrepo-kernel-modeshape,
as this particular class uses Infinispan 6.2 for a deprecated class org.infinispan.manager.CacheManager.

https://github.com/fcrepo4/fcrepo4/blob/master/fcrepo-kernel-modeshape/src/main/java/org/fcrepo/kernel/modeshape/services/functions/GetClusterConfiguration.java

Please let me know about your preference.
