In implementing axis error detail for authz (so that fedora-admin can say "Not
Authorized" instead of "Axis Fault"), the existing code didn't/doesn't seem to
handle this correctly. I didn't change that code. One of us should someday
look at it.

Basically, it's that serverside error detail is input as "<detail>line
one</detail><detail>line two</detail>". It looks like this is never parsed by
axis, and is just sent along as the text of a single Element built by axis.
This isn't grokked at the client. I added code to actually build an Authz
element, for that case, which can then be grokked clientside.
