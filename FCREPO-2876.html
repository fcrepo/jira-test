Description

1. Create a binary: <resource>

2. `curl -I -u fedoraAdmin:fedoraAdmin <resource> -H "Want-Digest: sha-256"`

3. verify that the Digest response header looks like this

`Digest: sha256=<checksum>`

instead of like this

`Digest: sha-256=<checksum>`

Danny Bernstein I'm not quite sure what the expected outcome for this ticket is. Do we want `Want-Digest: sha-256` to produce `Digest: sha256=blahblahlblah`?

"sha-256" appears to be the algorithm name expected by internal java libraries, so we would have to do some translation on the way out. I don't see any reason we can't retain the - in the urn specification, and my instinct would be to keep the keys matching on the input and output, but I don't feel strongly if there is reason to change it.

As a bonus, there is an existing test that explicitly expects `sha256` to fail when requesting digests:

https://github.com/fcrepo4/fcrepo4/blob/master/fcrepo-kernel-modeshape/src/test/java/org/fcrepo/integration/kernel/modeshape/FedoraBinaryImplIT.java#L389
