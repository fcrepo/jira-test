Description

On this page: https://wiki.duraspace.org/display/FEDORA43/RESTful+HTTP+API

It has a sample response that shows:

<http://localhost:8080/rest/path/to/some/resource#fixity/1400589459772> <http://fedora.info/definitions/v4/repository#status> "BAD_CHECKSUM"^<http://www.w3.org/2001/XMLSchema#string> , "BAD_SIZE"^<http://www.w3.org/2001/XMLSchema#string> ;

But this status predicate doesn't exist in http://fedora.info/definitions/v4/repository

Unknown, 2015-09-24 19:37 UTC

The fedora:status predicate was moved to the objState vocabulary as part of FCREPO-1363 Closed , which AFAIK remains unpublished.

A. Soroka should the fixity response use this external vocab for status values, or should the status predicate be restored to the main ontology? Or, better yet, is there another vocabulary better suited for describing these sorts of values?

Unknown, 2015-09-24 19:50 UTC

Seems to me that premis:hasEventOutcome would be a good fit for this: http://id.loc.gov/ontologies/premis.html#hasEventOutcome

A. Soroka, 2015-09-24 19:58 UTC

Wasn't there some kind of problem with using premis this way? Like it made it impossible for other people to us that predicate for their own purposes or something like that?

Unknown, 2015-09-24 20:10 UTC

A. Soroka good point. The current code adds this predicate to the set of immutable properties that cannot be changed. See: http://git.io/vnQSA and http://git.io/vnQSm

We could simply not add that particular predicate to that set. Given that the predicate is only ever used inside a dynamically generated fedora:Fixity hashURI, making the predicate mutable shouldn't present a problem.
