Description

When attempting to export a single tree containing about 86 high level resources from the membership/containment hierarchy of my local fcrepo5 instance, the exported ended up exporting many additional resources from outside the hierarchy (it may have been trying to export the whole repository, but I ended it after about 15000 resources had been exported). Our repository uses pcdm:memberOf relationships for defining membership, while ldp:contains is used for containment of fedora resources that make up a large object.

The full command I used was:

java -jar /tmp/fcrepo-import-export-0.4.0-SNAPSHOT.jar --mode export --resource http://localhost:8181/fcrepo/rest/content/ba/a3/01/51/baa30151-f1b7-446b-9266-d0618eaa9f76 --user user:password --dir /opt/data/export_test -i --binaries -x --predicate http://pcdm.org/models#memberOf,http://www.w3.org/ns/ldp#contains

Comments (1)

Ben Pennell, 2020-08-03 18:42 UTC

Apparently the issue was that I shouldn't have included "http://pcdm.org/models#memberOf" in the predicates option. In the current implementation if you provide the --inbound option it will automatically follow all inbound references as if they were membership relationships, regardless of the "predicate" param. So our pcdm:memberOf inbound relations were being followed due to that. Including it in the predicate section simply meant that it would follow outbound instances of the predicate as well.

 

This could end up being an issue for some repositories which define multiple inbound relationships if users want to only export part of their repository, as it could end up crawling out of the intended hierarchy. For instance, in Hyrax, membership in AdminSets is defined by a dc:isPartOf reference from a Work to the AdminSet. But there are also user defined collections which can span multiple AdminSets, and have pcdm:memberOf relations from Work to Collection. If attempting to export everything in an admin unit, you'd the Collections as well.

 

But there probably isn't any further work for this ticket. The README does describe the --inbound option, and while I did read it, I apparently misinterpreted it.
