Description

In Fedora 4.5.0 and before, when a new namespace was observed in RDF with namespace prefixes (e.g., turtle), the user-supplied namespace prefix was registered and used in subsequent uses of that namespace. If the user did not supply a prefix, or was using an RDF serialization without prefixes (e.g., ntriples), then Fedora generated a prefix like ns001.

Since Fedora 4.5.1, Fedora ignores any user-supplied prefix and always generates a prefix like ns001.

See discussion in https://jira.duraspace.org/browse/FCREPO-2252

Bethany Seeger, 2017-05-18 13:52 UTC

Thinking about design here - in terms of prefix definitions, would the cnd file take precedence, in case there's an overlap of prefixes with different definitions (ie, ones from the existing model in the system vs ones in the file)?  Seems like what's in the system should take precedence over the file.  Really, just thinking about how to do this in a clear way so users aren't then confused in a different way.    

Esmé Cowles, 2017-05-18 13:57 UTC

Bethany Seeger, yes, I think the CND file would take precedence.  Though given the issues that have surfaced in the 4.7.0/4.7.2 upgrades, I think that defining custom namespaces in the CND file might not be a good idea.  If users can post RDF with their own namespaces, then they would not need to update the CND file in order to have control over their namespaces.
