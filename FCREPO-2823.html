Description

Quoting section 5.7.2

In addition to requirements in 5.7.1 LDP-RS, when a client is allowed to perform acl:Append but not acl:Write operations on an LDPC, a POST request MUST be allowed. 

So if you can acl:Append a LDP-C you can't PUT or PATCH or DELETE, but you can POST to add a new resource inside it.

This has already been implemented--. Verification steps:

curl -u fedoraAdmin:fedoraAdmin -i -X POST http://localhost:8080/rest/
# returns new resource's URI: http://localhost:8080/rest/ff4f80f3-70f3-4292-9a1e-ef03c4d0df15

# HEAD to follow the Link rel="acl" location
curl -u fedoraAdmin:fedoraAdmin -I http://localhost:8080/rest/ff4f80f3-70f3-4292-9a1e-ef03c4d0df15

# create the ACL to the testuser can only append to the container
curl -u fedoraAdmin:fedoraAdmin -X PUT http://localhost:8080/rest/ff4f80f3-70f3-4292-9a1e-ef03c4d0df15/fcr:acl -H 'Content-Type: text/turtle' --data-binary @- <<END
@prefix acl: <http://www.w3.org/ns/auth/acl#>.
<#auth> a acl:Authorization;
acl:agent "testuser";
acl:accessTo </rest/ff4f80f3-70f3-4292-9a1e-ef03c4d0df15>;
acl:mode acl:Append .
END

curl -u testuser:testpass http://localhost:8080/rest/ff4f80f3-70f3-4292-9a1e-ef03c4d0df15
# --> 403 (cannot read the container)

curl -u testuser:testpass http://localhost:8080/rest/ff4f80f3-70f3-4292-9a1e-ef03c4d0df15 -X POST
# --> 201 (can create a child resource)

curl -u testuser:testpass http://localhost:8080/rest/ff4f80f3-70f3-4292-9a1e-ef03c4d0df15/a477dd32-da66-42e1-83f8-8f227f889897 -X POST
# --> 201 (can create a child resource of a child resource)
