FCREPO-3092 Support caching headers in transactions

Description

At present, neither etag or the fedora state token are returned when making requests within a transaction. So a client is unable to tell that the state of resource which is being used for read only purposes in a transaction is unchanged, and therefore cached versions may be used. Accessing the same state of a resource in and outside of a transaction gives different cache headers.

Additionally, no last modified header is returned in a transaction, which makes optimistic locking when inside of a transaction impossible. So it would be helpful to provide up to date last-modified headers.

So from the perspective of a client, it would be helpful to return these headers when making requests within a transaction.
