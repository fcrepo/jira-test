FCREPO-3460 Migration utils: Optionally log error and skip objects that cannot be migrated

Description

Currently, migration-utilities halts when it encounters an error migrating an object from Fedora 3 to OCFL.  Over the course of a large, long migration, this means that the migration process must be monitored and restarted several times, interventions that increase the amount of time and effort needed to migrate a repository.
Proposal:  Add two flags to migration-utils:
  --no-halt:  do not halt on error migrating individual objects (default: false)
  --max-errors:  only halt after X number of sequential object migration errors (default: no limit)
The max-errors flag would only be applicable when no-halt is specified.  The max-errors default would be no limit, i.e., every migration of object would be attempted, regardless of the number of errors that occur in a row.
No-halt behavior: if an object-specific migration error is encountered, an ERROR is logged, and the PID of the object is written to a file "pid/errors.txt" (alongside "pid/resume.txt").  The migration utility then attempts to migrate the next object in the list.
Once max-errors is reached (if set), the migration utility logs the ERROR "Maximum number of sequential errors reached: X", and then exits.
