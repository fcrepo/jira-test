FCREPO-2607 Incorrect ldp:contains reference on versioned resources

TypeBug
StatusOpen
PriorityMajor
ReporterBen Pennell
Created2017-09-14 12:42 UTC
Updated2021-09-17 17:42 UTC
Affects versionsFedora 4.7.4

Description

Bethany Seeger encountered an issue which results in the GET response for a versioned resource having an invalid ldp:contains statement.

If you have resource /a/ which contains resource /a/b/, then create a version of /a/b/, then PATCH /a/b/ to add a property to it, and then create a version of /a/, when you view the version of /a/ it ldp:contains something like /a/b/fcr:versions/vb instead of the expected /a/fcr:versions/va/b/.

The issue can be replicated in 4.7.4 with the following curl commands:





curl -XPOST http://localhost:8080/rest/ -H "Slug: a"

curl -XPOST http://localhost:8080/rest/a -H "Slug: b"

curl -XPOST http://localhost:8080/rest/a/b/fcr:versions -H "Slug: vb"

curl -XPATCH http://localhost:8080/rest/a/b -d "delete {} insert 

{ <> <http://purl.org/dc/elements/1.1/title> 'b title' }

 where {} " -H "Content-Type: application/sparql-update"

curl -XPOST http://localhost:8080/rest/a/fcr:versions -H "Slug: va"

curl http://localhost:8080/rest/a/fcr:versions/va


    
	
  1. incorrectly includes "ldp:contains <http://localhost:8080/rest/a/b/fcr:versions/vb>"
    2. 
	
  2. Should have included "ldp:contains <http://localhost:8080/rest/a/fcr:versions/va/b>"
    3. 
	
  3. Retrieve the resource referenced in va
    
curl http://localhost:8080/rest/a/b/fcr:versions/vb
    4. 
	
  4. when the snapshot of /a/ was created, /b/ had a dc:title, but the resource included in the snapshot does not have a dc:title because it is referencing the wrong version
{/code}
    5. 





The incorrect ldp:contains issue actually occurs without the PATCH request, but including makes it clearer that va is referencing the wrong state of b.  This could effectively result inconsistent results or data loss when exporting versioned resources.
