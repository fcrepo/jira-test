Description

After creating a binary resource in Fedora 6 through the web interface, I can use SPARQL-Update to add and delete a second ebucore:hasMimeType property to it, but I cannot modify or remove the initial default application/octet-stream value.

Ben Pennell confirmed this problem, noting that it is not occurring in Fedora 5 but is occurring in Fedora 6. He said: "My recollection is that ebucore:hasMimeType is generated from the header file for the binary, and the value from the header file is used for the HEAD/GET responses for the binary. But updating the RDF description for the binary has no impact on the binary's content type header."
