Description

Based on the GET URIs exposed in the REST API, support use of these URIs as resource identifiers in the resource index. See http://fedora-commons.org/confluence/display/DEV/Supporting+the+Semantic+Web+and+Linked+Data

This could involve

  • rewriting of query output to convert info:fedora/ URIs to HTTP resource URIs
  • rewriting of query input to convert HTTP URIs to info:fedora URIs

The info:fedora URI form should be retained for portability etc

Comments (3)

Stephen Bayliss, 2010-07-14 16:02 UTC

Potentially make the "translation" between info:fedora/ URIs and http URIs configurable - for the situation where Fedora is "invisible" on the web, but Fedora resources are exposed through a user interface - eg allow translation of info:fedora/test:pid to http://server/library/viewResource?id=test:pid. Default config should be based on REST API, but having it configurable might be useful for some users when for instance exposing resource maps that should contain resolvable URIs.

Stephen Bayliss, 2010-11-17 20:19 UTC

As part of this we should take into account that the info URI registry is now closed, and they recommend long term moving away from them to more "web friendly" identifier schemes. http://info-uri.info/
