Esmé Cowles, 2016-02-18 15:18 UTC

https://github.com/fcrepo4/fcrepo4/pull/986

The generic JDBC config can be used with both MySQL and PostgreSQL. But there are two complications:

1. Having to manually download the JDBC driver and database pooling JARs, and add them to the classpath
2. The MySQL- and PostgreSQL-specific configs use non-standard types (LONGBLOB and BYTEA instead of the standard TEXT). Using the standard TEXT type works, but I'd like to repeat some of my tests to see if there are any performance implications.

Andrew Woods, 2016-02-22 20:56 UTC

Esmé Cowles, 2016-02-22 21:30 UTC

The PR as it stands makes a packaged installation that supports both MySQL and Postgres. I was hoping that we could have a single generic JDBC config, rather than separate ones for each database. So the issues I listed were if we could use that generic config.

I did some testing with PostgreSQL and it isn't able to use the TEXT column type, so it will need its own config. And the convenience of bundling the JDBC drivers in the WAR file is nice too. So maybe it makes sense to include MySQL and Postgres drivers and config? Or maybe they could be moved to webapp-plus?

Andrew Woods, 2016-02-23 01:23 UTC

Can you describe the setup you did for your postgres? I would like to test this.

Esmé Cowles, 2016-02-23 01:48 UTC

My Postgres setup is pretty much the same as the MySQL setup. I built and deployed the WAR file to Tomcat with these system properties set:

  JAVA_OPTS="${JAVA_OPTS} -Dfcrepo.modeshape.configuration=classpath:/config/jdbc-postgresql/repository.json"
  JAVA_OPTS="${JAVA_OPTS} -Dfcrepo.ispn.postgresql.username=$USER"
  JAVA_OPTS="${JAVA_OPTS} -Dfcrepo.ispn.postgresql.password=$PASS"

The one change was that Postgres doesn't allow automatically creating the database, so I had to create it manually with:

createdb -O $USER ispn
