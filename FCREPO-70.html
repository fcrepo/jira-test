Description

Aaron reported this. When running a SQL rebuild, the NSDL team noticed that the lowlevel storage file registry writes the paths differently than Fedora normally does: it uses the "canonical" path (this is the path with any symlinks resolved).

The desired behavior is to save the path in the way it is configured in fedora.fcfg. That way, the symlink target is respected later, if it changes.

To recreate this problem:

  • install an empty fedora repository.
  • configure the objectPaths directory in fedora.fcfg to point to a symlink instead of a physical directory.
  • create an empty object
  • note the associated path value in the objectPaths table (it will include the symlink as part of the path name)
  • shut down fedora and do a sql rebuild
  • note the new path value in the objectPaths table (it will NOT include the symlink...instead it will contain the canonical path, which is not the desired behavior)
