Bill Branan, 2008-02-20 23:12 UTC

[Comment from Sourceforge Task]
Comment Submitter: bbranan
Note that with the removal of describeUser/adminPing the Fedora Administrative Client no longer checks the authorization of the user on login. If a user authenticates, they are able to enter the client. Each call issued via the client interface is checked for authorization based on the repository XACML policies before being performed. If the logged-in user is allowed to perform the operation it proceeds as normal, otherwise the user will see an Authorization Denied error. The only change being made here is that the user can no longer be denied access to the Admin Client by setting the policy for adminPing(). This does not affect the ability to allow/deny access to operations performed by the Admin Client.
