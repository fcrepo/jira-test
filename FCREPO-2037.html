Description

See: https://github.com/fcrepo4-exts/fcrepo-java-client/issues/11

Currently the client doesn't provide a way to add the following allowed headers:

Content-Disposition
Content-Type
digest
slug
if-match
if-none-match
if-unmodified-since
if-modified-since
Range

I would like to add support for all of the headers expected for basic object creation or retrieval.

In terms of implementation, the approach so far has been additional parameters to the post/put/get/patch methods, which may get unwieldy with the full set of options. I would favor a method override of the form:

public FcrepoResponse post(final URI url, final InputStream body, final Map headers)

Possibly with restrictions in each method so that it can only set allowed headers, but that may be iffy since some methods cover multiple endpoints with different headers allowed.

I'm not all that informed about camel, but I believe this would work there too?

Former user, 2016-05-25 21:19 UTC

My choices seem to be generics extending generics with a self helper to avoid type safety warnings or duplicating every parent method (via inheritance or delegation). Not much of a choice...

Generics:

public abstract class BodyRequestBuilder<T extends BodyRequestBuilder<T>> implements RequestBuilder {
    protected abstract T self();

    public T body(InputStream stream, String contentType) {
        return self();
    }
}

public class PostBuilder<T extends PostBuilder<T>> extends BodyRequestBuilder<PostBuilder<T>> {
    @Override
    protected PostBuilder<T> self() {
        return this;
    }

    public PostBuilder<T> digest(String value) {
        return self();
    }
}

Duplication:

public abstract class BodyRequestBuilder implements RequestBuilder {
    public BodyRequestBuilder body(InputStream stream, String contentType) {
        return this;
    }
}

public class PostBuilder extends BodyRequestBuilder {
    @Override
    public PostBuilder body(InputStream stream, String contentType) {
        super.body(stream, contentType);
        return this;
    }

    public PostBuilder digest(String value) {
        return this;
    }
}

(The delegation approach requires pretty much the same duplication).

Both would work, I guess the generic approach is more extensible since there is less boilerplate to re-add, but it is a bit hard to read. I'm not finding other options aside from simply avoiding inheritance.
