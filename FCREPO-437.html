Description

Trying to ingest an object into Fedora fails if the document contains a reference to an external resource and the Fedora server is only allowed to access that resource via a HTTP proxy.

My first idea to solve this was to set the environment variable CATALINA_OPTS to something like

CATALINA_OPTS="-Dhttp.proxyHost=proxy.fiz-karlsruhe.de -Dhttp.proxyPort=8888"

and restart Tomcat.

Unfortunately this isn't sufficient because the HTTPClient module which Fedora uses doesn't read that properties automatically.

So the next step was to set the proxy parameters into the HTTPClient in WebClient.java just after a new instance of the HTTPClient was created (see attached file).

That's all. Maybe someone else has the same problem.

The proxy can be configured via the CATALINA_OPTS environment variable for tomcat.

Configuration with only proxy host and port:
export CATALINA_OPTS="-Dhttp.proxyHost=proxy.host.tld -Dhttp.proxyPort=8888"

With username and password (both have to be non-empty if used):
export CATALINA_OPTS="-Dhttp.proxyHost=proxy.host.tld -Dhttp.proxyPort=8888" -Dhttp.proxyUser=user -Dhttp.proxyPassword=password

Most cases will probably also need a NonProxyHosts list, that is a list with hosts that are not proxied:
export CATALINA_OPTS="-Dhttp.proxyHost=proxy.host.tld -Dhttp.proxyPort=8888" -Dhttp.proxyUser=user -Dhttp.proxyPassword=password -Dhttp.nonProxyHosts=localhost|*.otherhost.tld
