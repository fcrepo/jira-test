Description

Patching an ACL fails. I have a test object ACL that was.

@prefix webac: <http://fedora.info/definitions/v4/webac#> .
@prefix acl: <http://www.w3.org/ns/auth/acl#> .
@prefix rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
@prefix fedora: <http://fedora.info/definitions/v4/repository#> .
@prefix ldp: <http://www.w3.org/ns/ldp#> .

<http://localhost:8080/rest/box/fcr:acl#authorization>
  rdf:type acl:Authorization ;
  acl:agent "testuser" ;
  acl:mode acl:Read ;
  acl:mode acl:Write ;
  acl:accessTo <http://localhost:8080/rest/box> ;
  acl:default <http://localhost:8080/rest/box> .

<http://localhost:8080/rest/box/fcr:acl>
  fedora:created "2020-11-06T14:16:25.842650Z"^^<http://www.w3.org/2001/XMLSchema#dateTime> ;
  fedora:lastModified "2020-11-06T14:17:19.091992Z"^^<http://www.w3.org/2001/XMLSchema#dateTime> ;
  fedora:createdBy "fedoraAdmin" ;
  fedora:lastModifiedBy "fedoraAdmin" ;
  rdf:type webac:Acl ;
  rdf:type ldp:Resource ;
  rdf:type fedora:Resource ;
  rdf:type ldp:RDFSource ;
  rdf:type ldp:Container ;
  rdf:type fedora:Container .

 

When I execute this request.

curl -i -ufedoraAdmin:fedoraAdmin -H"Content-type: application/sparql-update" -d " DELETE { <http://localhost:8080/rest/box/fcr:acl#authorization> <http://www.w3.org/ns/auth/acl#default> <http://localhost:8080/rest/box> } WHERE { }" http://localhost:8080/rest/box/fcr:acl -XPATCH

I would expect the acl:default clause to be removed, but nothing changes even though I get the 204 response.

I think this is because the identifier translator which is operating in the FedoraLdp PATCH section is not in the FedoraAcl PATCH section.
