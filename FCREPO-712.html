Description

The following xsd:dateTimes should be equivalent:

String a = "1970-01-01T00:00:00.2Z";
String b = "1970-01-01T00:00:00.200Z";

according to http://www.w3.org/TR/xmlschema-2/#dateTime

However, Fedora treats these as different dates, namely that "a" is 198 milliseconds before "b". This is due to what sane people would call a bug in SimpleDateFormat, but some spec engineers beg to differ:

SimpleDateFormat formatter = new SimpleDateFormat();
formatter.setTimeZone(TimeZone.getTimeZone("UTC"));

formatter.applyPattern("yyyy-MM-dd'T'HH:mm:ss.S");
Date aDate = formatter.parse(a);
formatter.applyPattern("yyyy-MM-dd'T'HH:mm:ss.SSS");
Date bDate = formatter.parse(b);

System.out.println(aDate.equals(bDate));
System.out.println(aDate.getTime() + " vs. " + bDate.getTime());

which prints out:
false
2 vs. 200

This is the closest bug report I could find: http://bugs.sun.com/bugdatabase/view_bug.do?bug_id=4516915
Again, sane people would say that .2 is two-tenths, not two-thousandths, but I digress...

As the various DateUtility methods all rely on SimpleDateFormat for parsing and formatting dates, Fedora can record the wrong datetime and moreover, clients that do parse datetimes correctly can't pass them back to Fedora. For example, if Fedora serializes a dsCreateDate of "1970-01-01T00:00:00.200Z", and a client retrieves and (correctly) parses that as "1970-01-01T00:00:00.2Z" and uses that in a subsequent purgeDatastream request as the startDT and endDT, the purgeDatastream request will fail, as Fedora reads the date as "1970-01-01T00:00:00.002Z".

Of course, if you actually had another datastream version at "1970-01-01T00:00:00.002Z", you would have successfully purged the wrong version.

I'll note that I only caught this because the purgeDatastream tests for fedora-client were intermittently failing, as fedora-client does handle xsd:dateTimes correctly. See http://github.com/mediashelf/fedora-client/blob/master/src/main/java/com/yourmediashelf/fedora/util/DateUtility.java for what I believe is a correct implementation, but it's a complete re-write that doesn't use SimpleDateFormat.
