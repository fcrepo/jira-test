Description

Bug reported by Matt Zumwalt:

Fedora isn't proffering an authentication challenge when I hit the REST API methods. I had to point my browser at http://127.0.0.1:8080/fedora in order to authenticate my browser and then go back to http://127.0.0.1:8080/fedora/objects/demo:5/export

In the past, Fedora would challenge the browser whenever it attempted to perform a protected method without authenticating, and a failed authentication would return a 400 error. What changed that it's returning a blank page now?

Bill Branan, 2008-10-10 21:10 UTC

The REST API, prior to the work on this task, was not included in the servlet filtering chain which allows other Fedora interfaces to authenticate users. The changes for this task include adding a new servlet filter which handles determining which REST API requests map to API-A, for the case where API-A AuthN is off. Filter mappings are also added to select the correct filter for the RestServlet, depending on choices made at install time.
