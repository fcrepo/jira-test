Description

Single-request transactions should write directly to the target database table without using the corresponding transaction table. These direct writes must be aggregated under a spring @Transactional annotation at the kernel API level.

The transaction table is only necessary for batching a series of changes across multiple requests into a single database transaction. When a Fedora transaction does not span multiple requests, the intermediary tables are unnecessary and increase latency.

Based on an experimental branch (https://github.com/pwinckles/fcrepo4/tree/no-tx), changing this behavior should reduce request latency by 10-20ms.
