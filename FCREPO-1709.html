FCREPO-1709 Kill dependency on org.modeshape.jcr.security.AuthenticationProvider

TypeImprovement
StatusClosed
ResolutionFixed
PriorityMinor
ReporterA. Soroka
Created2015-08-25 20:02 UTC
Updated2018-04-10 19:08 UTC
Resolved2018-04-10 19:08 UTC
Componentsf4-auth, f4-core

Description

Currently the Fedora auth SPI depends directly on org.modeshape.jcr.security.AuthenticationProvider. This is a Modeshape type dependency which should be confined to the Modeshape kernel implementation. Instead, an appropriate Fedora-specific type should be substituted for org.modeshape.jcr.security.AuthenticationProvider.

Ralf Claussnitzer, 2017-02-08 22:40 UTC

Usage of `org.modeshape.jcr.security.AuthenticationProvider` can be found in the `fcrepo-auth-common module`. I assume this is the `f4-auth` JIRA-component? And additional interface type similar to this has to be defined in `fcrepo-kernel-api`, wrapping all of the used Modeshape types?

This is bigger than the description suggests. The `fcrepo-auth-common` module depends on `modeshape-jcr` and `modeshape-web-jcr` (plus `fcrepo-kernel-modeshape` for testing).

Not sure whether just wrapping all Modeshape types really accomplishes something. A naive approach would probably lead to a shallow copy of the Modeshape API itself.

Andrew Woods, 2017-02-09 14:16 UTC

Somewhat related to this conversation, there are currently three authorization modules:

  • webac - https://github.com/fcrepo4/fcrepo-module-auth-webac
  • rbacl - https://github.com/fcrepo4/fcrepo-module-auth-rbacl
  • xacml - https://github.com/fcrepo4/fcrepo-module-auth-xacml

Given that the fcrepo-specification only includes mention of webac, we should be planning on deprecating rbacl and xacml... and therefore consolidating/refactoring webac, auth-common, and parts of rbacl that webac depends upon.
