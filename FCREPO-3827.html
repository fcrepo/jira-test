Jared Whiklo, 2022-06-02 14:05 UTC

So the main issue with this NPE on rollback is the permissions on the transactions. Currently we allow any user to create a new transaction, but can any user commit/rollback any transaction they have an ID for? We don’t track whom started a transaction, so if we want to limit that we’d need to make some changes. Alternatively, we can just allow any user to commit/rollback any transaction that they have the UUID for.

Jared Whiklo, 2022-06-02 15:33 UTC

Discussion at the June 2, 2022 Tech Call resulted in a decision to open PUT/DELETE access to the transaction endpoints for fedoraUser to mimic the POST access.

This could conceivably result in a user guessing a transaction ID and commit/rolling back a transaction for the fun of it. There will be a follow-on ticket for this issue.
