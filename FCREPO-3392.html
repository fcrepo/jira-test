Description

The Fedora 5->6 migration path will require transforming the exported Fedora 5 repository into Fedora-aware OCFL.  In order to perform this transformation,  we need to be able to read a Fedora 5 export.  The plan is that fcrepo-upgrade-utils will perform this task of transforming Fedora 5 into Fedora 6 compliant OCFL.

To this end, it would be helpful to extract from fcrepo4 core a new fcrepo4 core module that encapsulates all the Fedora-specific logic for writing Fedora-compliant OCFL.  This thin layer of abstraction which represents what we have called in our community discussions "the Fedora sprinkles" will then be used by fcrepo-upgrade-utils in order to write OCFL using the same logic that Fedora 6 (and beyond) will use.  Whether this module will stay in the fcrepo core code-base or become its own independently versioned artifact is an open question.  This task is simply to refactor and extract the code into a module that can then be reference by external utilities such as fcrepo-upgrade-utils.  

In order to boost our capacity to work in parallel,  this ticket covers part one of this task which would be to extract an interface or set of interfaces into the new module that can then be used by the developer working on https://jira.lyrasis.org/browse/FCREPO-3393 .  So once this ticket is complete,  fcrepo-3393 can be started by another will part 2 is completed: https://jira.lyrasis.org/browse/FCREPO-3394

It is possible that breaking this task into two steps may not give us much, in which case,  parts 1 and 2 can be done at that same time.
