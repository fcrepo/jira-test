Description

Currently users do not have control over what resources they wish to migrated - it’s either all or nothing. This feature would provide them with the ability to exclude resources based on PID with wildcard

Comments (2)

Dan Field, 2023-01-24 17:04 UTC

We could perhaps add an additional CLI argument to sit alongside the current pidlist opt-in -p argument, This argument would need to be mutually exclusive to -p in order to make any sense though. I can not think of a use case for requirng both.

What I am less clear on, is how the wildcard functionality would work. Was there a specific use-case for this? Presumably it’s usefullness is dependant on the convention of a users PIDs. wildcards for UUIDs don’t make much sense but could perhaps be os use in sequential numeric PIDs or alpha-numeric PIDs.

Dan Field, 2024-01-02 17:41 UTC

I think we can close this. It seems Danny’s issue was raised before we had the ability to include a PID list for inclusion in the migration process. I don’t think we need both an inclusive and exclusive input list and there is scope for clashes and confusion if we did have both.
