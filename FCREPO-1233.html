FCREPO-1233 Ingest of AtomZIP files fails with FileNotFoundException

Description

Fedora allows exporting whole objects in AtomZIP1.1 file, but ingesting this file doesn't work. No error is presented in front end applications.

However, logs fill with FileNotFoundExceptions like this:
```
Unable to read temp file created for datastream from archive for qucosa:1 / ATT-1
java.io.FileNotFoundException: /home/claussni/opt/apache-tomcat-7.0.55/temp/atomzip7872738724372657615/ATT-1.0.pdf (No such file or directory)
```

Root cause is that the temporary folder ```/atomzip7872738724372657615/``` doesn't exist on ingest time.

The bug is in ```org.fcrepo.server.storage.translation.AtomDODeserializer.deserialize()```. The temporary directory gets deleted after building the new digital object, but references for managed datastreams still point there.

Ralf Claussnitzer, 2015-03-02 07:50 UTC

Benjamin, thanks for looking into this. To answer your question about the objects characteristics, see this object from my vagrant setup:
https://github.com/qucosa/qucosa-vagrant/blob/master/puppet/modules/fedora/files/qucosa_1_atom.zip
The error should be triggered by any simple object with an attached file datastream.

But, the problem I addressed in the initial pull request simply is this broken workflow:

1- Upload ATOMZip
2- Extract all files to temporary directory
3- Build Fedora Object with datastreams referencing this temporary directory
4- Delete this very temporary directory
5- Ingest the Fedora Object trying to upload non-existing files to Fedora

The order is clearly wrong here. I think this is because the original XML based METS and ATOM based ingest routines don't rely on temporary uploaded files hanging around somewhere; So that after the construction of the Fedora Object all temporal data can be destroyed.
