FCREPO-3636 Validate RDF on rebuild

TypeImprovement
StatusOpen
PriorityMedium
ReporterDanny Bernstein
Created2021-02-16 19:04 UTC
Updated2021-02-23 06:38 UTC
Componentscore
Affects versionsFedora 6.0.0

Description

Currently we are not validating RDF on rebuild.  A problem could arise if the internal RDF subject and object URIs do not conform to Fedora's expectations.  We will index the object but then choke when trying to access it.  

To be defined:  the validation rules

Ralf Claussnitzer, 2021-02-23 06:38 UTC

I was not so much thinking about RDF in particular but that could be a one side of the same problem. What I was actually thinking about is invalid XML documents (my use case mostly). Or more general: POSTed content that does violate the specified request content type. For example sending a GIF with content type application/jpeg. Currently there is no way to protect Fedora from this.

In the end I will need to implement an extra-Fedora HTTP endpoint to check the transmitted files against very specific content types rules. For example, we use a custom content type application/vnd.qucosa.mets+xml which defines certain structural constraints.

Since this is very application specific it should not be included in Fedora, I agree. I'm actually not sure if API-X is the appropriate solution for this. There is Camel now and it can produce HTTP endpoints for integrating with Fedora.
