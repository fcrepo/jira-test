Description

Currently only an ingest cleans up after itself if it fails, by removing artefacts created during the ingest (objectStore, datastreamStore, registry, fieldSearch, resourceIndex).

If an operation fails part-way through, then anything added during the operation should be removed, to prevent inconsistencies eg between the registry, objectStore and datastreamStore.

NB the objective of this is NOT to introduce full transactioning including rollback, it is to ensure consistency. Particularly the canonical store (objectStore, datastreamStore) should be left in a consistent state.
