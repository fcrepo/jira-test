Description

WebAC is now part of the API specification, and should not be an add-on module. Move it into the fcrepo4 repository
https://github.com/fcrepo4/fcrepo-module-auth-webac

Apparently, fcrepo-module-auth-webac depends on some classes from rbacl, which is in fcrepo4-exts.
https://github.com/fcrepo4-exts/fcrepo-module-auth-rbacl

Move all necessary code from those external repositories into the core code base.

Comments (4)

Aaron Birkland, 2017-09-15 21:05 UTC

It may also be an option to leave it in its separate repo, declare it as a (non-optional) dependency, but still change the various webxml and spring files in the main repo so as to enable webac from the default build

This may take some judgement calls.  Leaving it as a separate repo (but as a hard dependency) would be the most conservative approach.

Esmé Cowles, 2017-09-18 13:18 UTC

I think there are two big reasons to merge the webac module back into the core codebase:

  1. To catch breaking changes and incompatibilities as soon as they happen, by having the webac tests run on each build
  2. To make it easier to do releases, by reducing the number of separate projects that need to be released

That said, I think it would be fine to start out by making it a non-optional dependency that is compiled in by default.
