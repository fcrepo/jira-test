Ben Pennell, 2018-11-12 22:04 UTC

I see two references to it
https://github.com/fcrepo4/fcrepo4/blob/master/fcrepo-kernel-modeshape/src/main/java/org/fcrepo/kernel/modeshape/rdf/impl/AclRdfContext.java#L57
https://github.com/fcrepo4/fcrepo4/blob/master/fcrepo-http-commons/src/main/java/org/fcrepo/http/commons/responses/ViewHelpers.java#L202

Apparently `fedora:writable` controls if the “Update Content” panel appears in the html ui.

It also appears to be telling us if modeshape is giving any of the following permissions “add_node,set_property,remove”. That seems a little out dated given that we are not relying on modeshape permissions anymore. I’m not sure if others feel that it is still necessary to provide a triple that tells the user if they can write to a resource, but the current implementation is inaccurate. We will probably need to update how the “Update Content” panel gets rendered too if I’m reading things correctly (edited)

Peter Matthew Eichman, 2018-11-15 16:46 UTC

My feeling is that we should figure out a way to fix fedora:writable so a client application or a user can know in advance if they can write to a resource. Also, with the support of acl:Appends mode in WebAC, should we think about adding a fedora:appendable triple as well, to differentiate these two use cases?

As an alternative, if there was a way for the resource to return an HTTP header that indicates what modes the requesting user has permission on the current resource, that would help. Something like this for read-only access:

Access-Mode: <http://www.w3.org/ns/auth/acl#Read>

read/append (but not write):

Access-Mode: <http://www.w3.org/ns/auth/acl#Read>,
    <http://www.w3.org/ns/auth/acl#Append>

read/append/write (but not control):

Access-Mode: <http://www.w3.org/ns/auth/acl#Read>,
    <http://www.w3.org/ns/auth/acl#Append>,
    <http://www.w3.org/ns/auth/acl#Write>

all modes:

Access-Mode: <http://www.w3.org/ns/auth/acl#Read>,
    <http://www.w3.org/ns/auth/acl#Append>,
    <http://www.w3.org/ns/auth/acl#Write>,
    <http://www.w3.org/ns/auth/acl#Control>
