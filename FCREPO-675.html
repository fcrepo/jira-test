Stephen Bayliss, 2010-06-23 09:25 UTC

Reopening this as there's a danger that we're introducing version semantics that we might not want to commit to.

Using the URL objects/pid/datastreams/dsid/versions could be seen to imply that datastream versions should be addressable resources using URLs such as objects/pid/datastreams/dsid/versions/versionid - and that we should in the future provide these endpoints for GET/DELETE operations.

Do we instead want to steer clear of "versions" semantics and instead use a URL ending with "history"?

Former user, 2010-06-23 12:28 UTC
