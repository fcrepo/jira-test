Description

Currently there is a mismatch between Mode and WebAC permission modes which makes it difficult to implement SOLID/WAC features such as acl:Append. More precisely, WebAC permissions are more granular than Modeshape. The work of this ticket (which may need to be broken into multiple tickets depending on what is involved) move WebAC into the fcrepo-http-api layer.

Peter Matthew Eichman, 2018-04-16 19:33 UTC

Some thoughts upon initial review of the current state of Fedora's authz stack:

  1. We will remove support for the deprecated XACML and RBACL Fedora Authorization Delegates (FADs)
  2. Confirm what happens if we initialize Modeshape without a FAD; if it defaults to full access, that's fine, otherwise we may need to have a simple FAD to just grant full access to any operation that has bee cleared by the HTTP layer
  3. Remove the AbstractRolesAuthorizationDelegate class and any related cruft from the WebAC FAD
  4. Investigate rewriting the WebAC FAD to use Apache Shiro, and use the Shiro API in the HTTP layer
