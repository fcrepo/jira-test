Following up on Esmé Cowles's question from the call earlier, I see now the implementation I described of using "prefer header = minimal" to skip server managed triples was in fact implemented only in my mind, so something along those lines will need to be done to make this work for import. It is complicated, though, because the triples on disk will include the server-managed ones, and so we'll need to work around that (perhaps something like checking if the minimal triples coming from Fedora are a subset of what is on disk).

There are also a couple typo bugs on the import side, so clearly that part hasn't been tested.

I also think FCREPO-2240 Closed is a blocker for proper functioning of the verification tooling on import operations.

Esmé Cowles, 2016-11-07 20:03 UTC

Josh-

We do that kind of filtering in the import utility now:

https://github.com/fcrepo4-labs/fcrepo-import-export/blob/master/src/main/java/org/fcrepo/importexport/importer/Importer.java#L270-L278

But I'm not thrilled with that approach of filtering out a laundry-list of predicates and types. Checking whether the minimal triples are a subset of the standard triples sounds like a cleaner approach.

Joshua Allan Westgard, 2016-11-07 22:22 UTC

The subset option is easy to implement, but there is some danger of false positive verification, if for example some number of non-server-managed triples didn't successfully import, then the graph of triples in Fedora could still be a subset of the graph on disk – though presumably the import-export tooling would have caught such an error because Fedora would (I'm guessing) complain that it could not accept all triples in the submitted graph.

An alternative occurred to me that one could make two requests to Fedora, once for minimal triples and once for the full set, and then diff the two graphs to get the set of server-managed triples. Those server managed triples could then be stripped out from a graph of the triples on disk one by one (with some logic for matching subject/predicate – the subject, however, being relative depending on whether the base repository or port has changed) to arrive at the non-server managed triples for the graph on disk.

All of this will be unnecessary once the import tooling can set server managed triples.
