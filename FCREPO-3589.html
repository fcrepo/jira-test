FCREPO-3589 Membership/containment not returned as inbound references

TypeBug
StatusClosed
ResolutionFixed
PriorityMinor
ReporterBen Pennell
AssigneeBen Pennell

Affects versionsFedora 6.0.0

Description

At the moment, membership and containment triples are not returned when making a request to a member or child object with prefer InboundReferences supplied. It appears there is an integration test for IndirectContainers (testGetObjectReferencesIndirect) that expects membership relations to show up in this situation:

https://github.com/fcrepo/fcrepo/blob/main/fcrepo-http-api/src/test/java/org/fcrepo/integration/http/api/FedoraLdpIT.java#L2951

Should we implement this? If so, should the inbound references only appear for membership, or should they also appear for containment?

Comments (5)

Andrew Woods, 2021-01-12 01:33 UTC

I think the rule should be: if a resource-A has a triple with object of resource-B, then a GET request on resource-B with "Prefer: InboundReferences" should return a response that includes resource-A.
