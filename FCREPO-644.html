Description

At the London committer's meeting, there was a consensus that improvements to service deployment should move past incremental improvements to the default WSDL implementation and allow for entirely different service descriptions.

The first step towards this is separating the service-related interfaces used by other modules out from the default 3.0 implementation classes, with the eventual goal of a module-based approach accommodating discrete service deployment models.

Much of this work is just disentangling the implementation and interfaces classes at the package level, but there are a couple of trickier changes, in particular:

ServiceMapper is directly instantiated by the ServiceDefinitionTripleGenerator_3_0. ServiceMapper should really be an entirely hidden implementation, or at least an interface. But the triple generating classes don't really have a context besides a DOReader to work with.

It is also worth noting that ModelBasedTripleGenerator, like Server, effectively handles plug-in logic.
