FCREPO-3246 Cannot create binary resources with content types claimed by RDF sources

Affects versionsFedora 6.0.0

Description

It's not possible to create binary resources with content types that are claimed by RDF sources, for example "text/plain". The bug is in the isBinary() method.

Ben Pennell Adding that header fixes it. Is that a requirement now or is it supposed to still work without the header?

Ben Pennell, 2020-03-10 19:05 UTC

Pretty sure this is how it works in fedora 5. I can't actually remember how you were supposed to ingest file types that were considered RDF as binaries in fedora 4, although i think there was a way to do so. You could probably ask about it in fedora-tech.

The behavior in fedora 5 is documented at least:

https://wiki.lyrasis.org/display/FEDORA5x/RESTful+HTTP+API#RESTfulHTTPAPI-BluePOSTCreatenewresourceswithinaLDPcontainer

In the "CONTENT-TYPE" section

Peter Winckles, 2020-03-10 19:20 UTC

That header was not required in F5. There are FedoraVersioningIT tests that no longer work because they attempt to create binary resources with the content-type of text/plain, which now fails.

Ben Pennell, 2020-03-10 20:07 UTC

I believe you are right that text/plain requiring this special handling is new, it looks like Fedora 5 carved out a special exception for text/plain and csv:

https://github.com/fcrepo4/fcrepo4/blob/fcrepo-5.1.0/fcrepo-http-api/src/main/java/org/fcrepo/http/api/FedoraLdp.java#L759

Whereas in 6 we are only checking what mimetypes jena thinks are rdf types. So for these types, this is a bug. For other RDF types, it seems that requiring the non-rdf source header is expected.
