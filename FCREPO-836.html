Description

The current fedora (3.4.1) installation script does not handle non standard tomcat installations well. There is an assumption of a particular directory structure. However package installed tomcats, for example tomcats installed with the Ubuntu package installer, may arrange their directory structures differently. This causes problems locating resources such as lib files, which manifest when fedora is started up or the fedora command line scripts (notably rebuild.sh) are run. It would be useful if it was possible to configure the installation script so that such directory structures could be specified before the script was run.

Discussed during the Jan 18th committer meeting:

We generally agreed that the commandline utils should have a copy of the needed libs separate from those deployed in the webapp container....it's weird/problematic otherwise. So, this issue is being opened with that solution in mind.

Regarding different lib locations for different containers for the purpose of the webapp only (some go into tomcat/common/lib, some go in tomcat/webapps/fedora/WEB-INF/lib), there is a separate outstanding issue whose solution we think would address that: https://jira.duraspace.org/browse/FCREPO-504

During the discussion, Asger also pointed out that it would be good to have an easy way to deploy custom modules/code without necessarily opening the war file, inserting your libs, and re-packaging, then re-deploying it. He'll submit a separate issue for that.
