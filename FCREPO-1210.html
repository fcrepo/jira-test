Description

Managed/Inline Datastreams should support ETag/If-None-Match, Last-Modified/If-Modified-Since, and Content-Length/Range.
E Datastreams that point to file URIs should support ETag/If-None-Match, Last-Modified/If-Modified-Since, and Content-Length/Range.
E Datastreams that point to http[s] URIs should pass If-None-Match,If-Modified-Since and Range headers to the external service.
In all cases, HTTP 304 should be respected and passed back to the client where appropriate.

Benjamin Armintor, 2014-06-11 17:42 UTC

Just to clarify Range requests requirements:
For control group X/M/E(file) datastreams:
1. They should include "Accept-Ranges: bytes" as a response header for their contents dissemination
2. They should accept "Range: X [- Y]" request headers for their content dissemination
3. If "Range" is in the request headers, they should return a "Content Range: bytes X-Y/LENGTH" response header
4. Bad "Range" requests should result in a 416 response status - and because this feature is built into the existing infrastructure of a single response stream, this will include all multipart range requests

For control group E(http) datastreams:
5. they should pass Range request headers through to backend, and Accept-Ranges/Content-Range back to clients.
And type E(http) datastreams should pass Range request headers through to backend, and Accept-Range/Content-Range back to clients.
