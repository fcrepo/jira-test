Description

By default, MySQL/MariaDB use case insensitive collations. This is problematic because it treats resource ids as case insensitive when the rest of Fedora treats them as case sensitive. Postgres does not have this problem as it is case-sensitive by default.

The problem can be seen by doing the following:

Unable to find source-code formatter for language: shell. Available languages are: actionscript, ada, applescript, bash, c, c#, c++, cpp, css, erlang, go, groovy, haskell, html, java, javascript, js, json, lua, none, nyan, objc, perl, php, python, r, rainbow, ruby, scala, sh, sql, swift, visualbasic, xml, yaml
curl -u fedoraAdmin:fedoraAdmin http://localhost:8080/rest/binary -H "Link: <http://www.w3.org/ns/ldp#NonRDFSource>; rel=type" -v -H "Content-Type: text/plain" -X PUT --data-binary "testing"
curl -u fedoraAdmin:fedoraAdmin http://localhost:8080/rest/binary
curl -u fedoraAdmin:fedoraAdmin http://localhost:8080/rest/BINARY

The final command incorrectly produces a 500 because it unexpectedly blows up when trying to access the resource in OCFL.

We likely need to update our DDLs to specify a case sensitive collation, rather than leaving it to the server default.
