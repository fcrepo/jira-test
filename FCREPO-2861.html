Description

The "hasTombstone" link header does not currently check to see if there is already a trailing slash on an identifier before adding "/fcr:tombstone". The result is urls like "http://localhost:8080/rest/deleteme//fcr:tombstone". This is usually not a problem, but some clients do weird things with consecutive slash characters that cause subsequent requests to fail. See:

https://github.com/rest-assured/rest-assured/issues/867

I haven't verified if this affects 4.7.x.

Here is an example:

curl -vi -XPUT http://localhost:8080/rest/deleteme -ufedoraAdmin:fedoraAdmin

curl -vi -XDELETE http://localhost:8080/rest/deleteme -ufedoraAdmin:fedoraAdmin

curl -vi http://localhost:8080/rest/deleteme -ufedoraAdmin:fedoraAdmin

  1. < HTTP/1.1 410 Gone
  2. < Link: <http://localhost:8080/rest/deleteme/fcr:tombstone>; rel="hasTombstone"

curl -vi http://localhost:8080/rest/deleteme/ -ufedoraAdmin:fedoraAdmin

  1. < HTTP/1.1 410 Gone
  2. < Link: <http://localhost:8080/rest/deleteme//fcr:tombstone>; rel="hasTombstone"
