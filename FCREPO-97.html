Description

After running fedora-rebuild, the pidGen tables sometimes isn't populated. This can cause an error when ingesting objects where the pid is unspecified and must be auto-generated.

The workaround is to check this table after a rebuild and, if it is unpopulated, issue the following SQL before restarting Fedora:

INSERT INTO pidGen (namespace, highestID)
VALUES ($NS, $HIGHESTID)

Where $NS is the namespace, such as "demo",
and highestID is the higest existing numeric
part of all PIDs in the repository, such as 10.

This was caused by clearing the tables after the RebuildServer had started as part of the rebuild process. The value of the last generated PID in memory differed from that in the database, and this cause the behavior to occur when the pidGen table was populated prior to running a rebuild. The behavior wouldn't occur if the pidGen table was empty prior to a rebuild, because the value in memory would not be out of sync with the value in the db (both empty).

The solution was to change the beginning of the SQL rebuild process so that the tables were cleared BEFORE the RebuildServer was started.

The change has been committed to the maintenance-2.2 branch as well as the trunk.
