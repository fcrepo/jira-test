Aaron Birkland, 2011-05-08 00:17 UTC

I've been trying to get this to work for quite some time. The source of my consternation seems to be a bug in xerces:
https://issues.apache.org/jira/browse/XERCESJ-1130

Basically, one cannot define a Schema using two component Schemas with the same namespace.

As an example, in order to validate datastream history, two schemas are needed, datastreamHistory.xsd and datastreamProfile.xsd. They both use the namespace http://www.fedora.info/definitions/1/0/management/. Due to the bug in Xerces, pseudocode
schema = schemaFactory.newSchema([datasteamHistory.xsd, datastreamProfile.xsd])
will produce a schema will end up equivalent to:
schema = schemaFactory.newSchema(datastreamProfile.xsd)
so you will get an error that no datastreamHistory element can be found.

I cannot find a simple way around this bug.. producing a single schema file by "concatinating" the two might possibly work, but I haven't tried that yet

I believe this still applies to xerces 2.11, but I have not tried it, as neither xerces 2.10 or 2.11 is in Maven central Very annoying that such a well known and critical apache project can't or won't update their artifacts in maven central.

Maybe we could also find some other implementation of javax.xml.validation.Validator?
