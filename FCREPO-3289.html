Description

When a repository is not auto-versioning and a resource is deleted. That "deletion" is not versioned to the OCFL object from the mutable head.

This ticket is to determine what the expectation is for what deleted but not purged resources look like in Fedora's OCFL storage.

Comments (8)

Peter Winckles, 2020-04-29 19:06 UTC

The problem is that the deletion is only recorded in the mutable head, and is not represented in the OCFL object proper. Furthermore, it is impossible for the deletion to ever be recorded in the OCFL object because Fedora does not let users version deleted resources, which is how users normally commit changes in the mutable HEAD to an OCFL version.

Andrew Woods, 2020-11-18 15:08 UTC

It seems important to be able to indicate in OCFL that a resource has been deleted, even if auto-versioning is not employed. At a minimum, we should have an answer for this for production, if not Beta.

Peter Winckles, 2020-11-18 15:39 UTC

The only way you could do this is if you auto-version resources when they are deleted.

Andrew Woods, 2020-11-18 15:52 UTC

That seems like a potentially reasonable approach... as long as we document it.

Danny Bernstein, 2021-03-05 17:52 UTC

Peter Winckles:  so for clarification:  when in manual versioning mode,  when a resource is deleted,  whether in a long or short transaction,  we automatically  stamp a version after committing to the mutable head.

Peter Winckles, 2021-03-08 13:32 UTC

Yes, that is what I was suggesting
