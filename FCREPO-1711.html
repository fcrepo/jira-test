FCREPO-1711 Investigate Fixity Properties and Possible Modification

Affects versionsFedora 4.4.0

Description

Determine whether it is possible to modify properties related to fixity:

  • Is a file's sha1 checksum stored in a property or added to the property response dynamically?
  • If it is stored in a property, can it be modified if the code preventing that is removed?
  • Are fixity responses resources that could potentially be modified?

I don't think it's a huge problem. I think two options we should consider are:

1. Allow containers (including skolemized blank nodes) and hash URIs to have premis:hasMessageDigest, but return an error when trying to update it on a NonRdfSource. This would support the JHU usage (where the property is used on a blank node), but prevent breaking fixity, etc.

2. Also allow updating premis:hasMessageDigest on NonRdfSources, which a warning that doing the update can break fixity, etc.
