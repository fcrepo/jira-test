Description

Import plant patent dataset produce error "HTTP 412 Precondition Failed":
WARN 15:53:55.499 (Importer) Adding If-Unmodified-Since header: Fri, 26 May 2017 22:53:22 GMT
ERROR 15:53:55.501 (Importer) Error while importing .../fcrepo/rest/fd/e3/a3/e1/fde3a3e1-c6cd-46af-a859-254627e6258a.ttl (412): HTTP 412 Precondition Failed

Step to replicate:

  • Start Fedora 4.8.0-SNAPSHOT:
    $ java -Dfcrepo.properties.management=relaxed -jar bin/fcrepo-webapp-4.8.0-SNAPSHOT-jetty-console-a07a1a46.jar --port 8080 --headless --contextPath /fcrepo
  • Restore plant patent dataset:
    curl -i -X POST --data-binary "1473315261896-0" "http://localhost:8080/fcrepo/rest/fcr:restore"
  • Export the dataset:
    java -jar -Dfcrepo.log.importexport=DEBUG bin/fcrepo-import-export-0.1.1-SNAPSHOT.jar -b -m export -d data -r http://localhost:8080/fcrepo/rest
  • Start another server:
    $ java -Dfcrepo.home=fcrepo4-data-2 -Dfcrepo.dynamic.jms.port=61717 -Dfcrepo.dynamic.stomp.port=61713 -Dfcrepo.properties.management=relaxed -jar bin/fcrepo-webapp-4.8.0-SNAPSHOT-jetty-console-a07a1a46.jar --port 8686 --headless --contextPath /f4
  • Import the exported dataset:
    $ java -jar bin/fcrepo-import-export-0.1.1-SNAPSHOT.jar -m import -d data -M http://localhost:8080/fcrepo/rest,http://localhost:8686/f4/rest -r http://localhost:8686/f4/rest

The "HTTP 412 Precondition Failed" error will appear repeatedly.

Andrew Woods, 2017-05-26 23:57 UTC

I have verified the existence of this bug.

I suspect it is due to the fact that the resource that fails (fde3a3e1-c6cd-46af-a859-254627e6258a) gets updated after its last-modified date is collected... due to the fact that it has children resources.

 

In thinking about this more, is there any reason that we do not simply use something like Instant.now() as the If-Unmodified-Since header value?

 

It looks like this Travis error may be related to this same issue: https://travis-ci.org/fcrepo4-labs/fcrepo-import-export/builds/236746989#L3975 (the /res1 resource has children that will affect /res1's last-modified date).

Esmé Cowles, 2017-05-28 01:06 UTC

Andrew Woods, it's strange, but I haven't been able to trigger the 412 error locally (I even spun up a Linux VM to see if it was somehow a Mac/Linux thing).

But I would be fine with using the current time in the If-Unmodified-Since header — given the use to restore old content, the intention here is to explicitly overwrite whatever is there, so using something like that will always succeed seems reasonable.
