FCREPO-2474 import-export does not respect containment predicates when pointed at rest/

Description

If I point import-export at http://localhost:8080/rest/pcdm it will recurse through the repository according to ldp:contains relationships.

If I point it at http://localhost:8080/rest it will export that top container only, even though there are two resources (and many more contained within those) in that container:

<http://localhost:8080/rest/>
fedora:lastModified "2017-04-12T23:21:32.652Z"^^<http://www.w3.org/2001/XMLSchema#dateTime> ;
rdf:type ldp:RDFSource ;
rdf:type ldp:Container ;
rdf:type ldp:BasicContainer ;
fedora:writable "true"^^<http://www.w3.org/2001/XMLSchema#boolean> ;
rdf:type fedora:RepositoryRoot ;
rdf:type fedora:Resource ;
rdf:type fedora:Container ;
ldp:contains <http://localhost:8080/rest/pcdm> ;
ldp:contains <http://localhost:8080/rest/baddatatest> ;
fedora:hasTransactionProvider <http://localhost:8080/rest/fcr:tx> .

Esmé Cowles, 2017-05-24 14:12 UTC

I believe this is fixed by https://github.com/fcrepo4-labs/fcrepo-import-export/pull/90

The commit referenced in the ticket made the checking more strict (making sure that the subject of the triple was the resource being retrieved: https://github.com/fcrepo4-labs/fcrepo-import-export/commit/5240eae2bd4629f76f6fc397f8b280c1f40f4349#diff-230835395ae42488584f0706d8828ad4R343 ).

But I think that was overly strict, both because trailing slashes are added and removed in different places, and because hash URIs or other subjects are possible (particularly for other impl. which might not have the single-subject requirement).  So I've removed the requirement for the subject: https://github.com/fcrepo4-labs/fcrepo-import-export/pull/90/files#diff-230835395ae42488584f0706d8828ad4R340
