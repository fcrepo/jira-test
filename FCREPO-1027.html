Description

Errors in the ILowLevelStorage are not correctly reported.

A couple of examples:

A) Managed content datastream file missing

  • create an object
  • add a managed content datastream
  • locate in the Akubra datastream store
  • delete the file
  • do a REST API delete
    result: 200 reported, WARN in the log file. This I think should be a 500 and an ERROR (or even FAIL)

B) FOXML file missing

  • create an object
  • locate the FOXML file in the Akubra object store
  • delete the file
  • do a REST API delete
    result: 404 reported, WARN in the log file. Again I think this should be a 500 and an ERROR or FAIL

Suggest implementation of some test cases for this based on "wrapping" the Akubra implementation in such a way that exceptions can be configurably forced (eg pass parameter to the storage layer that specifies "throw an exception if trying to read object ns:pid/dsid") then test various API methods to ensure that 500 errors are reported (and ERROR/FAIL logged) when there has been a failure in the storage layer.
