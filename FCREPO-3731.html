Description

In a number of places Fedora checks a resources type to determine what action to preform. As much as possible, this logic should be based on the interaction model and not the rdf types. The reason being that the interaction model is stored in the resources headers and is cheap to get, but the rdf types require parsing the user rdf and is generally much more expensive.

Here are a couple of examples of where this is happening:

https://github.com/fcrepo/fcrepo/blob/main/fcrepo-kernel-impl/src/main/java/org/fcrepo/kernel/impl/services/MembershipServiceImpl.java#L453

https://github.com/fcrepo/fcrepo/blob/main/fcrepo-auth-webac/src/main/java/org/fcrepo/auth/webac/WebACFilter.java#L583
