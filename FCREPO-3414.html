FCREPO-3414 Stacktrace in response: PUT without Content-Type

TypeBug
StatusClosed
ResolutionFixed
PriorityMedium
ReporterAndrew Woods
Created2020-09-08 20:33 UTC
Updated2020-11-14 21:07 UTC
Resolved2020-11-14 21:07 UTC
Fix versionsFedora 6.0.0
ParentFCREPO-3142 Modeshape out, OCFL In.

Description

This bug can be seen when attempting to create a BasicContainer with an RDF body, but without a provided content-type. The bug is that the body of the HTTP response to the client is an internal stacktrace. The fix should catch the exception, include a simple error message (e.g. "Content-Type header required"), and a 400 response code.

To recreate this bug:
$ curl -i -d "<> <http://awoods.com#title> 'A title'" -XPUT localhost:8080/rest/test -H'Link: <http://www.w3.org/ns/ldp#BasicContainer>;rel="type"'
