Description

Fedora objects contain RDF triples. These triples are added to the configured triplestore by the addAllDatastreamTriples method of BaseTripleGenerator.java

As of today, this method hard-codes "RELS-EXT" for addition to the triplestore.

Why not add all of the Fedora object's semantic information to the triplestore ?

I suggest modifying this method to add the triples contained by all datastreams that have the "application/rdf+xml" MIME type and the "Internal XML Metadata" control group.

If we develop a patch for this, will it be accepted into Fedora's trunk ?

Cheers,
Nicolas Raoul.

Bill Branan, 2008-10-29 16:29 UTC

There are various reasons why all users do not necessarily want all datastreams which include RDF to be indexed by default. One of these reasons is that these datastreams are often indexed in external triplestores with configuration specific to the expected relationship types. While code could be added to include arbitrary RDF datastreams in the default Fedora triplestore index, this cannot be assumed as a default policy.
