Description

Background: This bug appears to have existed since the inception of API-A Lite. I discovered it while working on refactoring item 1814192 (Constants for namespace/schema uris/locs).

In API-A Lite, many of the XML responses are not namespace-qualified. It appears the intent was to have all of these responses exist in the "/definitions/1/0/api/access" namespace, but the way the XML is written doesn't do that.

For example, objectProfile's root element is (non-namespace-qualified) "objectProfile", and contains the following namespace/xsd-related attributes: "xmlns:xsi", "xsi:schemaLocation". What's missing is an xmlns attribute that declares the namespace of the current element (and children) to be "http://www.fedora.info/definitions/1/0/access/"
