Rosie Le Faive, 2019-05-09 19:59 UTC

As pointed out by Danny in the CLAW issue linked there, we do expect to see this attached to the /fcr:metadata, but as a <link rel="type"/> in its HTTP headers and not in the content (since the content is about the binary proper). 

Jared Whiklo, 2019-05-09 20:42 UTC

Currently a binary returns these <link rel="type"/>s in its headers

Link: <http://www.w3.org/ns/ldp#Resource>;rel="type"
Link: <http://www.w3.org/ns/ldp#NonRDFSource>;rel="type"
Link: <http://mementoweb.org/ns#OriginalResource>; rel="type"
Link: <http://mementoweb.org/ns#TimeGate>; rel="type"

A binary description returns these <link rel="type"/>s in its headers.

Link: <http://www.w3.org/ns/ldp#Resource>;rel="type"
Link: <http://www.w3.org/ns/ldp#RDFSource>; rel="type"
Link: <http://mementoweb.org/ns#OriginalResource>; rel="type"
Link: <http://mementoweb.org/ns#TimeGate>; rel="type"

So in the headers you have a correct separation of RDFSource and NonRDFSource. So I will just look at the RDF properties.

Jared Whiklo, 2019-05-13 21:02 UTC

Rosie Le Faive it is relatively easy to add it to the headers, but it is an internal "type" and so does not really mean anything outside of Fedora.

I would suggest that as the actual binary has a rel="describedby" header which points to the description, you are better to use that and treat the description like any other ldp:RDFSource object.

But maybe you have a use case for this fedora:* type?
