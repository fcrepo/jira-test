Description

The base LDP / REST endpoint (/rest/) is modifiable but does not have an etag. This allows for race conditions in which multiple systems are using PUT to update it simultaneously. It is also inconsistent with other LDP containers provided, though hopefully code would not assume the existence of an etag.

Expected Behavior: All HTTP responses from all modifiable resources, including /rest/, should have an ETag HTTP Header.

Actual Behavior: /rest/ does not have an ETag HTTP Header.

Related: #1498 from Trey Pendragon

Aren't Etags required by LDP anyway? The way I read it is that ETag values in the headers is a MUST, and using it to avoid collisions is a SHOULD.

4.2.1.3 LDP server responses MUST use entity tags (either weak or strong ones) as response ETag header values, for responses that contain resource representations or successful responses to HTTP HEAD requests.

4.2.4.5 LDP clients SHOULD use the HTTP If-Match header and HTTP ETags to ensure it isn’t modifying a resource that has changed

Thanks Aaron! Yes, s/should/must/ in my expected behavior and the issue title. That said, I still think it's minor as modifying the base container isn't something most actual systems would bother with.
