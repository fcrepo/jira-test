FCREPO-3648 PUT to invalid fcr:metadata endpoint gives 500 response

Description

Making a PUT request to a fcr:metadata endpoint for an object that doesn't exist returns a 500 error and logs a lengthy stacktrace, and actually leaves behind ghost nodes for the intermediate container. It seems like the fcr:metadata path should be rejected before anything is created, and give a 4xx response.

In this example, "what" does not exist:

curl -ufedoraAdmin:fedoraAdmin -XPUT http://localhost:8080/rest/what/fcr:metadata -v

HTTP/1.1 500 Internal Server Error

Peter Winckles, 2021-02-18 22:29 UTC

It's interesting that the ghost nodes aren't being rolled back when the transaction fails. This sounds like two bugs:

1. PUTs to fcr:metadata should be rejected if it does not already exist (fcr:metadata resources should only be created as a side-effect of creating a non-RDF resource)
2. Ghost nodes are not rolled back if the transaction that created them fails.

Ben Pennell, 2021-02-19 13:42 UTC

Doing a PUT to a fcr:metadata is a legit method of updating the user RDF in the binary's description, as long as it is the child of a non-rdf resource.

Peter Winckles, 2021-02-19 13:50 UTC

Yes, it's valid for updating. So, if there is a PUT on a fcr:metadata resource that does not exist, it should be rejected.
