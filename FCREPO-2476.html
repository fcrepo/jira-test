Esmé Cowles, 2017-05-24 18:08 UTC

There are some pretty big blockers to this working right now.  On Cavendish's side, there's no support for binaries or external content, so none of the datasets will work right now.

But there are also some other issues that we might want to fix on the Import/Export Tool side:

  • findRepositoryRoot's dependence on the fedora:RepositoryRoot type seems problematic — at the very least, we should fall back to using the resource URI (maybe with the path removed) if the current algorithm doesn't work.
  • Most attempts to import a container failed with the error "javax.ws.rs.ClientErrorException: PUT requires If-Match header" — we should either be using POST with a Slug header, or we could do a HEAD and get the current ETag to use with the If-Match header.
Andrew Woods, 2017-05-24 18:12 UTC

I would suggest moving to POST since the API Spec is moving towards making PUT optional.

Benjamin Armintor, 2017-05-24 18:23 UTC

Esmé Cowles recognizing those tickets as separate issues, would proxied content (with file URIs) support the import? Or is local storage a prerequisite?

Esmé Cowles, 2017-05-24 18:24 UTC

Though now that I think about it — Cavendish does support PUT to create.  The operation that was failing was PUT to update.  Cavendish requires an If-Match header when updating an existing resource.  So the import of /rest succeeded and created placeholders for its child objects, and then the PUTs to update those object with their real RDF is what was failing.

Esmé Cowles, 2017-05-24 18:29 UTC

Benjamin Armintor, I think supporting internal binaries would make the import easiest (because it would map most simply from what the Mode impl. supports).  But proxied content will be good enough — we'll just have to do more work to map the file locations, whether they should be left in the import space or referred to where they are, etc.

Benjamin Armintor, 2017-05-24 18:33 UTC

For what it's worth, If-Match on update is a SHOULD in LDP (4.2.4.5). I've tried to support all of the requirements at SHOULD or MUST.

Esmé Cowles, 2017-05-24 20:08 UTC

Benjamin Armintor I absolutely agree that the If-Match header is a good idea.  The import/export utility should be using it to make sure we're not clobbering resources that other clients have updated.
