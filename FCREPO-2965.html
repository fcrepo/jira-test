Description

Semantic differences in the message bodies emitted by fcrepo4 and fcrepo5 require different approaches to parsing the respective messages.  Add support for parsing fcrepo5 messages, ideally while retaining backward compatibility with fcrepo4 messages.

 

"Backwards compatibility" merely means mapping values from fcrepo4 and fcrepo5 messages to the correct camel headers without any sort of semantic translation between the differen vocabularies used.
