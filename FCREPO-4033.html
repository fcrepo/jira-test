FCREPO-4033 Fedora holding memory when hit with reindexing requests

TypeBug
StatusOpen
PriorityHigh
ReporterJared Whiklo
Created2025-08-28 16:02 UTC
Updated2025-08-28 16:06 UTC
Componentscore

Description

National Library of Wales is trying to migrate 53M objects and then when reindexing into a triplestore. They are seeing Fedora slow down and consume large amounts of memory and high CPU, when pausing the reindexing it seems to run for several hundred more objects before stopping.

Even once the reindexing has stopped Fedora still does not release the memory it is holding on.

NL Wales has also modified fcrepo-camel-toolbox to include an AgregationStrategy to have the triplestore updates batched up as 500 to 1,000. They have also altered the reindexing to avoid checking each object for children as they are using a flat shallow layout.

Was able to reindex by lowering concurrency and slowing the requests to about 150M per seconds. Fedora was running with high memory usage and high CPU and slowed down.

They were able to index 1M objects in an hour. Running at full speed.

Course of action is to try:

  1. reindexing objects with Fedora’s JMS disabled but also logging up to DEBUG and look for any event messages being emitted.
  2. stand up a Fedora and hit it with Apache Bench at 1,000 to 10,000 concurrent requests for longer and longer timeframes looking for the memory increase, try with metrics to see if something appears.
