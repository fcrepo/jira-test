Description

A couple of system properties are referenced throughout the POMs and code but never declared in any POM. These properties can be set in Maven command line executions: ```mvn ... -Dfcrepo.test.port=8080```

The properties should be declared in the man POM using some default values. They can than be overridden by command line arguments.

Ralf Claussnitzer, 2015-02-03 20:04 UTC

Now, I think I know what's going on.

The Build Helper Maven Plugin dynamically creates Maven properties on runtime in the `process-test-classes` phase. One of these properties is `fcrepo.test.port` [1]. There are more port parameters in other configurations in other POMs. It seems like this plugin is crashing if the property already exists and is empty (bug?).

I'm not sure what to do here. Since Maven has no problems it doesn't look like there is anything broken. It's just IntelliJ IDEA complaining about undefined properties. My pull request, however, makes no sense then.

Are these port properties documented somewhere?

[1] https://github.com/fcrepo4/fcrepo4/blob/master/pom.xml#L708

Ralf Claussnitzer, 2015-02-04 08:54 UTC

The build-helper-maven-plugin dynamically changes the environment in a way IDEs might not be aware of. That's a problem of IDEs Maven support, not a problem of the build system itself.

I propose renaming those dynamic properties to denote the fact that they are generated at build time, e.g. `dynamic.fcrepo.test.port`. Does this make sense? If you think so I will update the pull request accordingly and add a page to the Developer Guide.
