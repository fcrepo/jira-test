Is related toFCREPO-768 Installer defaults to Akubra if no option is specified in an install.properties file

Description

The resources/scripts/test properties files are out of date. For instance they use fesl.enabled, whereas the installer now uses fesl.authn.enabled and fesl.authz.enabled.

Maybe we could have an installer-generated warning so when reading a properties file during installation, if an expected value is not found and the default is used, this could be reported?

Furthermore, the defaults specified in WebXMLOptions.java are not consistent with those specified in OptionDefinition.properties - the constructor appears to be setting its own default values.

test case:

  • don't specify fesl.authz.enabled and fesl.authn.enabled: ConfigA and ConfigB tests pass
  • specify the default values (authn true, authz false): tests fail.

In the first case the default values should have been used, however this appears not to be the case.
