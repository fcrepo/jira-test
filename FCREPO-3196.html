FCREPO-3196 Refactor ArchivalGroup validation into the kernel layer.

TypeStory
StatusOpen
PriorityMinor
ReporterDanny Bernstein
Created2020-01-30 23:50 UTC
Updated2021-07-06 19:01 UTC
Componentscore
Affects versionsFedora 6.0.0

Description

Currently validation for archival groups is happening in the AbstractPersister.resolveRootObjectId() class down in the fcrepo-persistence-ocfl module. 

It may make more sense for this initial check to happen higher up in the stack, namely that the kernel or HTTP layer.   Be that as it may we still need a way to determine whether a given resource should be nested within an archival group on persist.  

What archival group if any should new fedoraResourceA be nested in? 

The FedoraToOCFLIndex  can tell you for a given fedoraResourceId what  is the fedora identifier associated with the ocfl object root.   We could extend this to maintain a flag indicating whether or not the root identifier is an ArchivalGroup.

Then we could move the AbstractPersister.findArchivalGroupInAncestry() into FedoraToOCFLIndex.
