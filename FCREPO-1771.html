Description

As per consensus in the 2015-10-08 Fedora Tech call[1], create a fcrepo4-vagrant base box that contains:

  • Java 8
  • Maven
  • Karaf
  • Tomcat
  • Solr
  • Fuseki

Host this base box on Atlas, which then can be used in fcrepo4-vagrant to speed up builds.

This would be similar to what the Islandora community did with Islandora Vagrant[2] and Islandora Vagrant Base Box[3].

[1] https://wiki.duraspace.org/display/FF/2015-10-08+-+Fedora+Tech+Meeting
[2] https://github.com/islandora-labs/islandora_vagrant
[3] https://github.com/islandora-labs/islandora_vagrant_base_box

James Griffin, 2015-10-17 16:59 UTC

Nick Ruest thank you very much for this release. I have not found any faults with the build thus far.

I have attempted to structure some acceptance tests for the build using Beaker. Please see the following:

https://github.com/jrgriffiniii/fcrepo4-vagrant-base-box/tree/FCREPO-1771-jrgriffiniii-beaker

Using an extension of RSpec, Beaker permits me to validate the state of the Box after it has been built. For example:

[...]
  describe file('/opt/apache-karaf-4.0.1') do
    it { should be_directory }
  end

  describe file('/opt/karaf') do
    it { should be_symlink }
  end
[...]

Should this approach to quality assurance seem appealing, I encourage you to clone the branch within the forked repository, and execute the following:

$ bundle exec rspec spec/acceptance/

By default, I am testing against the Atlas build (this is a proof of concept). I can just as easily restructure this to build against the environment provisioned using the BASH scripts.

Further (and, I would argue, ideally) this could be restructured for a CI environment. Assuming that TravisCI builds do not timeout when downloading the base Box, I would speculate that this could be attempted using a .travis.yml file alone.

Please let me know if this is useful. Thank you again.
