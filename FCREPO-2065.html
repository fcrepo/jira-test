Description

Scenario: both normal users (as configured in tomcat) and impersonated users (via admin account and on-behalf-of header) access the repository.

If admin user calls fedora with on-behalf-of header, all works as expected. If non-admin user calls fedora and adds on-behalf-of header, the contents of header gets propagated to FEDORA_ALL_PRINCIPALS - this is done in HttpHeaderPrincipalProvider.getPrincipals() as DelegateHeaderPrincipalProvider is a subclass of HttpHeader...
