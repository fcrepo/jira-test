Description

Whenn you enter
http://fedora-server.dom/fedora/objects/
(note the final slash; this can happen by "hacking off" the last part of a long URL to navigate back), then
a query of the following type is issued by Fedora:
http://fedora-server.dom/fedora/objects/?pid=true&title=true&description=true&identifier=true&terms=*&query=&maxResults=20
(Note the / before ?pid)
The resulting page contains broken links of the type
http://fedora-server.dom/fedora/objects/objects/prefix%3Asuffix
(Note the duplication of objects/ in the path)

Following the broken links gives back a completely empty page.

The 3.5 behavior was to return a 404 for /fedora/objects/, for what it's worth.

Benjamin Armintor, 2012-08-23 18:38 UTC

Frank's code should be merged in for other reasons, but I'm closing this issue as won't fix: /fedora/objects and /fedora/objects/ are two different URIs and thus two different REST resources. We should be returning a 404 when there's a trailing slash, and interpreting it as a request for an object profile with a null PID. If anyone is relying on /fedora/objects/ to resolve to the object search, they are depending on a bug in the REST API introduced in the CXF migration. If the reporter is relying on the object search programatically, they should be using the XML output serialization anyway.

Jörg Knappen, 2012-08-24 14:40 UTC

From a usability point of view, I think the "buggy" behaviour of fcrepo-3.6 to present the search view on
localhost:8080:fedora/objects/ preferable to the old behaviour of presenting a 404.

The main point is that the URL is probably entered by a complete layperson (in respect of fedora
and its technologies) who wants to find some item from the repository. The search form fulfils the
expectations of the layperson, the 404 answer leaves him or her cluelessly.

Benjamin Armintor, 2012-08-24 17:51 UTC

That service is intended to support repository administration and a machine- and human-usable REST api, not end-user discovery. If end-user access at ambiguous URLs is important to a particular installation, FCRepo 3.6 makes it relatively easy to wire in a customized REST resource to perform that function.
