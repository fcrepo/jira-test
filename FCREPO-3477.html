Andrew Woods, 2021-01-09 00:11 UTC

We may want to discuss the desired behavior here, as the current behavior may be considered correct.

The Fedora API Specification says:

  • https://fedora.info/2018/11/22/spec/#ldprv-get
    ```
    If no LDPRm is appropriate to the Accept-Datetime value, implementations should return a 406 (Unacceptable).
    ```

The question is, "what is 'appropriate'"?

F5 considered Accept-Datetime values that precede the first Memento as "inappropriate"... whereas, F6 returns the first Memento in this case.

The Memento specification leaves the question of "appropriateness" up to the implementation:

  • https://tools.ietf.org/html/rfc7089#section-3.1
    ```
    In order to respond to a datetime negotiation request, the server
    uses an internal algorithm to select the Memento that best meets the
    user agent's datetime preference. The exact nature of the selection
    algorithm is at the server's discretion but is intended to be
    consistent, for example, always selecting the Memento that is nearest
    in time relative to the requested datetime, always selecting the
    Memento that is nearest in the past relative to the requested
    datetime, etc.
    ```

There is a compatibility argument for aligning the F6 behavior with F5.

Peter Winckles, 2021-01-14 16:52 UTC

To me, it seems like the test is wrong.

From https://wiki.lyrasis.org/display/FEDORA5x/Versioning:

The date algorithm Fedora uses to determine which LDPRm should be returned to a TimeGate request, as indicated by the value of the Accept-Datetime header, is as follows:

    Any Accept-Datetime value that is earlier than the first/oldest Memento will return a reference to the first/oldest Memento.
    Any Accept-Datetime value that is later than a specific Memento’s timestamp but earlier than another Memento’s timestamp will return the older Memento.
    An Accept-Datetime value that matches a stored Memento datetime value perfectly will return the Memento preserved at that timestamp.
    An Accept-Datetime value that is later than the last Memento will return a reference to the last/youngest Memento.

 

Danny Bernstein, 2021-01-14 18:03 UTC

If I'm not mistaken,  the above documentation is not aligned with fedora 5x behavior.   Since that is what is out in the wild I would suggest we update these documents to reflect 5x's behavior and then align f6 with f5.

 

Danny Bernstein, 2021-01-15 17:52 UTC

Peter Winckles:  as it turns out I was mistaken.  The documentation is correct.  I verified that in 5.1.1, the date algorithm behavior matches the documentation. I'll investigate the test to see what's going on there.  

Danny Bernstein, 2021-01-15 18:02 UTC

Actually - on further examination the issue appears to be in the case of a resource with no mementos. Since F6 by default is autoversioned,  it is returning the most recent memento whereas F5 does not autoversion and therefore returns 406 because there are no mementos.

So the fix is to check whether or not there are mementos before testing for a 406.
