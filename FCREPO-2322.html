FCREPO-2322 verification tool cannot determine if a record is missing

Description

If I create an f4 export and then verify it, it fails to notices that I've removed some resources in Fedora.

The logic of the verification tool should, perhaps, walk both of the systems - first walking one system, say the file system, checking to see that things are in fedora. Then, secondly, walk the fedora 4 server checking to see that the resources are on disk. This would help determine if resources have been dropped altogether. Perhaps the second pass could have a short cut, since if the item is there, the resources have already been compared for sameness in the first pass.

Part of me wonders if the above is actually necessary, but it does seem like it's a huge gap if we can't tell that a resource is missing altogether.

So if I do an export, then I delete resources from Fedora. Should the validation of my export fail? I'd say no, because at the time the export the resource was there. Otherwise I think the verification tooling should be migrated into the import-export script and occur right after the export.

Bethany Seeger, 2016-12-12 16:41 UTC

That's very true.

Use cases for this type of feature:
1) a resource could get lost during export/import (unlikely, but it would be good to know if one does go missing)
2) I want to know what's changed since I last exported things from the system.

I would agree that #2 is out of the scope of the purpose of this tool. When I wrote this ticket, I was thinking of use case #1.

Jared Whiklo, 2016-12-12 17:02 UTC

Ok so we need to know when the export started and possibly when it ended, then we need to walk the Fedora repo down from the chosen resource for any resources that existed before either of date/times and see if they exist on disk.

Joshua Allan Westgard, 2016-12-16 15:05 UTC

After discussion it was agreed that we would provide documentation explaining that the verification tool only works against the resources that are in the tree in the location specified by the config file submitted.

  1. If users add resources after export, they will get an error because the added resource won't be present in the exported set.
  2. If users delete resources from the original tree after export, the tool will not notice that they have been deleted, even though "extra" resources would be present in the export.

This ticket should be closed as "will not fix" and a new ticket for documentation opened.
