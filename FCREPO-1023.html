Egbert Gramsbergen, 2011-11-01 20:47 UTC

The currently used format follows a very early draft at http://www.w3.org/TR/2004/WD-rdf-sparql-XMLres-20041221/
It is more than just a namespace issue. As an illustration, compare (within a <result> element)
old:
<hpage uri="http://work.example.org/bob/"/>
and new:
<binding name="hpage">
<uri>http://work.example.org/bob/ </uri>
</binding>
(where I added a space after /bob/ because otherwise the Wiki screws things up)
Btw, it would be nice if both forms would be available e.g. through a different "format" parameter in the RI search service. Speaking for myself, I have lots of predefined queries where the results are processed with xslt and modifying all these is more than a trivial task.

frank asseg, 2012-05-04 13:25 UTC

I added this functionality using a new format parameter.
Please check out https://github.com/fcrepo/trippi/tree/fcrepo-1023. The format parameter is called "SPARQL_W3C" as can be seen in the attached screenshot. The result of a query looks something like this:

<?xml version="1.0" encoding="UTF-8"?>
<sparql xmlns="http://www.w3.org/2005/sparql-results#">
	<head>
		<variable name="object"/>
		<variable name="modified"/>
	</head>
	<results>
		<result>
			<binding name="object"><uri>info:fedora/demo:1</uri></binding>
			<binding name="modified"><literal datatype="http://www.w3.org/2001/XMLSchema#dateTime">2012-05-04T07:52:30.986Z</literal></binding>
		</result>
		<result>
			<binding name="object"><uri>info:fedora/demo:19</uri></binding>
			<binding name="modified"><literal datatype="http://www.w3.org/2001/XMLSchema#dateTime">2012-05-04T07:52:27.08Z</literal></binding>
		</result>
	</results>
</sparql>

Problem is that i don't know how to handle null nodes. In the standard SparqlTupleWriter.java null nodes get printed qith an attribute bound="false" but i have not found anything in the W3C spec about this. Can you guys give me an hint?

While on the job....

The CSV-format returned from Tuple queries is not very helpful. It quotes ("x") your resultset variables, which is hindering futher processing. Execute the following sparql query:
SELECT ?s ?p ?o
WHERE

{ ?s ?p ?o }

The CSV returned starts with: "s","p","o". Load the stream in a Jena ResultSet ...
ResultSet resultSet = ResultSetFactory.load(entity.getContent(), ResultsFormat.FMT_RS_CSV);
... and print the variables:
System.out.println(resultSet.getResultVars());
Producing the output: ["s", "p", "o"]

Now transform the resultset to sparql xml, using the Jena ResultSetFormatter:
ResultSetFormatter.outputAsXML(..., resultSet);
And you get invalid xml like: <variable name=""s""/>

So why are my variables quoted in the first place?
