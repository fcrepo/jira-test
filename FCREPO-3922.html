Description

Due to the changes in https://fedora-repository.atlassian.net/browse/FCREPO-3882 when you try to access the final version of a binary using the HTML UI it throws a 500 Server Error.

This is because while the http://localhost:8080/rest/some-binary will return the 410 Gone, the HTML UI automatically tries to go to http://localhost:8080/rest/some-binary/fcr:metadata and that throws the stack trace.

Jared Whiklo, 2024-02-28 21:25 UTC

Correction this is a problem with the HTML UI, which sticks the /fcr:metadata on the end.

i.e.

Create a binary, edit it’s metadata, delete it (preferably taking a second or more for each action to get 3 mementos).

eg. http://localhost:8080/rest/some-binary

Access the first or second memento with HTML UI

eg. http://localhost:8080/rest/some-binary/fcr:metadata/fcr:versions/20240228211850

Then choose the last memento, and end up at

http://localhost:8080/rest/some-binary/fcr:versions/20240228211935/fcr:metadata

fcr:metadata is in the wrong location and this causes the stacktrace.
