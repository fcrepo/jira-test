FCREPO-2430 Import/Export: Make use of configuration explicit

Fix versionsfcrepo-importexport-0.2.0

Description

Generating a config implicitly and then using it on subsequent operations means that those who expect their command-line options to apply only for that command will be surprised.
Generating a config to /var means that on certain OS, the config will be lost upon system restart. So those who rely on the persistence of previous command line options will also be surprised.
Generating a config on first execution means that order of operation between otherwise independent calls matters (say, 3 calls, each exporting a different object with different options).
I would recommend an explicit --set-config or --write-config option to eliminate these 3 categories of surprise.

See: https://wiki.duraspace.org/display/FF/Sprint+3+Feedback+-+Joe+Atzberger

Esmé Cowles, 2017-05-25 18:00 UTC

Joe Atzberger, the tool checks if the config file is there, and writes it with the current options if it's not. Other than that, it doesn't read or use the config file, unless the –config option is specified (in which case, it gets parsed and used for the args).  I think the log message "Configuration file exists, new file will NOT be created" may be more confusing than helpful here.

The logic behind writing a config file based on the current options was that it made it much easier to use the config file feature if you had a sample to work from.  But I'm increasingly thinking we shouldn't write one unless an option says we should (and provides the path to write it).
