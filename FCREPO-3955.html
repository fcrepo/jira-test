FCREPO-3955 500 response for range request with content size as end of range

Description

This is a bit of an oddity, but if you request a byte range for a binary where the end of the range is the exact same as the content length of the binary, then fedora responds with a 500. I’ve confirmed this behavior in fedora 5 and 6, although we probably only need to fix it in 6.

Given a file that is 1713 bytes in size:

curl -v -o /dev/null http://localhost:48080/rest/76ec0df2-17f3-4ad3-a79c-aa2a19c09e2f  -H"Range: bytes=1000-1713"

< HTTP/1.1 500 Server Error

curl -v -o /dev/null http://localhost:48080/rest/76ec0df2-17f3-4ad3-a79c-aa2a19c09e2f  -H"Range: bytes=1000-1712"

< HTTP/1.1 206 Partial Content

curl -v -o /dev/null http://localhost:48080/rest/76ec0df2-17f3-4ad3-a79c-aa2a19c09e2f  -H"Range: bytes=1000-1714"

< HTTP/1.1 416 Requested Range Not Satisfiable

curl -v -o /dev/null http://localhost:48080/rest/76ec0df2-17f3-4ad3-a79c-aa2a19c09e2f  -H"Range: bytes=1713-1715"

< HTTP/1.1 416 Requested Range Not Satisfiable

curl -v -o /dev/null http://localhost:48080/rest/76ec0df2-17f3-4ad3-a79c-aa2a19c09e2f  -H"Range: bytes=1713-1713"

< HTTP/1.1 500 Server Error

My impression from the specification is that we should actually return a 206 for any range request where the end of the byte range is equal or greater than the content size since it means the client is requesting the rest of the file:

https://httpwg.org/specs/rfc7233.html#byte.ranges

A client can limit the number of bytes requested without knowing the size of the selected representation. If the last-byte-pos value is absent, or if the value is greater than or equal to the current length of the representation data, the byte range is interpreted as the remainder of the representation (i.e., the server replaces the value of last-byte-pos with a value that is one less than the current length of the selected representation).

So while the 500 responses would be especially good to fix, it seems like we should be returning 206 for requests like these. It sounds like 416 is expected if the start of the range is greater than the end, or greater than or equal to the size of the file.
