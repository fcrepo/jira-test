FCREPO-1206 Multipart PUT requests are broken

Description

Trying to update a datastream using a multipart encoded PUT request does not work. Fedora will save the multipart wrapper in the datastream contents. See attached file for example.

It seems like the problem is here:

https://github.com/fcrepo/fcrepo/blob/master/fcrepo-server/src/main/java/org/fcrepo/server/rest/RestUtil.java#L45

because isMultipartContent() only recognizes multipart messages that use the POST method:

http://commons.apache.org/proper/commons-fileupload/apidocs/src-html/org/apache/commons/fileupload/servlet/ServletFileUpload.html#line.66

Benjamin Armintor, 2014-01-25 02:50 UTC

It is apparently believed that the semantics of PUT are incompatible with multipart request bodies, so I doubt that commons-fileupload regards this as a bug (and Fedora 3 is not going to change this dependency in the foreseeable future). See also http://www.w3.org/Protocols/rfc2616/rfc2616-sec9.html#sec9.6

Don Brower, 2014-01-25 03:04 UTC

Thanks for the answer. I don't completely follow how that section of RFC-2616 precludes multi-part uploads (e.g. what if all the files form a single semantic unit), but that is fine.

FYI, the docs for modifyDatastream say the content should be multipart encoded.

https://wiki.duraspace.org/display/FEDORA37/REST+API#RESTAPI-modifyDatastream

Benjamin Armintor, 2014-01-25 03:35 UTC

The POST behavior just takes the first part... Hmm. Well, i any case, worth re-opening if nothing else as a landmark to a muddled part of the API.
