FCREPO-623 Journaling RMI transport writer does not send close() events

Description

RMI transports will always fail when rolling over to a new journal file. A receiver will terminate the connection with an exception indicating refusal to write to a new journal while another is still open.

Aaron Birkland, 2010-01-12 16:22 UTC

This does not affect 3.2 or earlier versions. There is no relevant code change in Fedora 3.3, leading me to believe that perhaps the behaviour of a third party library has changed (or a different implementation is being used). The problem seems to come from the StAX XMLEventWriter. The code assumes that XMLEventWriter.close() will result in close() being called on the underlying writer (which is in this case is an RMI journal transport class). For whatever reason, this is not happening in this version, so the transport is never closed.

I made a quick workaround patch that explicitly closes the rmi transport writer (attached), but this issue deserves to be look at in more depth to verify that similar situation does not occur elsewhere, and determine if it is the StAX impl's fault (i.e. a buggy library), or if the code is making an improper assumption that just happened to work
