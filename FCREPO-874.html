FCREPO-874 ServerInitializationException: Failed to ingest system object(s), while upgrading from 3.3.1 to 3.4.2

Resolved2015-01-16 21:01 UTC
Affects versionsFedora 3.4.2

Environment

Linux 2.6.35.11-83.fc14.i686.PAE Fedora 14 i686

Description

1. have a previous 3.3.1 installation in /usr/local/fedora-3.3.1
have /usr/local/fedora-3.4.2 directory created
have /usr/local/fedora -> fedora-3.4.2
have $FEDORA_HOME set to /usr/local/fedora

2. follow instructions "Upgrading from 3.x to 3.4.2" on https://wiki.duraspace.org/display/FCR30/Upgrading+from+3.x:
(2.a) modify /usr/local/fedora-3.4.2/server/config/fedora.fcfg (fedora_db = DB for 3.3.1 instance):
<param name="jdbcURL" value="jdbc:mysql://localhost/fedora_db?useUnicode=true&amp;characterEncoding=UTF-8&amp;autoReconnect=true">
(2.b) modify /usr/local/fedora-3.4.2/server/config/fedora.fcfg:
<module role="org.fcrepo.server.storage.lowlevel.ILowlevelStorage" class="org.fcrepo.server.storage.lowlevel.DefaultLowlevelStorageModule">
<param name="object_store_base" value="../fedora-3.3.1/data/objects" isFilePath="true">
<param name="datastream_store_base" value="../fedora-3.3.1/data/datastreams" isFilePath="true">

3. starting the new repository fails:

org.fcrepo.server.errors.ServerInitializationException: Failed to ingest system object(s)
...
Caused by: org.fcrepo.server.errors.LowlevelStorageException: file /usr/local/fedora-3.4.2/data/objects/2010/1005/15/54/fedora-system_ContentModel-3.0doesn't exist for reading

COMMENTS:

  • using full-paths doesn't work either (value="/usr/local/fedora-3.3.1/data/objects")
  • possible solution: rebuild MySQL (and Resource Index ?) using fedora-rebuild.sh

Stephen Bayliss, 2011-03-10 23:25 UTC

Looking at the error message, it is looking for file /usr/local/fedora-3.4.2/data/objects/2010/1005/15/54/fedora-system_ContentModel-3.0

This looks like a path to your 3.4.2 objects, not 3.3.1.

Fedora picks up the path from the SQL database, so it looks like it is not looking at the 3.3.1 database, but the 3.4.2 version.

Foudil Bretel, 2011-03-11 15:31 UTC

I see. No, actually Fedora does look at the 3.3.1 database (as indicated in the documentation, I haven't created a new DB for 3.4.2), which contains objectPaths like "/usr/local/fedora/data/objects/2011/0208/17/26/bil-fiche_FOUDIL46.1". But since /usr/local/fedora is now a link to fedora-3.4.2, Fedora is looking at an non-existent path.

I find it misleading not having param "object_store_base" in fedora.fcfg taken into account by Fedora at startup, or maybe the documentation should state that the directory/filesystem itself should point to previous 3.x locations.
