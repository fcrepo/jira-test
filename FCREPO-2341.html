Description

When testing the API-X demo[1] depositing binaries via the Fedora html UI, sometimes the user is redirected to the wrong place. Instead of /fcr:metadata, the user is sometimes directed to the API-X service document.

This appears to be due to the UI parsing link headers incorrectly. If there are multiple link relations, e.g.:
Link: </otherPlace>; rel="anOtherRel"
Link: </fcr:metadata>; rel="describedby"
.. the net effect is that the UI picks a random link regardless of relation.

const fn = function (method, url, headers, data) {

Jared Whiklo, 2016-12-11 03:35 UTC

On second thought trying to test this through a docker machine is too confusing. However I think the answer is much the same as Unknown did for the checkIfNonRdfResource so something like

    const fn = function (method, url, headers, data) {
      http(method, url, headers, data, function(res) {
        if (res.status == 201) {
          const loc = res.getResponseHeader('Location');
          const linkheaders = res.getResponseHeader('Link').split(", ");
          const link = linkheaders.filter(function(h) { return h.match(/rel="describedby"/)});
          if (linkheaders != null && link.length > 0) {
            window.location = link[0].substr(1, link[0].indexOf('>') - 1);
          } else if (loc != null) {
            window.location = loc;
          } else {
            window.location.reload();
          }
        } else {
            ajaxErrorHandler(res, 'Error creating binary');
        }
      });
    }

should work.
