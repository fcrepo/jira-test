FCREPO-3609 Conditional PUT without Server Managed Triples Using 'If-Match' Always Fails

Affects versionsfcrepo-6.0.0-alpha-2

Environment

ISLE (Alpine docker container, running Tomcat 9 and Java 11)

Description

When attempting to perform a conditional update without server managed triples using an ETag and If-Match, Fedora 6 always returns 412 - Precondition Failed.

 

To recreate:

  • Get the Etag for a representation without server managed triples: 
    $ curl -sSI -H "Accept: application/ld+json" -H 'Prefer: return=representation; omit="http://fedora.info/definitions

    /v4/repository#ServerManaged"' http://example.org/fcrepo/rest/path/to/resource | grep Etag | cut -d '/' -f 2

"6EE1808846332B561426844981C370A0"

  • Get the same representation and write it to a file: 
    $ curl -H "Accept: application/ld+json" -H 'Prefer: return=representation; omit="http://fedora.info/definitions/v4/repository#ServerManaged"' http://example.org/fcrepo/rest/path/to/resource > test.json
  • Edit the file and change some RDF.
  • Try and PUT it back using `If-Match`: 
    $ curl -X PUT -H 'Authorization: XXX' -H 'Content-Type: application/ld+json' -H 'Prefer: handling=lenient' -H 'If-Match: "6EE1808846332B561426844981C370A0"' --data-binary @test.json http://example.org/fcrepo/rest/path/to/resource

Request failed due to unspecified failed precondition

It is unclear if this is a bug in how the ETags are generated or if I'm just not providing the correct Prefer header with the PUT request.
