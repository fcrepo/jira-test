FCREPO-615 With FeSL enabled, authentication is required for every resource

Description

When FeSL in enabled in the installer, the generated Fedora web.xml sets the AuthFilterJAAS with a wildcard url-pattern which requires authentication for every resource, even if APIA-Auth is not required.

For example, if you set API-A authentication to false (the installer default), but enable FeSL, requests to API-A resources such as http://localhost:8080/fedora/search still require authentication. Also, requests to resources such as http://localhost:8080/fedora/ri/index.xsl also require authentication.

Comments (4)

eddie, 2009-12-20 02:59 UTC

This is partly a bug in the installer, which creates the filter-mapping with a wildcard url-pattern regardless of install options. However, even if the installer is corrected to create individual filter-mappings for the various API-A/M servlets, there's still the problem of REST-API requests. That is, if API-A auth is false, then REST-API requests that map to API-A should not require authentication.

Notably, with the legacy authentication system, REST-API calls are differentiated via a special filter when API-A auth is false: fedora.server.security.servletfilters.FilterRestApiAuthn which explicitly checks for HTTP GETs and bypasses authN except for known API-M uri-patterns.

Seems like something similar would have to be done to AuthFilterJAAS. However, the workaround employed in FilterRestApiAuthn has the disadvantage that there's no way to further customize what requests should be allowed to pass without authentication. Moreover, there's the potential for authN settings for the SOAP API methods to get out of sync w/ the REST API methods.
