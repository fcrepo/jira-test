Description

This was found in the fcrepo4-vagrant setup. When audit is enable, there will be exceptions in the karaf log for the various indexing routes.

It appears that the baseURL is being set incorrectly for audit objects, so any routes that try to get information regarding those objects throw an exception.

I'm not clear on what's causing this, but the baseURL it's complaining about (fedora:info/) seems like it might be coming from the JMS messages that fedora emits for audit....?
