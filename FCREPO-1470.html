FCREPO-1470 non-LPDC LDPRSes as "pointlike objects"

ResolutionWon't Do

Created2015-04-15 16:38 UTC
Updated2021-09-17 17:37 UTC

Affects versionsFedora 4.1.1

Description

Fedora should respond to a request to create a non-LDPC LDPRS by creating such a resource as a "pointlike object", an object with no datastreams and no child objects. This created resource should support the correct LDP interaction model.

Comments (12)

Andrew Woods, 2015-04-15 16:41 UTC

Implied here is the fact that such an object "prevents" subsequent creation of child resources (datastreams or objects), correct?

A. Soroka, 2015-04-15 16:43 UTC

My understanding is that such behavior does arise from the choice of LDP interaction model, but it would be nice to hear that confirmed by people who understand those models better than do I. Robert Sanderson? Benjamin Armintor?

Benjamin Armintor, 2015-04-15 16:48 UTC

I think that you can't have contained resources and not be a Container, but whether that means that the interaction model needs to be explicitly added first seems an implementation decision outside the scope of the spec (Robert Sanderson?) RdfSource is a parent type of Container.

Benjamin Armintor, 2015-04-15 16:49 UTC

Though, just to clarify, I think we must require the RdfSource ixn model.

A. Soroka, 2015-04-15 17:04 UTC

Definitely the RdfSource ixn model. I'm a little confused by "whether that means that the interaction model needs to be explicitly added first seems an implementation decision outside the scope of the spec". How else would we provide for the "guard" against containment?

Robert Sanderson, 2015-04-15 18:10 UTC

The domain of ldp:contains is ldp:Container, so yes, if there is a contains relationship then the inference is that the subject is a container.
So yes, I think a non container prevents creation of child resources.

A. Soroka, 2015-04-15 18:14 UTC

Maybe this is JCR-enforceable?

Andrew Woods, 2015-04-15 18:25 UTC

The question of how the prevention of child resources is enforced boils down to the underlying implementation of this ticket. The requirement on "point-like objects" is that they support the LDPR interaction model:
http://www.w3.org/TR/ldp/#ldpc-post-createrdf

It seems that the implementation would follow the lines of proposal 3 in the wiki:
https://wiki.duraspace.org/display/FF/Design+-+Modeling+for+non-LDPC+objects#Design-Modelingfornon-LDPCobjects-Proposal3:LDPRsas"Pointlikeobjects"

A. Soroka, 2015-04-15 18:37 UTC

Sure. I'm not trying to forestall or foreordain any particular implementation. Just making notes.
