FCREPO-4045 API endpoint for validating OCFL object

TypeNew Feature
StatusReceived
PriorityHigh
ReporterBen Pennell
Created2025-12-04 15:36 UTC
Updated2025-12-04 15:36 UTC

Description

We currently provide an API endpoint for performing fixity checks of binaries, but there is not a way to validate other types of resources or the rest of the OCFL structure via the fedora API. Validating the OCFL structure has been left to other clients operating along side fedora.

Since ocfl-java already provides this functionality, and we use it during reindexing, it would potentially be straightforward to allow it to be called on demand. While we have avoided directly surfacing implementation details about storage to avoid lock in to a particular implementation, it does seem like a feature that is well suited for fedora so that it could be integrated into similar camel based workflows like the fixity check one.

The API for this would still need to be worked out. It does not necessarily need to state that it is OCFL related, it could be an endpoint like id/fcr:valid or id/fcr:validate and return a PREMIS formatted response along the lines of the fixity output https://wiki.lyrasis.org/display/FEDORA6x/RESTful+HTTP+API+-+Fixity, but more pass/fail plus whatever error message came back from the ocfl client.
