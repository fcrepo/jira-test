FCREPO-2638 Create new internal URI pattern

Description

To allow Mementos to display paths to the canonical version of children even if those resources are deleted we would like to create a new internal-prefix for those paths and necessary transformers to convert that prefix to a full URI without dereferencing the JCR Node (as it might be deleted).

This task is to create that internal prefix and create a transformer to convert a node at
some-prefix:/rest/foo/bar
to
http:// <some host and port> / <context path if applicable> /rest/foo/bar
for example

Possibly, the idea was that we need a way to create static URIs to objects in the repository but we still wanted to be able to change the baseURI of the server.

This task was to create some placeholder we could use when generating the internal static URIs and translate it when we send it out in a response.

Jared Whiklo, 2018-04-20 19:12 UTC

Having spent sometime with the HttpResourceConverter I am now thinking that we could just store the internal references as literal URIs, but without the baseUri stuff (http://localhost:8080/rest/ for example). Then we could just build the URI by passing that path to the normally configured UriInfo.baseUriBuilder and get a full URI.

Which is a long way of saying that maybe this could be dropped.
