Description

Given that an unrecognized default checksum algorithm is configured for a resource, a fixity operation returns with "BAD_CHECKSUM" but claims SHA-1 (which is the default) has been used. This might also happen whenever a valid checksum is configured as default (SHA-1, MD5, ...) but no appropriate digest has been calculated for the resource.

See also: https://jira.duraspace.org/browse/FCREPO-2297 and https://jira.duraspace.org/browse/FCREPO-2403

Andrew Woods, 2017-02-14 15:13 UTC

As you know, there are two flavors of fixity:

  1. On-ingest
  2. On-demand

The first is fairly well-aligned with the spec already. The on-demand implementation in the specification is slightly simpler than what we currently have.
I encourage you to be involved in the process for defining the "delta" between the current implementation and the spec: https://wiki.duraspace.org/display/FF/2017-02-10+Fedora+API+Adopters+Guide+Meeting
