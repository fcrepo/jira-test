Description

While inspecting the compiler warnings i stumbled over this in DOReaderCache.put(DOReader reader):

        String pid = null;
        try {
            pid = reader.GetObjectPID();
        } catch (Exception e) {
        }
        Long time = new Long(System.currentTimeMillis());
        List l = new ArrayList();
        l.add(reader);
        l.add(time);

later this list gets added to a Map m_readers, with the PID being the Key.

As you can see two different types (String, Long) get added to a List and type and semantics are dependent on the index in the list only. Although Lists are guaranteed to be ordered i imho consider this an anti-pattern since it makes lots of things more complex then they need to be. (e.g. Collections.sort()).
