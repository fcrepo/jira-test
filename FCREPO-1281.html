Description

The javax.ws.rs.core classes appear to be causing issues with OSGi loading of fcrepo-camel.

When a route tries to use the FcrepoClient, a class not found error is thrown, even though the class (apparently) has been loaded into the bundle.

Since Link header parsing is the only place where the Jersey classes are being used, one option would be to parse the headers manually (split on ";", remove leading and trailing <>, etc)
