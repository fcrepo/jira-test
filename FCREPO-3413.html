FCREPO-3413 Stacktrace in response: PATCH with unknown prefix

Description

This bug can be seen when trying to perform a PATCH request that includes the use of a RDF prefix that is undefined. The bug is that the body of the HTTP response to the client is an internal stacktrace. The fix should catch the exception, include a simple error message (e.g. "RDF was not parsable: [line: 1, col: 4 ] Unrecognized keyword: unknown"), and a 400 response code.

1. Create a resource
$ curl -i -XPUT -H"Content-Type: text/turtle" -H'Link: <http://www.w3.org/ns/ldp#BasicContainer>;rel="type"' --data-binary @body.ttl localhost:8080/rest/test0

  • Where @body.ttl is:
    ```
    <> <http://test.com#title> "A Title"
    ```

2. Verify the new resource includes the triple found in body.ttl
$ curl -i localhost:8080/rest/test0

3. Perform PATCH
$ 512 curl -i -XPATCH -H"Content-Type: application/sparql-update" --data-binary @update.su localhost:8080/rest/test0

  • Where @update.su is:
    ```
    DELETE { <> unknown:title "A Title"; }

    INSERT

    { <> unknown:title "new title"; }

    WHERE {
    }
    ```
