FCREPO-3359 Concurrent creation of objects fails in transactions

TypeBug
StatusOpen
PriorityMinor
ReporterBen Pennell
Created2020-06-26 20:09 UTC
Updated2020-06-30 19:55 UTC
Affects versionsFedora 4.7.5, Fedora 5.1.0

Description

Multiple requests attempting to create new objects in pairtrees where pairtree components share the same name can result in generating invalid pairtree names. For example, the following operations can produce the issue:

 

PUT http://localhost:8080/fcrepo/rest/base
start tx:1

PUT http://localhost:8080/fcrepo/rest/tx:1/base/path/to/myobj1

start tx:2

PUT http://localhost:8080/fcrepo/rest/tx:2/base/path/to/myobj2

commit tx:1 and tx:2

If the two commits are concurrent, then the result can be the following resources being created:

 

http://localhost:8080/fcrepo/rest/base/path/to/myobj1

http://localhost:8080/fcrepo/rest/base/path[2]/to/myobj2

The issue can be reproduced with the following integration test:

https://gist.github.com/bbpennel/c5684c114586c257e57e54bbfcb0ee0b

Attempting to perform modification operations on either myobj1 or myobj2 will produce variations on the following error (exact stacktrace depends on the operation):

You can produce similar outcomes with DELETE and MOVE operations, probably POST as well. Performing a GET directly against "path[2]" will throw an error if WebAC is turned on, due to an encoding issue with the brackets.

Note: the basic container "base" (or "d61a4b67-fe3d-4807-b03a-cc121234b877" in the example above) was not necessary to produce the sibling count indexed pair trees. However, if I placed the pair tree at the root of the repository, no exceptions were thrown when performing operations on objects in the pair tree.

This is the same issue as https://jira.lyrasis.org/browse/FCREPO-2086 where the resolution explicitly does not cover transactions.

Ben Pennell, 2020-06-26 22:27 UTC

While objects like this can be difficult to deal with, it does seem that if you perform a MOVE directly against indexed pair tree nodes you can rename them to something without the index, and then interact with the path. For example:

curl -X MOVE -H "Destination: http://localhost:8181/fcrepo/rest/deposits/a9_2" "http://localhost:8181/fcrepo/rest/deposits/a9%5B2%5D"

Succeeds but sometimes returns the message "There is no node that will serve as the parent of the moved item". You can then move anything contained within that path to the correct path. If WebAC is enabled, then it may require encoding the characters here (this breaks some tests):

https://github.com/fcrepo4/fcrepo4/blob/fcrepo-5.1.0/fcrepo-auth-webac/src/main/java/org/fcrepo/auth/webac/WebACFilter.java#L190

String requestUrl = httpRequest.getRequestURL().toString();
requestUrl = requestUrl.replace("[", "%5B").replace("]", "%5D");

As otherwise URI.create will fail on unencoded []s.
