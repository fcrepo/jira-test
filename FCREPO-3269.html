Description

The default triples from Fedora 5.1.0 for a binary are

<http://localhost:8080/rest/binary1>
    rdf:type fedora:Binary ;
    rdf:type fedora:Resource ;
    fedora:lastModifiedBy "bypassAdmin" ;
    premis:hasSize "17"^^<http://www.w3.org/2001/XMLSchema#long> ;
    ebucore:hasMimeType "text/plain" ;
    fedora:createdBy "bypassAdmin" ;
    fedora:created "2020-04-02T16:21:49.406Z"^^<http://www.w3.org/2001/XMLSchema#dateTime> ;
    fedora:lastModified "2020-04-02T16:21:49.406Z"^^<http://www.w3.org/2001/XMLSchema#dateTime> ;
    premis:hasMessageDigest <urn:sha1:482cb0cfcbed6740a2bcb659c9ccc22a4d27b369> ;
    ebucore:filename "" ;
    rdf:type ldp:NonRDFSource ;
    iana:describedby <http://localhost:8080/rest/binary1/fcr:metadata> ;
    fedora:hasFixityService <http://localhost:8080/rest/binary1/fcr:fixity> .

 

Some of these triples probably are not needed or can be a different syntax.

For example iana:describedby is now a header and not needed. Also in Fedora 5 we had to restrict the updating of the ebucore:hasMimetype as it was necessary to allow us to serve the binary (https://jira.duraspace.org/browse/FCREPO-2520). I would recommend that we store the incoming mimetype under a server managed property so user RDF changes don't need to be vetted and we can still serve the binary.
