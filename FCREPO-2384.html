Description

This task is to add the AppleTree capability into Fedora's id-translation chain as an option that by default is NOT enabled.
The reason it should not be enabled by default is because it should only be used on new repositories... not repositories that have existing content.

See:

  • https://gitlab.amherst.edu/acdc/acrepo-apple-trees/blob/c79ed5788420d428c70029450dfe6b62e421a777/src/main/java/edu/amherst/acdc/orchard/AppleTreeConverter.java

Andrew Woods, 2017-01-19 21:41 UTC

Clojure and Gradle are fine. The immediate reason for bringing the project into the Fedora fold is to resolve the dependency clash issue; specifically, we would want to release SNAPSHOT artifacts of the AppleTree to the Sonatype snapshot repository and update the project version number to be aligned with Fedora's version: 4.8.0-SNAPSHOT:
https://github.com/acoburn/acrepo-apple-trees/blob/master/build.gradle#L35

In this case, the implication would be that we integrate the AppleTree into fcrepo-webapp-plus instead of the core code due to the fact that we do not allow the core code to depend on fcrepo4-exts dependencies.

The alternatives are to either bring the single functional and single test classes into an existing core module (fcrepo-kernel-api?) or as its own core maven module.
