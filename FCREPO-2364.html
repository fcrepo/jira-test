Description

This is related to FCREPO-2323: https://jira.duraspace.org/browse/FCREPO-2323?focusedCommentId=53282&page=com.atlassian.jira.plugin.system.issuetabpanels:comment-tabpanel#comment-53282

We use httpd (apache) to reverse proxy tomcat. This entails adding a value for the proxyName attribute in Tomcat's server.xml config file:

<Connector port="8080" protocol="HTTP/1.1"
connectionTimeout="20000"
proxyName="server.artic.edu"

If I load content via the proxy and link resource 'a' to another ('b'), and then delete the linked resource ('b'), which should remove the relationship from 'a', everything works as expected.

If, however, I load content using 'localhost:8080,' the link from resource 'a' to resource 'b' remains even after I delete resource 'b'.

The question is whether this is by design (i.e. how tomcat operates when using a proxy) or if it indicates a bug in fcrepo.

Two gists may help to describe the above. Each gist replicates the code used to test this and the resulting output.

The first shows the problem when using 'localhost': https://gist.github.com/kefo/7a8d92ee4e1f7d52639436d299e5a718

The second shows the result when using the proxyName: https://gist.github.com/kefo/d9554f73ce9e47d1975d8b3862242ecf
