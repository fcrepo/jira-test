Michael Durbin, 2016-09-05 18:08 UTC

The camel serialization module exports the RDF from the "resource" at the described-by header to a filename based on the URL of the described resource. ("/test/fcr:metadata" --> test.ttl) This implies the assumption that fedora will only ever have one describes/describesBy link per binary. The currently implemented approach serializes "fcr:metadata" in a folder named after the binary.

I would advocate (and will soon issue a PR to the effect) that we follow the camel convention for the following reasons:
1. Including fcr:metadata in our serialization format ties us to that contentious and ugly hack and its naming convention. (I think the assumption that we'll have only one describes/describedBy link will holder longer and between implementations better than the use of the constant "fcr:metadata")
2. Mapping LDP containers to directories seems more logical... having our only non-container resources (binaries) actually result in a directory in the RDF export is non-intuative.
3. Maintaining compatibility between the serializer and export as long as possible seems ideal.
