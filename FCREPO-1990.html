Description

This task is to create a standalone utility that can take the output of fcrepo-serialization [1] and load those resources (rdf and non-rdf) into an initially empty repository.

Special attention will need to be paid to the handling of server-managed triples and properties generated by Direct and Indirect container interaction models.

[1] https://github.com/fcrepo4-exts/fcrepo-camel-toolbox/tree/master/fcrepo-serialization

Joshua Allan Westgard, 2016-05-02 14:45 UTC

A first 'draft' of a script is available at https://github.com/jwestgard/fcrepo-serial-restore. The approach is the following:

  1. Read YAML configuration file to get the rest endpoint and backup locations, server credentials, and namespaces to filter;
  2. Iterate over the serialized backup tree, reading each turtle file and (after filtering out server managed triples) PUTting the turtle to the resource location represented by the corresponding directory path.

Currently, my local fedora is returning a 403 response, I'm guessing because I haven't filtered out some triples that Fedora doesn't want me to be setting. I'll keep working on it, but comments and advice welcomed!

ADDITIONAL FEATURES:

  1. Add the uploading of binaries;
  2. Support other serializations besides turtle;
  3. Add configurable levels of logging to record the requests made and the server's responses;
  4. Add support for resumability? I don't know how difficult this will prove to be, but it seems like it could be important for large repositories.

Andrew Woods, 2016-06-06 21:28 UTC

Joshua Allan Westgard, I am not sure if you are still working on this, but here are the results of running a simple test:

  1. Start the karaf/camel/fcrepo-serialization service (by default it stores resources at '/tmp/descriptions')
  2. Start an empty fcrepo
  3. Run 
    for x in {0..100}; do echo $x; curl -XPUT localhost:8080/rest/container${x}; done

    ..followed by

    for x in {0..100}; do echo $x; sed -e "s/XXXX/${x}/" dc-title.ru | curl -XPATCH -H"Content-Type: application/sparql-update" --upload-file - localhost:8080/rest/container${x}; done

    ..where "dc-title.ru" is:

    PREFIX dc: <http://purl.org/dc/elements/1.1/>

INSERT {
  <> dc:title "Some Title-XXXX"
} WHERE {}
    • This creates 100 containers with a dc:title property set.
  4. Save then clear the contents of the stored '/tmp/descriptions/'
  5. Start an empty fcrepo again (stop, clear the contents, and restart fcrepo)
  6. In the fcrepo-serial-restore project, update the config.yml as appropriate
  7. Run: 
    ./restore.py -c config.yml
  8. Compare the contents of the newly create contents of '/tmp/descriptions' with the original contents of that directory
    • The resources are named with the .ttl extension
    • The dc:title properties are gone
    • The original "fedora:created" and "fedora:lastModified" properties are not retained under some other property
