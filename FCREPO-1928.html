Esmé Cowles, 2016-03-03 16:21 UTC

If you send this Prefer header, then it won't complain if the server-managed triples are omitted:

Prefer: handling=lenient; received="minimal"

I can confirm that this works with a current master build of fcrepo4.

Andrew Woods, 2016-09-01 03:05 UTC

scossu, It was a simple experiment to create a PR that sets the default 'Prefer' header on PUT requests to handling=lenient; received="minimal". The resultant situation is exactly symmetrical to the current state.
Currently, you get a 409 response if you have not set Prefer: handling=lenient; received="minimal" on PUT requests that contain bodies WITHOUT server-managed triples.
Changing the default on PUT requests to Prefer: handling=lenient; received="minimal", would result in a 409 response for PUT requests that contain bodies WITH server-managed triples.

The current state supports the non-normative description in: https://www.w3.org/TR/ldp/#h-ldprs-put-servermanagedprops
The changed state would support the MAY of: https://www.w3.org/TR/ldp/#h-ldpr-put-replaceall

With an informed use of headers, the current state can support clients that wish to make PUT requests with either minimal or full RDF bodies.
In the changed state, it is not clear how full RDF body requests would be supported.

I would recommend we keep the state of Fedora as-is... but it has been added to the agenda: https://wiki.duraspace.org/display/FF/2016-09-01+-+Fedora+Tech+Meeting

Andrew Woods, 2016-09-08 22:54 UTC

scossu, we discussed this ticket on today's tech call:
https://wiki.duraspace.org/display/FF/2016-09-08+-+Fedora+Tech+Meeting

The consensus was that Fedora's current behavior complies with both HTTP's expectations the idempotency of PUT, as well as LDP's expectations around PUT requests.

Regarding: https://www.w3.org/TR/ldp/#h-ldpr-put-replaceall

  • This is a MAY clause that is not supported by Fedora

Regarding: https://www.w3.org/TR/ldp/#h-ldprs-put-servermanagedprops , and specifically the non-normative note:

  • Fedora supports exactly this model.

As you have already noted in this ticket, although the behavior you request is not Fedora's default interaction, it is available with the use of Prefer: handling=lenient; received="minimal".

On a related note, if Fedora were to change per this ticket, it would be logically necessary to change the behavior on GET to return user-triples only.

In discussing this topic on today's tech call, it was speculated that your use case is more in line with PATCH usage than PUT... and if so, you may be driven towards PUT due to the cumbersomeness of the SPARQL-Update syntax. But that is speculation.

For now, I am closing this ticket as Won't Fix, but please feel free to reopen it if you believe we are missing something in your request.
