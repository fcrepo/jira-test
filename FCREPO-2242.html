It would be nice if someone from the performance and scale group could evaluate this change w/r/t memory use of accessing large containers (containers w/ large numbers of triples). Especially for ntriples or turtle-based output.

RDFXML-, JSON-LD- and N3-based output is not streamed.

The useful performance tests would be scoped to repeated GET requests on large containers (i.e. resources w/ many triples):
1. For the following serializations (n-triples, rdf/xml, turtle, json-ld):
a) what is the avg time to first byte
b) what is the avg resource response time
2. Same as #1 but with some configurable level of concurrency (e.g. 10 - 20)
