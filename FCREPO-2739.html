FCREPO-2739 Server returns an error after inserting a particular triple syntax

TypeBug
StatusOpen
PriorityMajor
Reporterscossu
Created2018-03-18 02:24 UTC
Updated2018-03-20 01:27 UTC
Componentsf4-core
Affects versionsFedora 4.7.4, Fedora 4.7.5

Environment

Linux, Java 1.8

Description

Inserting an apparently innocuous triple such as:

curl -iXPUT --data-binary '<> <http://ex.org/p#123> <http://ex.org/res/abc> .' -H'Content-type:text/turtle' http://localhost:8080/rest/test_blowup

Returns an apparently successful response:

HTTP/1.1 201 Created
Date: Sun, 18 Mar 2018 02:14:17 GMT
ETag: W/"f2be3bf3552ed0f662c36cfe2f320c003d80fea0"
Last-Modified: Sun, 18 Mar 2018 02:14:17 GMT
Location: http://localhost:8080/rest/test_blowup
Content-Type: text/plain
Content-Length: 40
Server: Jetty(9.2.3.v20140905)

http://localhost:8080/rest/test_blowup

But on GET, the server returns a 500 error:

java.lang.IllegalArgumentException: The localName argument may not be null or zero-length
at org.modeshape.common.util.CheckArg.isNotZeroLength(CheckArg.java:360)
at org.modeshape.common.util.CheckArg.isNotEmpty(CheckArg.java:373)
at org.modeshape.jcr.value.basic.NameValueFactory.create(NameValueFactory.java:175)
at org.modeshape.jcr.value.basic.NameValueFactory.create(NameValueFactory.java:168)
at org.modeshape.jcr.cache.document.DocumentTranslator.getProperties(DocumentTranslator.java:245)
at org.modeshape.jcr.cache.document.LazyCachedNode.getProperties(LazyCachedNode.java:425)
at org.modeshape.jcr.AbstractJcrNode.getProperties(AbstractJcrNode.java:2073)
[...]

The culprit seems to be the numeral in the predicate after the `#` sign. Whether that may be legal syntax or not (it seems to me, and other ttl parsers accept it), the aggravating factor is that the resource is created but unusable in any way (including DELETE). The server should instead return an error before persisting the content if it has a problem with it.
