It is not possible to use multiple instances of fcrepo-camel.

This problem/enhancement was anticipated when this feature was originally proposed.

Unknown, 2016-11-16 18:02 UTC

The conversation in FCREPO-2088 Closed is somewhat orthogonal to this, but once fcrepo-camel 4.5.0 is released, it will be completely moot. By way of explanation, the current camel infrastructure uses JMS headers that consist of an identifier and a baseUrl. By assembling these, a Fedora URL can be constructed for a resource. And mostly, the baseURL is assumed to be equivalent to the fcrepo-camel endpoint URI. With fcrepo-camel 4.5.0 that structure will still be supported, but users will be encouraged to make use of a single URI. This is all in line with the draft messaging specification. As such, a single route can access any number of Fedora instances like so:

from("activemq:queue:fedora").routeId("FedoraRouter")
    .process(new EventProcessor())
    .choose()
        .when(header(FCREPO_URI).startsWith("http://test-repo.example.org"))
            .to("direct:test-stuff")
        .when(header(FCREPO_URI).startsWith("http://dev-repo.example.org"))
            .to("direct:dev-stuff")
        .when(header(FCREPO_URI).startsWith("http://repo.example.org"))
            .to("direct:production-stuff");

from("direct:test-stuff")
    .filter(not(header(FCREPO_EVENT_TYPE).contains(DELETED)))
        .to("fcrepo:localhost?authUsername=testUser&authPassword=testPass")
        .to("direct:something-else");

from("direct:production-stuff")
    .filter(not(header(FCREPO_EVENT_TYPE).contains(DELETED)))
        .to("fcrepo:localhost?authUsername=productionUser&authPassword=productionPass")
        .to("direct:something-else");
