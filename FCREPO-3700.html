Description

While trying to determine if Fedora supported unicode in binary filenames, I have seen some inconsistent behaviors. This applies to fedora 5 and 6.

Putting some chinese characters directly in as the filename gives good results in the response Content-Disposition, but not the binary description:

curl -H'Link: <http://www.w3.org/ns/ldp#NonRDFSource>; rel="type"' --data-binary @README.md -H'Content-Disposition: attachment; filename="浅顶软呢帽岩石"' -H"Content-type: text/plain" -XPOST http://localhost:8080/rest/ -ufedoraAdmin:fedoraAdmin

curl -I http://localhost:8080/rest/90703ac5-191e-48d8-84a9-17300e490520 -ufedoraAdmin:fedoraAdmin

# Content-Disposition: attachment; filename="浅顶软呢帽岩石"; creation-date="Thu, 15 Apr 2021 21:00:28 GMT"; modification-date="Thu, 15 Apr 2021 21:00:28 GMT"; size=4719

curl http://localhost:8080/rest/90703ac5-191e-48d8-84a9-17300e490520/fcr:metadata -ufedoraAdmin:fedoraAdmin

You are supposed to be able to define the encoding of the filename using "Content-Disposition: attachment; filename*=UTF-8..." form (note, it is filename* rather than filename), but this is simply ignored by fedora. In FedoraLdp it actually parses within the contentDisposition object, but the filename* value is stored as a parameter instead of as the filename, so its not found by the controller code.

curl -H'Link: <http://www.w3.org/ns/ldp#NonRDFSource>; rel="type"' --data-binary @README.md -H"Content-Disposition: attachment; filename*=UTF-8''%e6%b5%85%e9%a1%b6%e8%bd%af%e5%91%a2%e5%b8%bd%e5%b2%a9%e7%9f%b3" -H"Content-type: text/plain" -XPOST http://localhost:8080/rest/ -ufedoraAdmin:fedoraAdmin
