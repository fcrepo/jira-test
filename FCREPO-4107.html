FCREPO-4107 Extend On-Behalf-Of functionality

TypeImprovement
StatusOpen
PriorityHigh
ReporterRastislav Hudak
Created2026-09-11 08:10 UTC
Updated2026-09-21 11:30 UTC

Description

When a username is sent in the On-Behalf-Of header to Fedora, it will be used in WebAC authentication. We believe that it should also be used to update the fedora: createdBy and fedora: lastModifiedBy triples (the UpstreamAuth feature in Fedora 3.3+ did this too). This enables applications which implement their own authn/authz and are talking to Fedora via admin account to transparently act on behalf of the upstream user, which is important for audit purposes.

David Novák, 2026-09-21 10:11 UTC

I am slightly reserved this would be a desired behaviour, as the Fedora should keep the persistent audit log of the actual account driving any write operation. With this change, doors would be opened for silent operations which would never be properly attributed unless digging in the system log.

For example in our running instance, we solve this by storing the original identity in a dcterm:creator property of the metadata record of the container. This does not collide with the native provenance record, but keeps the data as needed.

Rastislav Hudak, 2026-09-21 11:30 UTC

David Novák Yes that’s fair. But if Fedora already accepts On-Behalf-Of and uses it in authorization, it would make sense to also emit a provenance triple for it. Leaving this to clients is duplication and creates inconsistency. Since using fedora:createdBy/fedora:lastModifiedBy would mask the actual account, using another triple would be fine for us too. Jared Whiklo would that be an alternative?
