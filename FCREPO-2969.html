Description

I am unable to add rdf:type properties to binary descriptions. When doing so, fcrepo returns a 204 but no new property appears when making a GET to the description.

You can see this behavior in the following failing integration test:

https://github.com/fcrepo4/fcrepo4/compare/5.0.0-RC...bbpennel:add-type-to-binary

As well as from the UI by bringing up the fcrepo 5 web console, creating a binary, then pasting the following into the update properties box:

INSERT {
 <> <http://www.w3.org/1999/02/22-rdf-syntax-ns#type> <http://pcdm.org/models#File> .
}
WHERE {}

It returns with no error, but the property does not appear.

Meanwhile the following update works and the new relationship appears:

INSERT {
 <> <http://example.com/link> <http://example.com/goodstuff> .
}
WHERE {}

Danny Bernstein, 2018-12-17 14:17 UTC

So I looked into this problem over the weekend.  The issue seems to be that the inserted triple lands on the binary jcr node rather than the binary description.  It is a very simple fix to simply merge any rdf:type properties on the jcr binary node with those on the jcr binary description node.   It is not clear to me what, in any, implications there would be to try to get the rdf:type properties to land on the binary description jcr node.

Ben Pennell, 2018-12-17 15:42 UTC

Danny Bernstein I had the feeling it might end up being something along those lines. Generally, it seems more appropriate to me that the rdf:types would land on the description node.

The one caveat coming to mind is the Link rel="type" header, would it make sense for a HEAD request against the binary to return the rdf:types added to the description? Maybe so, if we were returning all rdf:types as described in https://jira.duraspace.org/browse/FCREPO-2968
