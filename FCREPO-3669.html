Description

As discussed here (https://github.com/OCFL/spec/issues/528), OCFL should be operated on a case sensitive filesystem. Windows and Mac's filesystems are by default case insensitive, though it is perhaps possible to make them case sensitive.

Case is only an issue for Fedora when it comes to archival groups. If you have an archival group that contains two different resources with names that only differ in case, then the resources will clobber each other on case insensitive filesystems.

At the minimum, we should document this fact and encourage Windows/Mac users to make their filesystem support case sensitivity, or avoid creating AGs that contain resources that aggravate the casing issue.
