FCREPO-1148 Inconsistent error response on purgeDatastream with malformed dateTime

Description

Issuing a purgeDatastream request with a malformed startDT (e.g. "1999") results in a 500 error when using FeSL AuthZ but a 400 error when using the legacy AuthZ.

With the legacy AuthZ, DateUtility returns an IllegalArgumentException, which is eventually translated into a 400 (Bad request; unable to fulfill REST API request), e.g.:

INFO 2012-08-30 16:25:56.150 [http-8080-1] (DefaultManagement) Completed getDatastream(pid: test-rest:1, datastreamID: testMalformedDates, asOfDateTime: null)
WARN 2012-08-30 16:25:56.176 [http-8080-6] (BaseRestResource) Bad request; unable to fulfill REST API request
java.lang.IllegalArgumentException: Unparseable date: "1999"
at org.fcrepo.utilities.DateUtility.parseDateOrNull(DateUtility.java:210) ~[fcrepo-common-3.6.1-SNAPSHOT.jar:na]
at org.fcrepo.server.rest.DatastreamResource.deleteDatastream(DatastreamResource.java:286) ~[fcrepo-server-3.6.1-SNAPSHOT.jar:na]

However, with FeSL AuthZ, the date parsing is done by the xacml library which results in a ParseException that eventually translates into in a 500, e.g.:

INFO 2012-08-30 16:41:07.482 [http-8080-6] (DefaultManagement) Completed getDatastream(pid: test-rest:1, datastreamID: testMalformedDates, asOfDateTime: null)
ERROR 2012-08-30 16:41:07.501 [http-8080-7] (PurgeDatastream)
java.text.ParseException:
at com.sun.xacml.attr.DateTimeAttribute.strictParse(DateTimeAttribute.java:413) ~[sunxacml-1.2-melcoe.jar:na]
at com.sun.xacml.attr.DateTimeAttribute.getInstance(DateTimeAttribute.java:379) ~[sunxacml-1.2-melcoe.jar:na]
at org.fcrepo.server.security.xacml.pep.rest.objectshandlers.PurgeDatastream.handleRequest(PurgeDatastream.java:108) ~[fcrepo-security-pep-3.6.1-SNAPSHOT.jar:na]
at org.fcrepo.server.security.xacml.pep.rest.PEP.doFilter(PEP.java:160) [fcrepo-security-pep-3.6.1-SNAPSHOT.jar:na]

We need to decide what is the appropriate response here and then be consistent about it.
