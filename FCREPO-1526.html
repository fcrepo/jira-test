FCREPO-1526 NonRDFSources (or their description) should be able to have child containers

TypeStory
StatusClosed
ResolutionWon't Fix
PriorityMinor
ReporterTrey Pendragon
Created2015-05-07 19:51 UTC
Updated2015-05-29 19:07 UTC
Resolved2015-05-15 14:13 UTC
Componentsf4-core
Affects versionsFedora 4.2.0

Description

NonRDFSources should be allowed to have children, either directly underneath the NonRDFSource, or under its description (fcr:metadata). This would allow for the associating files with other files that are not directly linked to the parent container (e.g., a FITS XML description of a file is related to the file, not to the parent container directly).

Benjamin Armintor, 2015-05-29 15:36 UTC

There's no child/parent nomenclature in the LDP spec, and we should avoid falling back on it so as to clarify our design intentions. There are Containers and contained Resources. NonRDFSources and RDFSource are distinct subclasses of Resource, and RDFSource is the superclass of LDPContainer. Suggesting that NonRDFSources could be containers is a Liskov problem.

I think what this ticket intends is that the RDFSource describing a NonRDFSource be able to be a container. Robert Sanderson discussed this as a possibility when we started talking about the fixity redesign, but I agree that it's something that should be considered carefully.

Robert Sanderson, 2015-05-29 18:59 UTC

Sorry, I got half way through typing a response and was called away.

  • The LDP specification simply says that if there is a description of a non RDF Source (LDP-NR), then it must be referenced from the LDP-NR using a describedBy link header, and servers may create them when the LDP-NR is created, and that description is in RDF.

The LDP spec does not say that all of the subjects of triples in the describing RDF have to be the LDP-NR, and it doesn't say where the resource gets created relative to the LDP-NR. Fedora's implementation then adds these.

  • LDP doesn't say anything about URI patterns other than for Containers / Contained resources. It seems orthogonal to the description requirement as to where the resources are maintained that do the describing. The current fcr:metadata pattern is thus compatible, but as Benjamin Armintor says, NonRDFSources cannot also be ldp Containers and we should certainly not think of them in that way.

An alternative pattern might be to reserve a _fcr:metadataContainer suffix (or similar) and create an initial metadata RDF Source in it.

I think the use case for LDP-NR that happens to be in RDF is when there's arbitrary datasets that are being managed as if they were files. Imagine someone submitting their ontology along with their dissertation. We would need a very different platform to sustain that resource as intended.

A. Soroka, 2015-05-29 19:05 UTC

I certainly didn't mean to suggest that having the constraint on the subjects of triples comes from LDP. It comes from the fact that Fedora is an object repository, which is just as important a guide to behavior as LDP.
