Analysis:
It seems that the class responsible for the redundant selects during the ingest is the ResourceAttributeFinder. It tries to resolve the attribute ids urn:fedora:names:fedora:2.1:resource:datastream:state and urn:fedora:names:fedora:2.1:resource:object:state. The ResourceAttributeFinder then delegates the work of finding the object/datastream to DefaultLowlevelStorage.Store where a database select query against the given PID is executed.

Solution:
As the PDP invokes each of these operations independently, caching seems to be inappropiate in the ResourceAttributeFinder. Even introducing caching at the storage level could result in unwanted side effects like stale data. The only viable approach therefore seems to be to modify the authorization module so that in the case of an ingest of a new digital object the state of objects and datastreams will not be checked since they don't exist at this point anyway (or if they exist, the lowlevel storage will complain). In the light of the upcoming redesign of the Fedora security architecture it is questionable if this (very minor) issue is worth the effort as it would probably involve a substantial change in the existing code.
