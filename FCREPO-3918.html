Description

Currently fcrepo Docker image is built in 2 pipelines:

  1. The pipeline of fcrepo whenever a new releases has been created.
  2. The pipeline of fcrepo-docker (either triggered manually or by a commit to main or automatically based on a weekly schedule)

While researching for a solution for https://fedora-repository.atlassian.net/browse/FCREPO-3913 I found a few interesting approaches that could simplify the current solution.

Main goals:

  1. Only build fcrepo Docker image in pipeline of fcrepo-docker
  2. Don’t check out and build fcrepo when building the Docker image
  3. Automatically detect the latest releases.

For now this ticket is here as way for me to document the approaches. Resources:

  • Trigger pipeline from another repository:
    • https://blog.marcnuri.com/triggering-github-actions-across-different-repositories
    • https://stackoverflow.com/questions/74775432/trigger-another-repo-in-github-actions
  • Get latest release of fcrepo from Github releases with Bash/curl:
    • https://fabianlee.org/2021/02/16/bash-determining-latest-github-release-tag-and-version/ (corresponding releases API: https://docs.github.com/en/rest/releases/releases?apiVersion=2022-11-28#get-the-latest-release)
    • query available tags via Github API: https://docs.github.com/en/rest/git/refs?apiVersion=2022-11-28#list-matching-references

Get releases from Github via API:

curl --silent "https://api.github.com/repos/fcrepo-exts/fcrepo-camel-toolbox/releases"

Get latest release:

curl --silent "https://api.github.com/repos/fcrepo-exts/fcrepo-camel-toolbox/releases/latest"

Extract tag name:

curl --silent "https://api.github.com/repos/fcrepo-exts/fcrepo-camel-toolbox/releases/latest" | jq ".tag_name"

Extract release number from tag name:

curl --silent "https://api.github.com/repos/REPO/releases/latest" \\
| jq ".tag_name" \\
| sed -E 's/^"TAG_PREFIX-(.+)"$/\1/'
