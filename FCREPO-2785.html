Description

This ticket is to determine the best path forward to deprecating the use of the Modeshape Namespace registry.

This could mean returning full URIs in all responses or replacing it with some other option.

Once a path is determined then this ticket can move to implement it.

Ben Pennell, 2018-10-01 19:03 UTC

My understanding currently is:

  • to store info about a node in modeshape, you have to store it in jcr properties.
  • properties are identified with prefixed paths (i.e., fedora:lastModifiedBy).
  • The prefix must be in modeshapes baked-in namespace registry
  • We want to store full URIs for properties and control the prefixes outside of modeshape
  • modeshape won't accept a property named "http://example.com/property" because "http" is not a known prefix.

So unless there is a way to store info in modeshape that I’m not seeing in its API, it seems like three options are:

  1. Prefix predicate URIs prior to persistence, then have jena handle namespacing from a configuration file. For example, modeshape stores a predicate named “pred:http:%2F%2Fexample.com%2Fproperty”
  2. Leave modeshape’s namespace registry alone. Change the serialization of triples to translate out of modeshape prefixes into full urls, then switch to prefixes from the provided configuration.
  3. Leave modeshape’s namespace registry alone. When serializing triples return full URIs.

I don't think any of these approaches has any impact on POST/PATCH/PUT requests, since the prefixes there are handled internally by jena and received by fedora as URIs.
