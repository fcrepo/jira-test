Description

Error purging object demo:998, underlying Exception:

Caused by: java.io.IOException: Failed to delete file:

D:\Fedora34\fedora\data\datastreamStore\61\info%3Afedora%2Fdemo%3A998%2FDS1%2FDS1.0
at org.akubraproject.fs.FSBlob.delete(FSBlob.java:129) [akubra-fs-0.3.jar:na]
at org.akubraproject.impl.BlobWrapper.delete(BlobWrapper.java:117) [akubra-core-0.3.jar:na]
at org.fcrepo.server.storage.lowlevel.akubra.AkubraLowlevelStorage.delete(AkubraLowlevelStorage.java:456)

On closer inspection, this is due to an InputStream not being closed in:
org.fcrepo.server.storage.translation.AtomDOSerializer.setManagedContent(Entry entry, Datastream vds), line 418:

IOUtils.copy(vds.getContentStream(), m_zout);

Replacing with the following resolves the issue:

InputStream is = vds.getContentStream();
IOUtils.copy(is, m_zout);
is.close();

From http://commons.apache.org/io/api-release/org/apache/commons/io/IOUtils.html:

"Wherever possible, the methods in this class do not flush or close the stream. This is to avoid making non-portable assumptions about the streams' origin and further use. Thus the caller is still responsible for closing streams after use. "

Given this, might be worth a bit of a general code trawl-through for other instances of IOUtils to ensure streams are closed correctly where they should be.

(I'm pretty sure I have used IOUtils.copy() without thinking about closing streams afterwards. And this might explain why I end up with so many temp files that are not deleted).

Curious as to why this was not an issue with the legacy low-level storage implementation.
