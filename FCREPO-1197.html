asconrad, 2013-07-25 19:28 UTC

As a colleague of James I have done further research.

The FOXML file that is being ingested, sifd_1058.xml, has been generated by fedora-export.sh from another Fedora repository. The problem seems to be the last datastream definition in that that file:

<foxml:datastream CONTROL_GROUP="M" ID="provenanceMetadata" STATE="A" VERSIONABLE="true">
<foxml:datastreamVersion CREATED="2013-07-17T08:29:40.294Z" ID="provenanceMetadata.0" LABEL="" MIMETYPE="text/xml" SIZE="53">
<foxml:contentLocation
REF="http://localhost:8080/fedora/get/sifd:1058/provenanceMetadata/2013-07-17T08:29:40.294Z" TYPE="INTERNAL_ID"/>
</foxml:datastreamVersion>
</foxml:datastream>

The problem is the "REF" statement as the fedora-import command seems to try to execute that "get" before the object has actually been created. Import works by removing the datastream in question (CONTROL_GROUP="M") from the FOXML file. Probably not a good idea, though...

I am not a Fedora export so it is hard to assess whether this is a bug, or rather a consequence of our data model.

Benjamin Armintor, 2013-07-26 01:13 UTC

If the original repository is configured as localhost, the exported objects will not be useful to repositories running on other machines. You can configure an actual hostname for your repository in either the fedora.fcfg file (for pre-3.6 installations) or the WEB-INF/applicationContext.xml file (in 3.6 installations).
