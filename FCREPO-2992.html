FCREPO-2992 Document headers needed to be captured for import-export

TypeNew Feature

PriorityMinor

Description

This ticket is document the information stored in a resource that is exposed as headers but does need to be persisted in the import-export process.

An examples is the version information via the /fcr:versions Link header.

This could be documented here, or in some other import-export design page.

List of Headers:

All resources: 

Content-Type:  what are we doing now? Relying on the extension of the exported file?

For mementos

Memento-Datetime:  can be derived from the resource URL but might be more convenient?

 

External Content:

Location: means redirect

**Content-Location (no location header):  means proxy

Web ACLS: 

Link: <...>; rel="acl"

TimeMaps:

None

<resource path>.external - contains contents if binaries are exported. Otherwise, the file should not be present.  Empty file indicates 0 length binary resource.

<resource path>.headers - contains headers
