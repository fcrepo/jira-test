FCREPO-3197 Enhance migration-utils to add XML declaration for migrated in-line XML

Description

In-line XML datastreams migrated from Fedora 3 to OCFL do not contain an XML declaration. This declaration is is optional in XML 1.0, but common practice.  It is mandatory in XML 1.1. 

Please consider adding a declaration such as:

<?xml version="1.0" encoding="UTF-8"?>

Inline XML content in FOXML has a "SIZE" attribute. Are you ok with the resultant XML document having a different size than the source? Do you have thoughts on validation of migrated inline XML?

Scott Prater has observed that migration-utils changes the order of some inline XML attributes. See: https://jira.lyrasis.org/browse/FCREPO-3145

I am trying to get a better sense of the requirements for migrated inline XML. There is an argument that the purest migration would be a byte-for-byte copy of what is found inline. Any difference in the output from a byte-for-byte copy represents a slightly new datastream. What variance is acceptable (or even desired) from a byte-for-byte copy?

Doron Shalvi, 2020-02-06 17:25 UTC

As Scott Prater observes in FCREPO-3145 Closed I think the primary question is:  which should be considered the canonical version of the inline XML datastream?  The version stored on disk, or the version delivered by Fedora through its API?  From a systems perspective, I would tend to lean towards the latter, since I shouldn't have to know the internals of a system when performing an export/migration.  From a practical perspective the migration tool uses the stored FOXML, and most people migrating from F3 are probably familiar with stored FOXML, so this may not be a huge consideration.

In our situation I am not too concerned about the resultant XML document having a different size than the source "SIZE" attribute, since we use in-line XML primarily for metadata that will likely be reprocessed into another format during our migration anyway.  A possible workflow for validating migrated inline XML data for a given version of a given datastream could be:

  1. Migrate a byte-for-byte copy.
  2. Validate the migrated copy using the "SIZE" attribute and using an XML validator.
  3. (Optionally) Modify the migrated copy by adding an XML declaration.  Recompute size.  Store the modified copy and new size in place of the migrated copy.

Possibly, this could be another runtime command line option.

I'm not too vested in this particular request, partially because the migrated XML is still valid without a declaration.   I defer to those who are more concerned about preservation of in-line XML, with respect to the original question of which version is canonical.  I would note, however, that to some degree this is a general question that has come up a few times ( FCREPO-3198 Closed , FCREPO-3145 Closed ) - should the migration tool migrate exactly what Fedora 3 has stored, or should it account for runtime transformations represented by Fedora 3 code in serving the API?
