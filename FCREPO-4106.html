FCREPO-4106 Deleting and purging a resource in a TX causes missed cleanup

Description

If a resource is both deleted and its tombstone cleaned up in the same fedora transaction, then containment table entries related to the purged resource are not cleaned up. This blocks purging of tombstones of any ancestors of the object. I am able to replicate the issue with the following commands:

curl -XPUT http://localhost:8088/rest/my -ufedoraAdmin:fedoraAdmin -v
curl -XPUT http://localhost:8088/rest/my/path -ufedoraAdmin:fedoraAdmin
TXLOCATION=$(curl -s -ufedoraAdmin:fedoraAdmin -D - -X POST "http://localhost:8088/rest/fcr:tx" -o /dev/null | grep -i '^Location:' | awk '{print $2}' | tr -d '\r')
curl -XDELETE http://localhost:8088/rest/my/path -ufedoraAdmin:fedoraAdmin -v -H "Atomic-ID: $TXLOCATION"
curl -XDELETE http://localhost:8088/rest/my/path/fcr:tombstone -ufedoraAdmin:fedoraAdmin -v  -H "Atomic-ID: $TXLOCATION"
curl -ufedoraAdmin:fedoraAdmin -XPUT "$TXLOCATION"
curl -XDELETE http://localhost:8088/rest/my -ufedoraAdmin:fedoraAdmin -v
curl -XDELETE http://localhost:8088/rest/my/fcr:tombstone -ufedoraAdmin:fedoraAdmin -v

All of the commands succeed except for the last one, which fails with 04 Error: Resource /my/path not found. If you look in the containment table afterwards, there are still entries for both /my/path and /my, with end dates indicating that they were soft deleted but not purged. However, the OCFL object for /my/path is gone at this point.

Reindexing would probably resolve the issue if it comes up for anyone, or deleting the leftover entries from the DB.
