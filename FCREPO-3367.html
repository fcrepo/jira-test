Description

This bug can be seen when submitting the following erroneous request:
```
curl -i localhost:8080/rest/ag -H"Link: <http://fedora.info/definitions/v4/repository#ArchivalGroup>;'rel=type'" -XPUT
```

Hi, what should the correct reaction be?

The error is due to the 'rel=type' field. if it was rel='type', it works, but with 'rel=type', in the code, it takes that string, tries to find if its equal to 'type', it isnt so returns null and then tries to do a sting operation on a null value. my solution so far is to filter null values and it completes that curl call with a 201 Created, which i'm not sure is what you're looking for?
