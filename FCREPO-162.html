FCREPO-162 Object-specific POLICY datastream ignored when using Oracle

Description

When running Fedora backed by Oracle, with XACML enforcement enabled, the POLICY datastream is ignored. This behavior was discovered in Fedora 2.2.1, but exists in prior versions of Fedora as well.

CAUSE:
The reason this occurs is twofold:

1) A query executed by FastDOReader.GetDatastream fails in Oracle because it includes a DISTINCT clause, but at least one of the column types (dsBind.dsLocation) is a CLOB. And in Oracle, it is an error to issue a SELECT DISTINCT query involving a CLOB.

2) Although the above throws an exception, it is caught and ignored by PolicyFinderModule.getObjectPolicyFromObject. This causes the remainder of the code to assume the POLICY datastream simply doesn't exist.

The fix for this bug MUST:

  • Ensure unexpected errors thrown within
    PolicyFinderModule.getObjectPolicyFromObject
    are not ignored (let them bubble up or wrap
    them)
  • Avoid the use of FastDOReader. In this case,
    PolicyFinderModule should never be getting
    a FastDOReader because we know it requires the
    actual datastream content, which is NEVER stored
    in the database. This can be accomplished by
    passing false as the first parameter to
    DOReader.getReader(..)
  • Find and address other code paths that lead to
    FastDOReader.GetDatastream. NOTE: Due to CMDA
    changes, in the trunk, FastDOReader no longer exists,
    so this only needs to be done for maintenance-2.2.
  • Ensure we have a regression test for maintenance-2.2
    and trunk, which FAILS if the POLICY datastream
    is ignored.
