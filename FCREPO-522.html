Environment

Description

It is possible to create a new datastream terminating in .xml - eg file.xml

The html page for this datastream is unobtainable -> eg /objects/pid/datastreams/file.xml as it incorrectly looks for a datastream without the .xml eg 'file' and states that 'file' doesn't exist.

/objects/pid/datastreams/file.xml.xml does resolve to the xml version of the file.xml ds properties.

Comments (2)

Chris Wilper, 2009-09-15 17:35 UTC

Discussed on Sept 15th committer call. Agreement that ".xml" shortcut should be dropped for this URL (which actually gets the datastream properties)...same for get object profile, since people can have PIDs that end in .extension.

Post to list: to use the ?format=xml form for these.
To get the content, use the dsid/content URL.

Highlight in release notes as potentially breaking change.

Check admin gui for which form it uses.
