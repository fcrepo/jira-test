FCREPO-3775 migration-utils should have the option to migrate resources as atomic resources

Description

migration-utils currently migrates objects as archival groups. This is not necessarily desirable and has two potentially negative consequences:

1. The object is versioned for every change to any of its parts, causing OCFL version inflation
2. The entire object is locked whenever any part of it is updated, meaning that two binaries within the same object cannot be updated concurrently

Example object with 121 versions from Jakov M. Vežić:

So the original in Fedora 3 has:
RELS-EXT: 48 versions
MODS: 18 versions
DC: 34 versions
FILE0: 4 versions
TN: 5 versions
STATUS_INGEST: 7 versions
FILE1: 2 versions
FULL_TEXT: 1 version

inventory.json is 635K

migration-utils should allow the user to decide how they want their objects modeled.
