  • On success,  object creation messages should be emitted.

David Cook, 2020-10-07 22:45 UTC

Andrew Woods let me know about this proposal, and it sounds very exciting. I think that it would really help us when doing ingests of large volumes (ie thousands) of large objects (e.g. 1GB-1TB).

At the moment, we have to send a large binary file to Fedora and then have Fedora send that to Object Storage, which is 1 more hop than I'd like. In Fedora 4, the Modeshape is also using outdated S3 client methods, which buffer objects in memory and cause other problems, so I'm excited at the thought of being able to use the latest object storage tooling to upload binary files, and then just have Fedora fetch the metadata after the fact. That would be amazing for our processing.

I don't quite understand the workflow specified in that Google document, but I would ask that consideration be put into creating an API endpoint that could reindex/accept a large number of new objects.

In Fedora 4, I've found that making large volumes of HTTP calls, even short ones, over even a local network is prohibitively slow for integrated applications. In practice, this means I collocate integrated applications on the same server as Fedora (as connecting via the local loopback device rather than a network socket provided speeds that were 6x faster if I recall correctly). While this worked for my use case in the short-term, it's not a scalable approach, and it makes it difficult to work in "cloud native" environments where you ideally want your services to be separated out to ease management and deployments. 

Anyway, I'm very excited for Fedora 6, and look forward to seeing more!
