Description

Right now we are running into issue with Tomcat reindexing process for our 3.8 million indexcat akurbra items. our server have regular bi-weekly server patching and will cause Tomcat to restart, and everytime it does that the whole process would restart all over. If there’s a way to allow Tomcat restart and resume reindexing that would be helpful in our migration progress with large numbers of items

Comments (5)

Jared Whiklo, 2023-10-05 16:00 UTC

Questions:
Can we track a list of the objects that have been reindexed?
Do the objects come out of ocfl-java in a consistent order?

Each object is reindexed in it’s own database transaction which is then committed, so we probably use the database as the record of already indexed children.

Direct/Indirect container relationships are generated after all the other objects are indexed.

So with some (Jared’s suggestion here) new flag to resume indexing, the server would re-run the IndexBuilder but skip any object with an entry in the ocflIndex or containmentIndex.

Alternative suggestion is to write a file on reindex of all processed objects. On Fedora startup if that file exists then continue reindexing. Once reindexing is complete, remove the file.
