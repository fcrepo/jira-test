FCREPO-3546 Error updating external binary after updated without type header

TypeBug
StatusOpen
PriorityMajor
ReporterBen Pennell
Created2020-11-30 22:23 UTC
Updated2021-02-08 15:20 UTC
Affects versionsFedora 5.1.1

Description

We have a proxied external binary in our repository which was created correctly, but then accidentally updated in a second request without providing 'Link: <http://www.w3.org/ns/ldp#NonRDFSource>; rel="type"'. The result is that future PUT requests fail to the binary with error:

Changing the interaction model ldp:BasicContainer to ldp:NonRDFSource is not allowed!

Attaching a debugger to fedora shows that the resource now mistakenly is both a BasicContainer and a Binary in modeshape:

jcr:mixinTypes=[ldp:NonRDFSource,fedora:Resource,fedora:Binary,ldp:BasicContainer]

I was able to replicate the issue by running fedora locally with:

mvn jetty:run -Dfcrepo.external.content.allowed=fcrepo-http-api/src/test/resources/allowed_external_paths.txt -pl fcrepo-webapp/

And then performing the following requests:

# Create external binary, with type link header included (succeeds)
$ curl -H"Link: <file:///Users/bbpennel/git/fcrepo5/README.md>; rel=\"http://fedora.info/definitions/fcrepo#ExternalContent\"; handling=\"proxy\"; type=\"text/plain\"" -H'Link: <http://www.w3.org/ns/ldp#NonRDFSource>; rel="type"' -XPUT -ufedoraAdmin:fedoraAdmin http://localhost:8080/rest/readme

# Update external binary, with type link header included still (succeeds)
$ curl -H"Link: <file:///Users/bbpennel/git/fcrepo5/README.md>; rel=\"http://fedora.info/definitions/fcrepo#ExternalContent\"; handling=\"proxy\"; type=\"text/plain\"" -H'Link: <http://www.w3.org/ns/ldp#NonRDFSource>; rel="type"' -XPUT -ufedoraAdmin:fedoraAdmin http://localhost:8080/rest/readme

# Update external binary, WITHOUT the type link header (succeeds, sort of)
$ curl -H"Link: <file:///Users/bbpennel/git/fcrepo5/README.md>; rel=\"http://fedora.info/definitions/fcrepo#ExternalContent\"; handling=\"proxy\"; type=\"text/plain\"" -XPUT -ufedoraAdmin:fedoraAdmin http://localhost:8080/rest/readme

# Try updating binary with type link header included again (fails)
$ curl -H"Link: <file:///Users/bbpennel/git/fcrepo5/README.md>; rel=\"http://fedora.info/definitions/fcrepo#ExternalContent\"; handling=\"proxy\"; type=\"text/plain\"" -H'Link: <http://www.w3.org/ns/ldp#NonRDFSource>; rel="type"' -XPUT -ufedoraAdmin:fedoraAdmin http://localhost:8080/rest/readme

Changing the interaction model ldp:BasicContainer to ldp:NonRDFSource is not allowed!

This error does not happen with internal fedora binaries. Also, making the request without the type link header succeeds when the object is in this state. For GET and HEAD requests, the object still behaves like a binary as well. So from the outside this mainly just breaks being able to make the same request to create and update the binary.

I'm not sure yet how to repair the object.
