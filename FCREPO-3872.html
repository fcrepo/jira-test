FCREPO-3872 Fixity checks are unusually slow for large files

Description

When accessing the /fcr:fixity endpoint for binary resources, very large files can take a very long time to run – in excess of 60-90 seconds. This seems unusually slow, especially since I can reproduce the problem on a well-resourced test system under no load. I’m seeing the same behavior in two different storage configurations, so I don’t think the problem is specifically related to my disk setup.

You can download the ~1.3GB flac audio file that first led me to discover the issue here:

https://digital.library.villanova.edu/files/vudl:358843/MASTER

You should be able to upload this as a binary to Fedora and then add /fcr:fixity to the binary’s URL in order to see the problem in action. I’ll be interested to hear if this performs significantly better for others!

Thank you!
