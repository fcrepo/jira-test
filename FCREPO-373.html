Description

The upgrade process for 3.1 to 3.2 needs to be defined. Several changes make this a more complex change than the "patch" approach we have used in the past.

1) Due to FCREPO-254 Closed , the system-defined CModel for SDeps (in src/java/fedora/server/resources/) needs to be upgraded
2) The web.xml file may need to be modified as a result of FCREPO-241 Closed
3) The name of the fedora-client.jar file has changed.

How to do this requires some though. For example, #2 and #3 might necessitate a re-install of Fedora, where people are advised to point the new installation to their old data (in the db, ri, and filesystem). #1 will require some more thought.

Comments (1)

Chris Wilper, 2008-10-21 06:45 UTC

Bill and I decided that the upgrade from 3.0 should require a fresh install of Fedora, while pointing at the old data/configuration (no rebuild required). The system objects will be auto-upgraded on the first run of this new instance. The exact process the user needs to follow will be hashed out in the 3.1 upgrade guide.
