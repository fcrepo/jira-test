FCREPO-2452 Handle export filename collisions from naming conventions

Description

Handle export filename collisions from naming conventions

It is possible to cause collisions which prevent export of individual objects/binaries during an export. This is triggerable by having two objects in the repository, one with a standard extension from the export process, one without.

For instance, "container" and "container.ttl", or "file" and "file.binary". In both cases, one of the objects will collide with another object's subdirectory. See the example below for the case involving containers.

The export should either avoid this issue or handle it gracefully. In both cases the issue is logged as a warning, and may not interrupt the export, so it would be difficult to know that objects had been lost. One solution might be to escape reserved characters (like .) that appear in IDs.

Container example:

curl -XPUT http://127.0.0.1:8984/rest/export_base/
curl -XPUT http://127.0.0.1:8984/rest/export_base/container
curl -XPUT http://127.0.0.1:8984/rest/export_base/container/child1
curl -XPUT http://127.0.0.1:8984/rest/export_base/container.ttl
curl -XPUT http://127.0.0.1:8984/rest/export_base/container.ttl/child1

Esmé Cowles, 2017-05-23 15:05 UTC

One way to address this issue would be to add a suffix to containers (e.g., ".container").  That would mean that the directories named "container.ttl" and "file.binary" would map to "container.ttl.container" and "file.binary.container", and not collide with other files.

Andrew Woods, 2017-05-24 00:56 UTC

Wouldn't this result in a variation of the current issue of conflicts:

/rest/container
/rest/container.ttl
/rest/container.ttl.container

It seems like exporting the above would result in a conflict.

However, using your idea of an additional suffix, maybe that suffix could be optionally user-provided... so users can avoid conflicts by choice.

Ben Pennell, 2017-05-24 13:05 UTC

Another option would be to escape all periods in object ids, reserving the character for extensions added by the exporter.
