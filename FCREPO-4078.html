Description

  1. Download test-data.tar.gz.
  2. Unpack the test-data.tar.gz with tar xvf ./test-data.tar.gz (this will unpack all files in the tar archive to the current directory).
  3. Use one of the Docker Compose files in test-data.tar.gz to replicate the error:
    1. For H2: Run docker compose -f docker-compose.h2.yml up
    2. For MariaDB, MySQL and PostgreSQL:
      1. Run docker compose -f docker-compose.postgres.yml up db in a terminal and wait till database has been fully initialized.
      2. Run docker compose -f docker-compose.postgres.yml up fcrepo to start Fedora in a separate terminal session.

Thomas Bernhart, 2026-04-07 14:41 UTC

After looking into this more closely, I can now narrow the issue down.

When I remove the constraint in search_resource_rdf_type_pkey on the table search_resource_rdf_type, the index rebuild succeeds.

I did this with PostgreSQL and anlysed which entries apear more than once in the table search_resource_rdf_type with the following SQL query after the succesfull rebuild:

select search_resource_rdf_type.*,
       string_agg(search_rdf_type.rdf_type_uri, ', '),
       string_agg(simple_search.fedora_id, ', ')
from search_resource_rdf_type
     inner join search_rdf_type on search_resource_rdf_type.rdf_type_id = search_rdf_type.id
     inner join simple_search on search_resource_rdf_type.resource_id = simple_search.id
group by search_resource_rdf_type.resource_id, search_resource_rdf_type.rdf_type_id
having count(*) > 1
order by search_resource_rdf_type.resource_id, search_resource_rdf_type.rdf_type_id;
