Description

A HEAD request to a Fedora container reports the content type as application/octet-stream. This seems incorrect.

Comments (6)

Danny Bernstein, 2017-01-10 00:19 UTC

According w3c http spec: https://www.w3.org/Protocols/rfc2616/rfc2616-sec9.html
"The HEAD method is identical to GET except that the server MUST NOT return a message-body in the response." Perhaps HEAD should return the same Content-Type as the GET.

Andrew Woods, 2017-01-10 00:27 UTC

Danny Bernstein, agreed. The only exception that we have temporarily agreed to live with between the headers of HEAD and GET is the Content-Length of binaries.

Andrew Woods, 2017-01-10 15:03 UTC

This looks like a good start, but I am not seeing the exact behavior I would expect.
For example:
curl -XPUT localhost:8080/rest/test
curl -i localhost:8080/rest/test
> Content-Type: text/turtle;charset=utf-8

  • As expected

curl -I localhost:8080/rest/test
> Content-Type: application/ld+json

  • Not as expected

However, the other scenarios work as expected:
curl -i -H"Accept: text/n3" localhost:8080/rest/test
> Content-Type: text/n3;charset=utf-8

  • Good

curl -I -H"Accept: text/n3" localhost:8080/rest/test
> Content-Type: text/n3;charset=utf-8

  • Good
