Description

Currently, the verification tool always logs to verify_output.txt by default. Since the tool is not much use without logs, it would be better if logs were named with date + time stamps, so that they will never be overwritten inadvertently.

A folder "logs" should be checked in to Github, but the contents gitignored. Log files can be generated automatically and stored in this form:

logs/YYYYMMDD-HHMM.log

Danny Bernstein, 2017-05-24 17:19 UTC

Joshua Allan Westgard:  I would suggest that change the "l/log-file"  to "-l/-log-dir"  parameter to specify the logs directory which will be logs/ by default.  I don't think there is any need to check in logs directory (I'm not sure that you can check in empty directories in github)

Also: perhaps we would like to do the same for the csv files? Instead of "-c/–csv" option we might have a "-o/–output-dir" option where csv files would get dumped.

Joshua Allan Westgard, 2017-05-24 19:38 UTC

Thanks, @dbernstein. You're right about checking in empty dirs. The normal workaround is to put a README in it or an empty .gitignore in there, and then github will check it in. But I would say as long as the code creates the directory if it doesn't exist we don't need to check in the logs directory.

Regarding CSV files, yes, I agree. It started out as an optional feature, but maybe it should just happen automatically. Also whether or not the CSV always gets created, the -o flag could be used to specify an output directory, and it could just be sent to the logs or to a "csv" directory by default.
