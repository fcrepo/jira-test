Description

We rewrite RDF to contain internal Fedora IDs. However, this breaks when the ID contains spaces because a URI with spaces is invalid. To reproduce:

curl -i -ufedoraAdmin:fedoraAdmin -XPOST -H"Slug: spaces 2" "http://localhost:8080/rest"

curl -i -ufedoraAdmin:fedoraAdmin -XPATCH -H"Content-type: application/sparql-update" -d "INSERT

{ <> <http://purl.org/dc/elements/1.1/title> \"test\" }

WHERE { }" http://localhost:8080/rest/spaces%202

Comments (12)

Andrew Woods, 2020-11-19 18:30 UTC

Maybe this ticket is a placeholder for what I understood the solution to be: disallow spaces in slugs.

Is that your understanding, Peter Winckles?

Peter Winckles, 2020-11-19 19:22 UTC

Andrew Woods, the issue isn't with slugs. You can create a resource with a space in the id without using a slug.

Andrew Woods, 2020-11-19 19:29 UTC

I am inclined to disallow spaces in resource IDs.

Jared Whiklo, 2020-11-23 21:57 UTC

Actually I don't think you can PUT a URI with a space. It gets rejected by Jersey. So the only practical place this appears is in the Slug. But the bigger issue (as defined in this ticket) is that spaces in Fedora IDs cause problems when dealing with RDF.

Andrew Woods, 2020-11-23 23:03 UTC

Is there any reason why we should not simply disallow spaces in resource IDs?

Jared Whiklo, 2020-11-24 16:35 UTC

Other than the fact that spaces are allowed in URIs and our IDs are directly linked to our URIs? Or were you thinking that external URIs and internal IDs would be more transformed than just replacing the hostname and context with the internal prefix?

Andrew Woods, 2020-11-25 00:59 UTC

I was thinking that we might consider disallowing spaces in Fedora resource URLs.

Peter Winckles, 2020-11-30 13:20 UTC

You can PUT to a URI with a space if the space is percent (or plus) encoded. The end result is the same. Jersey decodes it to a space and the space makes Fedora blow up.

Andrew Woods, 2020-11-30 15:34 UTC

Yes... shall we simply forbid spaces in Fedora resource IDs?

Andrew Woods, 2020-12-03 16:27 UTC

Approach decision:

  • We should be permissive with respect to characters that are problematic in URIs (such as spaces).
  • This ticket should encode characters that are not permissible.

The encoding should happen prior to inserting IDs/URIs into RDF documents.

It would be valuable to investigate Jena and the URI spec to have clarity on which characters are problematic.
