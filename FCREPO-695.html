Description

The Muradora codebase included an "evaluate" API method which allowed specification of subject, roles, actions, pid and (optional) dsid to determine if the specified action would be permissible in the given context.

The code is present in FeSL eg at org.fcrepo.server.security.xacml.pep.ContextHandlerImpl.evaluate

This method would be useful for front-end applications so that, for instance, a user interface appropriate to a user's permissions can be presented.

Nigel Thomas, 2010-11-26 23:09 UTC

The evaluate method exposed in an API would be really useful as Steve pointed out. At York we use the evaluate call to index evaluation results for controlled access to searching and browsing in our interface(s).
We have done some work studying the performance issues within XACML evaluation cycle and have found that some performance gains could be had by batching up evaluation calls as well. The PDP implementation from Muradora also support a BatchEvaluate call in addition to evaluate, it would useful expose both methods.
If performance enhancements could be had by exchanging data in binary format with evaluate call, I would be all for that too!
