Chris Wilper, 2009-11-24 20:38 UTC

Could this have something to do with the xslt processor WebLogic uses by default?

Fedora (trunk) comes with Saxon 9. But this stack trace indicates that xalan is being used in WebLogic when schematron validation occurs.

Chris Wilper, 2009-11-25 02:16 UTC

To force the use of Saxon in Fedora 3.2.1, you should be able to set the following system property so that it is visible to the Fedora webapp when it starts in WebLogic (consult weblogic docs for this; I have no idea)

javax.xml.transform.TransformerFactory=net.sf.saxon.TransformerFactoryImpl

It seems that, since the Fedora webapp includes saxon9, offering a "choice" of xslt processors (or accepting the default behavior, which I suppose is leaving it up to the servlet container) isn't adding value.

I think we should force the use of Saxon9 within the code itself. This would ensure future releases of Fedora are consistently using the xslt processor we test against.
