FCREPO-2988 Creating versions of containers containing tombstones issue

TypeBug
StatusOpen
PriorityMinor
ReporterBen Pennell
Created2019-02-08 21:11 UTC
Updated2021-09-17 17:42 UTC
Affects versionsFedora 4.7.5

Description

Given a container containing a child:

c1 --> c2

If you delete c2 and then create version v0 of c1, when you look at the contents of c1/fcr:versions/v0 you will see it listing c2 as a child of the version, and c2 will have the same contents it had before it was deleted even though it was deleted before creating the version.

If you delete c1/c2/fcr:tombstone and create version v1 of c1, then v1 will not list c2 as a child. So it appears that if you don't clean up the tombstone fedora will restore deleted children when creating a snapshot.

It can be replicated as follows (tested in 4.7.5 and 4.7.3)

 


curl -XPUT http://localhost:8080/rest/c1
curl -XPUT http://localhost:8080/rest/c1/c2

curl -XDELETE http://localhost:8080/rest/c1/c2

curl -XPOST http://localhost:8080/rest/c1/fcr:versions -H"Slug: v0"

curl http://localhost:8080/rest/c1/fcr:versions/v0/c2
# Status: 200
# <http://localhost:8080/rest/c1/fcr:versions/v0/c2>
#         rdf:type          fedora:Version ;
#         fedora:createdBy  "bypassAdmin"^^<http://www.w3.org/2001/XMLSchema#string> ;
#         fedora:created    "2019-02-08T21:05:24.907Z"^^<http://www.w3.org/2001/XMLSchema#dateTime> ;
#         rdf:type          ldp:RDFSource ;
#         rdf:type          ldp:Container ;
#         rdf:type          ldp:BasicContainer ;
#         fedora:writable   "true"^^<http://www.w3.org/2001/XMLSchema#boolean> ;
#         fedora:hasParent  <http://localhost:8080/rest/c1/fcr:versions/v0> .

curl http://localhost:8080/rest/c1/c2
# Status: 410

curl -XDELETE http://localhost:8080/rest/c1/c2/fcr:tombstone

curl -XPOST http://localhost:8080/rest/c1/fcr:versions -H"Slug: v1"

curl http://localhost:8080/rest/c1/fcr:versions/v1/c2
# Status: 400
# Prefix fcr has not been registered

curl http://localhost:8080/rest/c1/c2
# Status: 404
