Description

A Number if users have reported issues with very large transactions. These issues can manifest in a number of ways including not reporting the closure of a transaction or timeouts from the server. This ticket is to gather these issues together and then generate individual tickets for each fix.

Initial investigations lead to some possible database improvements in the form of rewriting SQL statements, adding new indexes and upgrading the underlying database client libraries as part of the dependancy upgrade project.

On one of our instances which has about 70k objects, uploading suddenly started to take more than 1min. I tracked this down to Fedora committing a transaction (which we use to reduce OCFL versions).

Dan Field, 2025-07-03 15:36 UTC

When committing a long running Fedora transaction, in which the time needed to perform the commit is long (due to a large total size of files of many gigabytes and a large numbers of files for example), the database connections needs to stay open for a long time without any activity because moving all those files from OCFL staging directory to the OCFL root (committing the OCFL persistent storage session, fcrepo-kernel-impl/src/main/java/org/fcrepo/kernel/impl/TransactionImpl.java#L361) can take a considerable amount of time.
