FCREPO-3698 Java client improperly encodes filename field

Description

When using the client to create a binary resource with a filename, the client is URI encoding the value of the filename. So in the following example:

client.put(resourceUri)
       .filename("this is my file.txt")
       ...

The ebucore:filename field in fedora ends up as "this+is+my+file.txt"

https://github.com/fcrepo-exts/fcrepo-java-client/pull/52

Switched to using spring's ContentDisposition utility to encode filenames. It retains spaces as spaces, and replaces a lot of other whitespace and control characters with spaces.

Some characters could cause the request to error out, such as newlines which produce the response:

<h1>Bad Message 400</h1><pre>reason: Illegal character VCHAR='"'</pre>
