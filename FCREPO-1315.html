I think it's safe to adjust Sonar to allow greater number of 'parents' (7?), and it boils down to how some developers approach OOP. For example, some of these custom exception classes are used only once in the codebase. It seems to me that the reason these types exist is anticipation and aesthetics (possibly meant to design the API a certain way) rather than functional. At any rate, it's a style issue, and we need to think about it first and then tell Sonar what to do (rather than accept a magic number from it).
