Description

In response to CVE-2023-046604 We need to patch the most recent versions of Fedora 3,4,5 and 6 to bring the packaged ActiveMQ up to a version listed as safe in the following document:

https://activemq.apache.org/security-advisories.data/CVE-2023-46604-announcement.txt

We also need assistance from anyone with Fedora build experience to ensure that the aging pom.xml files and related repositories and dependencies are able to be built in this day and age. An initial look at Fedora 3 and 4 show there is work to be done here.

Whilst the end goal is 4 new releases rolled out to GitHub, DockerHub and Sonatype, those actions require credentials and permissions that only select members of the team may have. That is the final step in the process though, so any help with getting the builds working is appreciated.

Make a comment on the ticket if you are working on a particular version, and jump on to the committers or tech channels on slack if you don't have access to committers, and keep the conversation going there.

Jared Whiklo, 2023-11-16 20:34 UTC

Discussion at the Community meeting resulted in Thomas Bernhart suggesting that they had disabled the internal brokers transport connectors on their Fedora 3 instance and just forwarded all messages to an external broker.

I realize we had done this awhile ago too just to allow securing the broker.

This information is for Fedora 3.8.1

To do this, you setup a new ActiveMQ instance on your server. I added authentication to allow other machines to connect if they had a username:password only.

Then you create an ActiveMQ configuration file, like

<beans 
  xmlns="http://www.springframework.org/schema/beans"
  xmlns:amq="http://activemq.apache.org/schema/core"
  xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
  xsi:schemaLocation="http://www.springframework.org/schema/beans http://www.springframework.org/schema/beans/spring-beans-2.0.xsd
  http://activemq.apache.org/schema/core http://activemq.apache.org/schema/core/activemq-core-5.5.0.xsd">
​
  <!-- ActiveMQ JMS Broker configuration -->
  <amq:broker id="broker" useShutdownHook="false">
​
    <amq:managementContext>
      <amq:managementContext connectorPort="1093" createConnector="false"/>
    </amq:managementContext>
​
    <!-- Your remote broker, configured with failover -->
    <amq:networkConnectors>
      <amq:networkConnector name="fedorabridge" userName="fedora" password="<redacted>" dynamicOnly="true" uri="static:(failover:(tcp://0.0.0.0:61616))"/>
    </amq:networkConnectors>
​
    <!-- The directory where Fedora will store the ActiveMQ data -->
    <amq:persistenceAdapter>
      <amq:amqPersistenceAdapter directory="file:/usr/local/fedora/data/activemq-data"/>
    </amq:persistenceAdapter>
  </amq:broker>
​
  <!-- Set this to prevent objects from being serialized when
       passed along to your embedded broker;  saves some overhead processing -->
  <bean id="jmsConnectionFactory" class="org.apache.activemq.ActiveMQConnectionFactory">
     <property name="objectMessageSerializationDefered" value="false"/>
  </bean>

</beans>

and in your fedora.fcfg file in the Messaging module you alter the “java.naming.provider.url” to point to this file.

<module role="org.fcrepo.server.messaging.Messaging" class="org.fcrepo.server.messaging.MessagingModule">
    <comment>Fedora's Java Messaging Service (JMS) Module</comment>
    <param name="java.naming.factory.initial" value="org.apache.activemq.jndi.ActiveMQInitialContextFactory"/>
    <!--<param name="java.naming.provider.url" value="vm:(broker:(tcp://localhost:61616,stomp://localhost:61613))"/>-->
    <param name="java.naming.provider.url" value="vm://localhost?brokerConfig=xbean:file:/usr/local/fedora/server/config/spring/activemq.xml"/>
    <param name="datastore2" value="apimAccessMessages">
      <comment>A datastore representing a JMS Destination for APIM events which do not update the repository</comment>
    </param>
    <param name="datastore1" value="apimUpdateMessages">
      <comment>A datastore representing a JMS Destination for APIM events which update the repository</comment>
    </param>
    <param name="enabled" value="true"/>
  </module>

If you have configured everything correctly you should see messages from Fedora 3 appear in your external broker in the same queue/topic you would expect.
