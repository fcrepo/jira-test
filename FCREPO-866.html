Stephen Bayliss, 2011-03-13 00:35 UTC

Schema validation reveals the following (added as sub-tasks of FCREPO-713 Closed ):

  • getObjectHistory - response has xsi:schemaLocation="http://www.fedora.info/definitions/1/0/access/ http://www.fedora.info/definitions/1/0/objectHistory.xsd" but the schema file is fedoraObjectHistory.xsd (404 from the given location) : schema location in response needs correcting or the xsd file needs renaming
  • datastream profile with asOfDateTIme - cvc-complex-type.3.2.2: Attribute 'dateTime' is not allowed to appear in element 'datastreamProfile' : schema needs updating to allow this (optional) attribute OR don't have the attribute in the response
  • findObjects/resumeFindObjects do not seem to have schema - they should, so we can avoid unintentionally breaking the API response
  • validation - does not specify schema in response (there is one at http://www.fedora.info/definitions/1/0/validation.xsd)
Stephen Bayliss, 2011-03-13 02:03 UTC

And back to the original issue...

Looks like org.fcrepo.server.security.xacml.pep.rest.objectshandlers.ListDatastreams.filterXML(...)

This is using a javax.xml.parsers.DocumentBuilderFactory which has not been set to be namespace-aware.

Potentially could affect other classes in org.fcrepo.server.security.xacml.pep.rest.objectshandlers

Update: this was the issue. Fixed, plus one other instance in objecthandlers.
