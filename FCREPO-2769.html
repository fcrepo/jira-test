FCREPO-2769 Restore resource from Tombstone

TypeStory
StatusOpen
PriorityMinor
ReporterDanny Bernstein
Created2018-04-18 21:34 UTC
Updated2018-10-02 22:29 UTC

Description

When a user deletes a resource a tomstone is put in its place.  Users have expressed a desire be able to "undelete"   the deleted resource.   To this end,  several things must be considered/implemented.

  1. Resources that were not created as "versionable" cannot be undeleted.
  2. When a resource is deleted,  a memento of the resource's state just before deletion should be created (otherwise there will be nothing to restore should the need arise).
  3. The timemap should be preserved when a resource is deleted.
  4. It should be possible to restore a memento  via a GET on the desired version followed by PUT on against the tombstone resource.
  5. We may need to employ a Prefer header such as "Prefer: ignore-tombstone"  in order to get bypass the tombstone's 415 response on a PUT.
