Description

Currently "isCollection" is not present in the Fedora relationships ontology at http://fedora-commons.org/definitions/1/0/fedora-relsext-ontology.rdfs. However it's a term that does seem to get used fairly frequently to allow discovery of resources that have children.

See the recent post by Gill Hamilton to the users list.

The wiki page FAQ item on this does in fact use this predicate although it is not defined in the ontology (https://wiki.duraspace.org/pages/viewpage.action?pageId=17530955) and Muradora also made use of this undefined predicate.

Should we therefore consider updating the ontology to include this? Or should we recommend that people use a predicate from their own namespace (and update the wiki FAQ item also)?

Comments (6)

Chris Wilper, 2010-08-06 21:34 UTC

I think this is an error in the FAQ. The fact that something is a collection could be expressed in a variety of ways (using a hasModel relation to a Collection content model, which implies the subject is a collection...). The FAQ entry seems to imply that you must have this relationship stated in order to have a collection object. That's not the case – this is just one way. Should we promote one particular way of modeling collections, or just give people a few examples? In any case, it should be clarified that this is just one way to model collections, and others are possible.

Stephen Bayliss, 2010-08-06 22:27 UTC

Good point. And using an "is" type of predictate with the intention of indicating the type or class of an object is possibly not the best solution when we both have hasModel and rdf:type.

And a collection content model can also provide useful features such as methods for returning a list of collection members (as per I think the demo objects).

Benjamin Armintor, 2010-08-07 10:32 UTC

There's also good old dc:type, and 'Collection' is right there in the dcmi type vocabulary.

I agree that between type attributes and an "isMemberOf" predicate, this is covered.

Asger Askov Blekinge, 2010-08-09 13:10 UTC

No, we do not need a third way of expressing the type of an object. #hasModel is the way to express the class of an object. Yes, you can use rdf:type. And yes, you can use dc. But these are non-standard in a fedora context.

About collection objects. No, let's not go there. We should not add a "Collection" content model. There are numerous reasons why this would be a bad idea. And without a specific content models, we should not add a "isPartOfCollection" relation to the ontology

Stephen Bayliss, 2011-04-08 15:13 UTC

Agree with Asger that content models is the way to go on this. Think we should close this issue. If people want to take their own route they can for instance use their own custom ontology.
