FCREPO-1024 Improve ingest throughput by removing unnecessary synchronized keyword in getIngestWriter

Description

As Jesper Damkjaer reported in this post:

http://fedora-commons.1317035.n2.nabble.com/fcrepo-dev-Synchronization-on-getIngestWriter-in-DefaultDOManager-tc6972143.html

DefaultDOManager.getIngestWriter seems unnecessarily synchronized. We suspect that removing the synchronized keyword might improve concurrent ingest throughput significantly.

We should also add a test that tries to concurrently ingest multiple objects with the same PID. Fedora should fail such attempts.

Comments (9)

Jesper Damkjær, 2011-11-10 02:42 UTC

I have now tried my parallel test against both the code containing the synchronized and the code without.
The test setup is 10 parallel threads each ingesting 10.000 objects containing different PIDs.
The hardware has 24 Xeon cores.

Before removing the synchronized keyword the threads took 9.59 minutes in average.
After removing the synchronized keyword the threads took 2.21 minutes in average.

In this test it was a speedup of x4.25.

Notice that this speedup is only for parallel ingests. Serial ingests will not receive this speedup.

Using jmockit I have mocked the DefaultDOManager in order to test getIngestWriter.

I have found a single problem not actually related to the synchronization: If two objects with the same PID are ingested at the same time, the first one will get the writeLock, but the second one will - when it cannot obtain the writeLock actually unlock the PID in the exception handling.

The code can be found in my github-fork: git@github.com:damkjaer/fcrepo.git
The unittests with mocks etc. is in the file: fcrepo-server/src/test/java/org/fcrepo/server/storage/TestIngestWriter.java

Should I try to correct this problem while looking at the code or should this be reported as a seperate issue?
