Esmé Cowles, 2017-09-19 14:30 UTC

Looking at the LDP ontology (https://www.w3.org/ns/ldp.rdf), I see that none of the four interaction models supported by Fedora (ldp:NonRDFSource, ldp:BasicContainer, ldp:DirectContainer and ldp:IndirectContainer), are subtypes of any of the others.  Since we do not allow creation of resources with types ldp:Resource, ldp:RDFSource, or ldp:Container, there is no valid change.

So I think the only work to be done here is FCREPO-2594 Closed (returning a 409 Conflict if a client attempts to change the interaction model).

Esmé Cowles, 2017-09-19 14:32 UTC

Aaron Birkland, do you agree with my analysis here?  If so, I think we can close this ticket and leave returning error codes to FCREPO-2594 Closed

Aaron Birkland, 2017-09-19 19:17 UTC

Esmé Cowles Hm, I think given the current LDP ontology, the relevant specification of the spec is essentially implying that the server must not allow a client to change the interaction model after a resource is created.  So I agree, that means nothing to do here.

Andrew Woods, 2018-01-11 15:19 UTC

I believe the resolution to this ticket is to change the process by which Direct and Indirect Containers are created.

Currently, when an RdfSource is created, it is automatically created as a BasicContainer. Subsequently, users add triples to that container giving it another type, such as DirectContainer or IndirectContainer.

The task of this ticket should be to allow the current BasicContainer behavior to continue, but allow the creation of Direct and Indirect Containers via the create request and "Link: <type>" approach: https://fcrepo.github.io/fcrepo-specification/#ldpnr-ixn-model
Changing the type of BasicContainers should be disallowed.
