FCREPO-3114 Unauthorized users can delete child resources

TypeBug
StatusOpen
PriorityMajor
ReporterDanny Bernstein
Created2019-11-07 22:44 UTC
Updated2024-01-11 20:51 UTC
Affects versionsFedora 5.1.0

Description

Doing some testing on Fedora 5.1.0:Given /fcrepo/rest/parent and  /fcrepo/rest/resource/child:
If  userA has read and write access to parent but no access to child,  userA can issue a delete to /fcrepo/rest/parent and delete the child as well.

 

To reproduce: 

#Create a resource and child
curl -X PUT http://localhost:8080/fcrepo/rest/resource -u fedoraAdmin:secret3
curl -X PUT http://localhost:8080/fcrepo/rest/resource/child -u fedoraAdmin:secret3

  1. PUT the following ACLs: 

unrestricted-parent.ttl:

 

@prefix webac: <http://fedora.info/definitions/v4/webac#> .
@prefix acl: <http://www.w3.org/ns/auth/acl#> .
<> a webac:Acl .
<#auth1> a acl:Authorization;
acl:mode acl:Read, acl:Write;
acl:accessTo </fcrepo/rest/resource>;
 acl:agent "testuser"
 

curl -X PUT http://localhost:8080/fcrepo/rest/resource/fcr:acl -H "Content-Type:text/turtle" -d "@unrestricted-parent.ttl" -u fedoraAdmin:secret3

restricted-child.ttl:

 

@prefix webac: <http://fedora.info/definitions/v4/webac#> . @prefix acl: <http://www.w3.org/ns/auth/acl#> .<> a webac:Acl .<#child> a acl:Authorization; acl:mode acl:Read; acl:accessTo </fcrepo/rest/resource/child>; acl:agent "testuser" .
 
 

curl -X PUT http://localhost:8080/fcrepo/rest/resource/child/fcr:acl -H "Content-Type:text/turtle" -d "@restricted-child.ttl" -u fedoraAdmin:secret3 -v

 

Try to delete the child with the test user - you should get a 403:

curl -X DELETE -u testuser:password1 http://localhost:8080/fcrepo/rest/resource/child -v

Now delete the parent (204):

curl -X DELETE -u testuser:password1 http://localhost:8080/fcrepo/rest/resource -v
