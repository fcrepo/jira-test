FCREPO-3313 Out of memory error when uploading large files to AWS S3

TypeBug
StatusOpen
PriorityMedium
ReporterDavid Cook
Created2020-05-12 00:31 UTC
Updated2020-05-13 20:04 UTC
Affects versionsFedora 4.7.5

Environment

Ubuntu 18.04
Tomcat 8

Description

When uploading a 1+GB file to Fedora, there's no issue uploading the file to the Fedora API, but we get the warning when it starts to upload the data to AWS S3:

 

"(AmazonS3Client) No content length specified for stream data.  Stream contents will be buffered in memory and could result in out of memory errors."

 

Sure enough, with default Tomcat memory options of 2GB, we get Java out of memory errors: "java.lang.OutOfMemoryError: Java heap space"

 

The band-aid fix was just to increase the memory allocated to Tomcat, but it would be better if the whole file wasn't read into memory, as memory limits will always provide an arbitrary ceiling for file size limits.

 

Since the file has already been uploaded to Fedora at this point, it should be easy to determine the content length, set the Content-Length in the ObjectMetadata object, and then do the upload via AmazonS3Client. 

 

See:

https://docs.aws.amazon.com/AWSJavaSDK/latest/javadoc/com/amazonaws/services/s3/model/ObjectMetadata.html
https://docs.aws.amazon.com/AWSJavaSDK/latest/javadoc/com/amazonaws/services/s3/AmazonS3Client.html

 

Although as I say that... I'm getting the feeling that perhaps this is a ModeShape issue instead, which looks like it's correct in the master Modeshape: https://github.com/ModeShape/modeshape/blob/master/modeshape-jcr/src/main/java/org/modeshape/jcr/value/binary/S3BinaryStore.java#L283

 

Something to look out for in Fedora 6 without ModeShape I suppose... 

 

Fedora 4.7.5 uses ModeShape 5.4.0.Final which didn't set the Content-Length:

https://github.com/ModeShape/modeshape/blob/modeshape-5.4.0.Final/modeshape-jcr/src/main/java/org/modeshape/jcr/value/binary/S3BinaryStore.java#L203

 

Fedora 5.1.0 uses ModeShape 5.4.1.fcr... which I assume is similar enough to ModeShape 5.4.1.Final. It still has the bug: https://github.com/ModeShape/modeshape/blob/modeshape-5.4.1.Final/modeshape-jcr/src/main/java/org/modeshape/jcr/value/binary/S3BinaryStore.java#L203

 

It was added as a commit to master 3 years ago https://github.com/ModeShape/modeshape/commit/e8b8a2a1f55f8220b30bc723f8b3d0fd30f5a6f5

 

Ah, but the ModeShape project appears to be dead. 

 

I don't actually see AmazonS3Client in the Fedora 6 code, but perhaps that's a future project.

 

In any case, I don't see a fix for this coming to Fedora any time soon, but it's certainly an issue.
