Description

Language tags (xml:lang) on literals in the RELS-EXT datastream are ignored by the triple store. For example:
<rdf:RDF xmlns:rdf="http://www.w3.org/1999/02/22-rdf-syntax-ns#">
<rdf:Description xmlns:skos="http://www.w3.org/2004/02/skos/core#" rdf:about="info:fedora/aat:300006036">
<skos:prefLabel xml:lang="nl-NL">postkantoren</skos:prefLabel>
....
SPARQL queries only retrieve the literal "postkantoren" without the language tag.
In contrast, triples from the DC datastream do retain the language information correctly. So this is not a pure triple store issue but an issue of translating RELS-EXT into triples (and maybe also RELS-INT, but I did not check that).
If this issue is resolved, it would also be nice if the REST API methods for adding/deleting Relationships would be extended with a language parameter.

Depending on whether the management APIs should support a language attribute for addRelationship and purgeRelationship, this may require changes to the Management interface as well as the Journaling code. Supporting the language attribute on whole-datastream changes (such as ingest) is a much less drastic change.

Egbert Gramsbergen, 2012-08-27 12:54 UTC

For the test suite: a sample SPARQL query with the example above would be

SELECT ?s ?o
WHERE {
?s <http://www.w3.org/2004/02/skos/core#prefLabel> ?o
FILTER (LANG(?o)='nl')
}

to retrieve all objects with a skos prefLabel in Dutch.
