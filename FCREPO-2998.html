FCREPO-2998 Potential issue with namespace registry

Affects versionsFedora 4.7.5, Fedora 5.0.2

Description

Related to: RDF namespaces

There appears to be a potential issue with "xs: http://www.w3.org/2001/XMLSchema" as a predefined namespace binding. It may be missing "#" at the end? 

When defining a data type for objects of a triple, using the Fedora UI's SPARQL update feature, with the following insert: `<> dc:date "2019-05-22"^^xs:dateTime .`

 

The resulting triple (n-triples) is: 

<http://annadora.tacc.utexas.edu:8080/fcrepo/rest/2019-03-15-sparql-test> <http://purl.org/dc/elements/1.1/date> "2019-05-22"^^<*http://www.w3.org/2001/XMLSchemadateTime*> .

 

However, all fedora-generated triples with dateTime data types are serialized as:

<http://annadora.tacc.utexas.edu:8080/fcrepo/rest/2019-03-15-sparql-test> <http://fedora.info/definitions/v4/repository#lastModified> "2019-05-22T20:07:16.187Z"^^<*http://www.w3.org/2001/XMLSchema#dateTime*> .

Andrew Woods, 2019-05-24 17:45 UTC

The issue is related to:

  • ModeShape introduces some namespaces that do not terminate in either a '/' or '#' delimiter
    Such as:
    xs: http://www.w3.org/2001/XMLSchema
    xsi: http://www.w3.org/2001/XMLSchema-instance
  • Fedora includes the set of namespaces when updating/adding a property:
    https://github.com/fcrepo4/fcrepo4/blob/master/fcrepo-kernel-modeshape/src/main/java/org/fcrepo/kernel/modeshape/FedoraResourceImpl.java#L845
  • The resultant concatenated full-qualified terms are incorrect.

One possibility is to "fix" the namespaces by adding the '#' delimiter prior to having Jena execute the update request.
https://github.com/fcrepo4/fcrepo4/blob/master/fcrepo-kernel-modeshape/src/main/java/org/fcrepo/kernel/modeshape/FedoraResourceImpl.java#L845

From a user perspective, an immediate option is to use the fully qualified term(s):
"2019-05-22"^^<http://www.w3.org/2001/XMLSchema#dateTime>

..instead of the prefixed term(s):
"2019-05-22"^^xs:dateTime

Jared Whiklo, 2019-06-22 02:01 UTC

So I also did some digging.

According to the XML Schema : Datatypes specification. Section 3.1 Namespace Considerations defines the namespace URI as "http://www.w3.org/2001/XMLSchema", but in Section 3 Built-in Datatypes they specify that when using the prefix for (in their example) an "int" it would appear as "http://www.w3.org/2001/XMLSchema#int"

In Fedora this is coming from Jena. Because we set the created and lastModified datetimes we set them using the Calendar type. This makes Jena see them as XSDDateTime datatypes. So they get the internally defined namespace.

We could go to Jena and ask, but I imagine they would point to the XML Schema documents (linked above). So we could go to the W3C and ask...or just add # to the end.

For reference:

In the PropertyToTriple converter we call the ValueConverter. Because we pass in strings they are considered default datatypes and fall through to the stringliteral2node which is able to pull the datatype off but only recognizes "http://www.w3.org/2001/XMLSchema#datetime" as specifying a datetime. So you can't do range comparisons unless you use the #.
