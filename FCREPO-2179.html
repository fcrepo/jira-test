Description

Document the behaviors that lead to the binding of system-generated namespace prefixes (in the form ns00x) when new namespaces are invoked in content deposited in Fedora.

Develop a recommendation for a workaround or best practice that will allow users to avoid the inadvertent binding of such prefixes.

Joshua Allan Westgard, 2016-09-07 14:56 UTC

According to my testing, the only way to avoid the binding of a system-generated prefix is to ensure that the first use of a particular namespace is via a PATCH request in SPARQL update syntax. Any POST or PUT request with turtle, rdf-xml, or n3 payload will result in the binding of previously unused namespaces to system-generated prefixes.

Some documentation and a proposed workaround have been posted here: https://wiki.duraspace.org/display/FEDORA4x/Best+Practices+-+RDF+Namespaces

In addition, I attach a copy of a shell script that can be used to "pre-bind" a desired set of namespaces.
