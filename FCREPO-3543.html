FCREPO-3543 Make transactions more robust when auto-versioning is disabled

Description

Changes to OCFL objects with mutable heads cannot be rolled back. This means that transactions with auto-versioning disabled are much more fragile than transactions with auto-versioning enabled and can put resources in bad states.

At the minimum, we should rework the order that transactions are committed so that all of the database changes are committed first and the OCFL changes are the last to be made. This minimizes the chances of corrupting resource, but it can still happen if one of the OCFL commits fails.
