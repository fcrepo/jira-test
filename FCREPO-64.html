Description

Fedora's REST API correctly reports SIZE of "X" datastreams, but the size for all other types is currently reported as "0". For "M" datastreams, this is clearly wrong. For "E" or "R" datastreams, the correct thing to do is less obvious.

For example, hitting the following URL:
http://localhost:8080/fedora/objects/demo:SmileyBeerGlass/datastreams/DC?format=xml

...reports the correct size. But requesting the same info for an "M" datastream reports "0" as the size.

Stephen Bayliss, 2010-06-16 16:35 UTC

Looking at this in more detail:

  • for X datastreams we are ok
  • for M datastreams, the size could be updated as part of the DOManager.doCommit (when the new/modified datastream version is written) - this would require modifying the ILowlevelStorage interface so that the addDatastream and replaceDatastream methods returned the (long) size in bytes. Then when the FOXML is written it would have the correct SIZE. For filesystem storage this is fine - read the size of the file once written. For Akubra, the Blob has a getSize() method, so as long as that works correctly this also should be fine.
  • for E and R datastreams we could not rely on a SIZE attribute in FOXML as the content may have changed. So all API calls that report the size would need to do a HEAD on the resource URI and report the Content-Length header.

We would for E and R be dependent on Content-Length being correctly provided for HEAD requests by the service managing the content.

It does raise the question of whether computing the size for E and R should be automatic, or should be done only if the user asks (an additional parameter).

Stephen Bayliss, 2010-06-16 16:55 UTC

Also for E and R datastreams - it could be that the content is in another (or even the same) Fedora repository, so we should also ensure that the Content-Length response header is correctly supplied by the REST API getDatastreamDissemination - and that this call supports HEAD.

EDIT: HEAD seems to work fine and returns Content-Length

Stephen Bayliss, 2010-06-16 23:37 UTC

Fixed for M datastreams, but see also FCREPO-724 Closed for providing a tool to calculate size attribute for existing datastream versions, and FCREPO-725 Closed for providing dynamic size attribute for E and R datastreams.
