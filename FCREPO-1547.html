Comments (5)

Michael Durbin, 2015-05-19 15:12 UTC

The problem seems to be that once a pairtree node is created, it cannot be "repurposed" as a regular resource.

If you create a resource at "ab/cd" then want to create a resource at "ab" there doesn't appear to be any way to do so with the current version of fedora.

Perhaps we should change the semantics so that you can create named resources where pairtree nodes exist. The result would functionally equivalent to the case where you'd created "ab" then "ab/cd".

Michael Durbin, 2015-05-19 15:26 UTC

First, I'll update the behavior for fcrepo4 so that whenever possible, operations against paths that have pairtree nodes work as if no resource were there. (ie, you CAN create a new resource there, you CANNOT perform updates, etc.)

Michael Durbin, 2015-06-24 18:39 UTC

The amount of work to use ids in this pattern is likely not worth it, so instead we should encourage the use of opaque ids in migrations.
