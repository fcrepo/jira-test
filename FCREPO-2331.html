FCREPO-2331 Dead Reference Removal Utility

TypeNew Feature
StatusOpen

Affects versionsFedora 4.7.0
Is related toFCREPO-2323 Resource with URI property containing hash inaccessible when target is deleted

Description

This task is to create a utility that runs against a stopped Fedora repository,

  • traversing resources,
  • looking for properties of type WEAKREFERENCE or REFERENCE,
  • with values that reference non-existent resources,
  • and removing the dead reference property values.

This utility will likely follow a similar model as:
https://github.com/fcrepo4-exts/fcrepo4-upgrade-utils/blob/master/src/main/java/org/fcrepo/upgrade/utils/TechnicalMetadataMigrator.java#L51

Completion of this task is defined by:

  • first running a script, TBD (kefo?), that detects dead references,
  • followed by running this utility
  • followed by running the initial script again... showing no dead references.

kefo, 2017-01-23 17:00 UTC

I wanted to add a comment here for two reasons: 1) to start resurfacing this issue and 2) to provide any background to what I've done in the past that may or may not be helpful. Let's consider the 1st point covered.

As for the 2nd point, when it comes to testing whether this issue exists, I basically wrote a script that traverses a repository, gathers all the URIs, and then performs a HEAD and GET request on each resource looking for a 200, 404 pattern respectively. That's all it really is. It's more or less a single python script so easy to distribute and use. (I'll add that it is also possible, now, to perform a GET on each resource and tail the fcrepo.log, which now outputs INFO about each requested resource with a reference to a non-existent resource.)

I don't know if the following idea is helpful, but it is something we've contemplated on our end to correcting this sooner rather than later. We think we could simply perform a GET on each resource, strip the Fedora-specific properties, and PUT the resource back in the repo. We've not moved on this beyond theoretical discussion, but I'd welcome any immediate thoughts on it.
