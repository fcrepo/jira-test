Description

With the change in transaction handling the HTML UI no longer can handle transactions in its current form. Now we need to track the transaction ID and pass it as a header on each request until submit or roll back is called.

Comments (6)

Jared Whiklo, 2022-06-01 20:44 UTC

Did some work on this and I was able to use a cookie to track the transaction ID and send it with each AJAX request, but when you just view a resource you have a problem of it not being loaded by AJAX (and thus no Atomic-ID header is sent).

The only solution I can think of it to make the entire HTML UI an app that loads the content from the back-end which would allow us to affect the sent headers. But that kinda defeats the simple HTML UI we were going for.

Option B is to drop transaction support from the HTML UI.
