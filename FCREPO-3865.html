FCREPO-3865 Add the ability to run a reindex from the CLI or web interface on demand

Description

It would be useful the have the ability to re-index the OCFL files on demand. Either in whole or in part (if technically possible). At present, this functionality is reliant on the startup property fcrepo.rebuild.on.start which means that an accidental container restart will trigger an index deletion and re-index without warning. This can be a time consuming process (100 hours in my case) and results in an unservisable repository.

It might be worth investigating if this can be done in a non-destructive way, so as to reindex on the same container as a running repository without trashing the running database. perhaps swapping indexes on completion? This would best be a user option though as it would double the index size on disk and affect performance. I expect this would more usually be an offline operation though. taking place on a secondary container while not affecting producton.
