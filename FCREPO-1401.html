FCREPO-1401 fcrepo-message-consumer HttpClient opens too many connections

TypeBug
StatusClosed
ResolutionWon't Fix
PriorityMinor
ReporterFormer user
Created2015-03-13 14:26 UTC
Updated2015-07-02 14:05 UTC
Resolved2015-07-02 14:05 UTC
Componentsf4-message-consumer
Affects versionsFedora 4.1.0

Description

The fcrepo-message-consumer HttpClient instance currently disables all connection limits:

https://github.com/fcrepo4/fcrepo-message-consumer/blob/master/fcrepo-message-consumer-core/src/main/java/org/fcrepo/indexer/IndexerGroup.java#L208

This means that indexing a large number of objects will result in a very large number of open connections. This limit should be set to a more reasonable value and/or made configurable.

Howard Ding, 2015-03-19 18:41 UTC

I'm the initial reported of this on the Github tracker and have been looking into it a bit more (sorry, don't have a pull request at this time, don't know if I will).

It's not enough to just set connection limits as described. In the classes such as JcrXmlRetriever one needs to explicitly call releaseConnection on the requests at some point (and some of them need to have the type declaration changed from HttpUriRequest to the actual type to make this method available).

Doing both of these seems to fix the problem of having the connections pile up and exhausting the OS resources, but what I've done so far also makes two of the tests fail (both involving reindexing) and may be causing other problems (not sure yet, but I'm not sure that everything is actually getting indexed).
