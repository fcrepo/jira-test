Description

Steps to reproduce:

1. Navigate to a binary in the web console
2. Select a file and click "update"
3. The operation fails with a 400

The root cause is that the HTTP request is passing an empty Content-Type header. Relevant code: https://github.com/fcrepo/fcrepo/blob/main/fcrepo-webapp/src/main/webapp/static/js/common.js#L242

This should likely be addressed by giving the user a way to specify the desired mime type. Ideally, prepopulated with the current type.

Comments (3)

Peter Winckles, 2021-07-16 13:22 UTC

The code currently attempts to identify the mime type using javascript: https://developer.mozilla.org/en-US/docs/Web/API/File/type

The problem is that only works based on file extension for well-known extensions, and will otherwise return an empty string. Our code is not defaulting an empty string to “application/octet-stream”.
