Description

Fedora uses naming conventions to store system generated files within OCFL objects as described here: https://wiki.lyrasis.org/display/FF/Design+-+Fedora+OCFL+Object+Structure

In order for these conventions to work, there are handful of restrictions that must be enforced on user resource ids in order to avoid overwriting system generated files. We are not currently enforcing these restrictions. Here are a couple of examples:

In the following example, the fcr-root.json header file of the AG is overwritten with a binary header file:

curl -u fedoraAdmin:fedoraAdmin http://localhost:8080/rest/ag-01 -H'Link: <http://www.w3.org/ns/ldp#BasicContainer>;rel="type"' -H'Link: <http://fedora.info/definitions/v4/repository#ArchivalGroup>;rel="type"' -v -H "Content-Type: text/turtle" -X PUT --data "<> <http://purl.org/dc/elements/1.1/title> 'AG Parent'"

curl -u fedoraAdmin:fedoraAdmin http://localhost:8080/rest/ag-01/fcr-root -H "Link: <http://www.w3.org/ns/ldp#NonRDFSource>; rel=type" -v -H "Content-Type: text/plain" -X PUT --data-binary "testing"

In this example, the binary description file of one binary is overwritten by another binary:

curl -u fedoraAdmin:fedoraAdmin http://localhost:8080/rest/ag-02 -H'Link: <http://www.w3.org/ns/ldp#BasicContainer>;rel="type"' -H'Link: <http://fedora.info/definitions/v4/repository#ArchivalGroup>;rel="type"' -v -H "Content-Type: text/turtle" -X PUT --data "<> <http://purl.org/dc/elements/1.1/title> 'AG Parent'"

curl -u fedoraAdmin:fedoraAdmin http://localhost:8080/rest/ag-02/child-01 -H "Link: <http://www.w3.org/ns/ldp#NonRDFSource>; rel=type" -v -H "Content-Type: text/plain" -X PUT --data-binary "testing"

curl -u fedoraAdmin:fedoraAdmin http://localhost:8080/rest/ag-02/child-01~fcr-desc.nt -H "Link: <http://www.w3.org/ns/ldp#NonRDFSource>; rel=type" -v -H "Content-Type: text/plain" -X PUT --data-binary "changed!"

Note, these are not exhaustive examples.
