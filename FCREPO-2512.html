FCREPO-2512 line up verification tool's handling of 'predicates' option with behavior of import/export tool

TypeImprovement
StatusOpen
PriorityMinor
ReporterJoshua Allan Westgard
Created2017-06-03 12:58 UTC
Updated2021-09-17 17:42 UTC
Componentsf4-import-export
Labelsverification

Description

It appears that the import/export tool always creates a 'predicates' config option whether or not predicates has been specified as a parameter. The default is ldp:contains.

The verification tool should probably throw an error if predicates is not found in the config rather than supplying its own default value.

Comments (4)

Esmé Cowles, 2017-06-03 15:10 UTC

The other option is to stop writing default values to the config file — which might be a good idea anyway.

It would mean having the verification tool duplicate the defaults — but if we wanted to change any of the defaults, it would prevent old defaults in config files from interfering with that.

Joshua Allan Westgard, 2017-06-03 15:40 UTC

Thanks, Esmé Cowles. I'm happy to have default predicates explicitly recorded in config, but I think we'd be open to having it either way. It would, however, be good to come to an understanding about which options will always be present and which options are optional, so we can avoid any surprising behaviors.

Another config issue that came up for verification is the translation of the value in rdfLang to the appropriate extension. Right now the verification tool supplies a mapping as a constant because we found no convenient library to leverage for that. It might be convenient for verification purposes to have the extension recorded in the config.

Andrew Woods, 2017-06-05 15:56 UTC

Regarding which predicate(s) are being used in the course of an export, that seems like useful information to have in the config file regardless of whether the value was provided by the user or as a default by the tool.
