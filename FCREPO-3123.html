FCREPO-3123 Perform locking on ocfl objects during commit

Description

In order to prevent multiple persistence sessions from simultaneously trying to modify an OCFL object, we need to perform locking of all OCFL objects affected by a transaction during commit.

To avoid deadlock or excessive failure when two sessions try to modify some of the same resources, it may be best to take an approach with an externalized lock manager like the following:

package org.fcrepo.persistence.ocfl.api;

import java.util.Collection;

/**
 * Manages and acquires locks to OCFL objects
 *
 * @author bbpennel
 */
public interface OCFLObjectLockManager {    /**
     * Acquire a lock on all the specified OCFL objects for the given
     * persistence session.
     *
     * If any objects are locked by another session, then block the current
     * thread until all of the object locks may be acquired or the thread is
     * interrupted.
     *
     * @param sessionId identifier for the persistent session obtaining the lock
     * @param objectIds
     */
    void acquireLocks(String sessionId, Collection<String> objectIds);    /**
     * Release all of the object locks held by provided session.
     *
     * @param sessionId identifier for the persistent session
     */
    void releaseLocks(String sessionId);
}
