Description

 

Creating a resource using RDF containing URIs that begin with / is creating an invalid URI:

echo "<> <http://example.com/related> </test1>" | curl -XPUT -H "Content-Type: text/turtle" --data-binary @- http://localhost:8080/rest/test1

$ curl http://localhost:8080/rest/test1

@prefix rdf:   <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
@prefix fedora: <http://fedora.info/definitions/v4/repository#> .
@prefix ldp:   <http://www.w3.org/ns/ldp#> .<http://localhost:8080/rest/test1>
        <http://example.com/related>  <info:/test1> ;
        fedora:created                "2021-01-11T19:30:08.790136Z"^^<http://www.w3.org/2001/XMLSchema#dateTime> ;
        fedora:lastModified           "2021-01-11T19:30:08.790136Z"^^<http://www.w3.org/2001/XMLSchema#dateTime> ;
        rdf:type                      ldp:BasicContainer ;
        rdf:type                      ldp:Resource ;
        rdf:type                      fedora:Resource ;
        rdf:type                      ldp:RDFSource ;
        rdf:type                      ldp:Container ;
        rdf:type                      fedora:Container .

The n3 file persisted in OCFL has the URI in the same format.

Performing this same request in fcrepo5 produces the following triple:

<http://localhost:8080/rest/test1> <http://example.com/related>  <http://localhost:8080/test1>
